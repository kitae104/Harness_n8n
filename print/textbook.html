n8n 핵심 복습

트리거–처리–결과, 표현식, 구글 시트·Gmail·Gemini — 모두 같은 완성본에서 출발합니다

학습목표

  • 트리거–처리–결과 3단 구조로 워크플로우를 읽을 수 있습니다.
  • 표현식 {{ }}로 앞 노드의 값을 가져다 쓸 수 있습니다.
  • 구글 시트 기록, Gmail 발송, Gemini 안내문 작성을 한 워크플로우로 실행합니다.
  • 완성본 JSON을 가져오고 자격 증명을 다시 연결할 수 있습니다.

왜 이 단계가 필요한가

오늘 오후에는 앱 화면에서 들어온 민원을 n8n이 받아 처리합니다. 이때 받은 뒤의 처리, 곧 시트에 적고 메일을 보내고 안내문을 쓰는 부분은 기초과정에서 만든 것을 거의 그대로 씁니다. 바뀌는 것은 맨 앞의 시작 신호 하나뿐입니다. 그래서 오전에 이 처리 부분을 다시 손에 익혀 둡니다.

한 문장 요약 시작 신호(트리거)만 바꾸면 뒤의 일은 그대로 돌아갑니다. 오후에는 수동 실행과 샘플 민원 자리에 앱이 들어옵니다.
모든 결과 노드가 샘플 민원에 직접 이어진 이유 노드를 하나 지나면 넘어가는 값이 그 노드의 결과로 바뀝니다. 예를 들어 시트에 기록 뒤에 메일 노드를 이으면 메일 노드는 민원 내용이 아니라 "기록 결과"를 받게 됩니다. 그래서 세 결과 노드를 모두 샘플 민원에서 부챗살처럼 갈라 이었습니다.

따라하기

오늘은 모두 같은 완성본에서 시작합니다 기초과정 내용을 잘 기억하는 분도, 오랜만인 분도 1·2단계에서 같은 파일을 가져옵니다. 처음부터 다시 만드는 대신, 연결하고 실행하고 고쳐 보면서 기억을 되살립니다. 10단계까지가 필수이고, 11단계는 시간이 되는 만큼 합니다.
  1. 완성본 내려받기 아래 단추를 누릅니다. 파일은 보통 내 PC의 다운로드 폴더에 저장됩니다. 복습 완성본 내려받기 d1-p2.json
  2. n8n에 가져오기 n8n 첫 화면 오른쪽 위 Create workflow를 누릅니다. 빈 캔버스가 열리면 오른쪽 위 … → Import → From file을 누르고, 다운로드 폴더에서 d1-p2.json을 고릅니다.

    왼쪽부터 수동 실행, 샘플 민원, 세 갈래(시트에 기록, 접수 메일 보내기, AI 안내문 작성), 그리고 AI 안내문 작성 아래 작은 동그라미 Google Gemini Chat Model까지 노드 6개가 보이면 성공입니다. 몇몇 노드의 경고 표시는 정상이며, 4~9단계에서 연결합니다.

  3. 기록할 구글 시트 준비하기 먼저 브라우저 오른쪽 위 동그란 프로필 사진을 눌러, 준비물로 만든 개인 구글 계정으로 로그인돼 있는지 확인합니다. 4단계에서도 같은 계정을 고릅니다.

    새 탭 주소창에 sheets.new를 입력하고 Enter를 눌러 새 구글 시트를 만듭니다. 왼쪽 위 제목 없는 스프레드시트를 눌러 이름을 민원대장 연습으로 바꿉니다. 첫째 줄 A1 칸을 누르고 아래 줄을 복사해 붙여 넣으면 여섯 칸에 나뉘어 들어갑니다.

    이름	연락처	이메일	종류	상세설명	등록일
    화면 아래쪽 탭 이름(보통 시트1)도 확인해 둡니다. 5단계에서 씁니다.

    첫째 줄에 여섯 단어가 한 칸씩 들어가면 성공입니다.

    해결 머리글을 위 여섯 단어와 한 글자도 다르지 않게 고치세요

  4. 시트에 기록에 구글 계정 연결하기 시트에 기록 노드를 두 번 눌러 엽니다. 맨 위 Credential 칸을 누르면 보이는 Create new credential(화면에 따라 Connect to …)을 누르고, Sign in with Google → 3단계에서 확인한 계정 선택 → 허용 순서로 진행합니다. 구글 로그인 창이 뜨지 않으면 주소창 오른쪽의 팝업 차단 표시를 눌러 허용하세요. 허용 화면에 체크 칸이 있으면 모두 체크합니다.

    이렇게 만든 연결을 자격 증명(n8n이 내 구글·텔레그램 계정을 대신 쓰도록 맡겨 둔 열쇠)이라고 합니다. Account connected가 보이면 성공입니다. 자격 증명 창 오른쪽 위 X로 닫으면 시트에 기록 설정 창으로 돌아옵니다.

    자주 하는 실수

    해결 준비물로 만든 개인 구글 계정으로 다시 시도하세요

    증상 5단계 목록에 내 시트가 없거나, 실행하면 권한 오류가 나요
    원인 시트를 만든 구글 계정과 n8n에 연결한 구글 계정이 달라요
    해결 시트 오른쪽 위 프로필 사진으로 계정을 확인하고, 같은 계정으로 시트를 새로 만들거나 자격 증명을 다시 연결하세요

  5. 내 시트 고르기 시트에 기록 설정 창에서 Document 칸 왼쪽 작은 목록을 눌러 From list로 바꾸고, 목록에서 민원대장 연습을 고릅니다. Sheet 칸에 이미 시트1이 들어 있고 3단계에서 본 탭 이름도 시트1이면 그대로 둡니다. 다르면 칸 왼쪽 목록을 From list로 바꾸고 내 탭 이름을 고릅니다. 목록에 시트가 없으면 By ID로 두고 여기에_본인_시트_ID를 지운 뒤, 시트 주소 가운데 /d/와 /edit 사이의 긴 글자(시트 ID)를 붙여 넣습니다.

    아래쪽에 이름~등록일 여섯 칸이 fx 표시와 함께 보이면 성공입니다. 창 바깥 빈 곳을 눌러 캔버스로 돌아갑니다.

  6. Gmail 연결하기 접수 메일 보내기를 두 번 눌러 열고 4단계와 같은 방법으로 같은 구글 계정을 연결합니다(Gmail용 자격 증명이 따로 하나 생깁니다).

    Credential 칸에 Gmail 자격 증명 이름이 보이면 성공입니다. 창 바깥 빈 곳을 눌러 캔버스로 돌아갑니다.

  7. 받는 사람 바꾸기 샘플 민원을 두 번 눌러 엽니다. 이메일 칸의 본인이메일@example.com을 지우고, 6단계에서 연결한 내 Gmail 주소를 중괄호 없이 그대로 적습니다. 접수 메일 보내기의 To 칸이 {{ $json.이메일 }}이라서, 여기 적은 주소로 메일이 갑니다.

    이메일 칸에 내 Gmail 주소가 보이면 성공입니다.

    자주 하는 실수

    증상 실행은 초록색인데 메일이 오지 않아요

    해결 이메일 칸을 내 Gmail 주소로 바꾸고 다시 실행하세요

  8. Gemini 연결하기 AI 안내문 작성 아래 점선으로 매달린 작은 동그라미 Google Gemini Chat Model을 두 번 눌러 엽니다. Credential 칸에서 Create new credential을 누릅니다. Use Gateway credits와 Use my own credential 선택지가 보이면 Use my own credential을 고릅니다. API Key 칸에 준비물에서 발급받은 API 키(Gemini를 쓸 수 있게 해 주는 비밀 번호표)를 붙여 넣고, Host는 그대로 둔 채 저장합니다. 키를 적어 둔 곳을 못 찾으면, 키를 발급받았던 화면(aistudio.google.com/apikey)에서 다시 복사할 수 있습니다.

    저장한 뒤 연결에 성공했다는 표시가 보이면 성공입니다. X로 자격 증명 창을 닫습니다.

    API 키는 비밀번호처럼 API 키가 보이는 화면을 찍어 공유하거나 메신저로 보내지 마세요. 남이 내 키로 Gemini를 쓸 수 있습니다.
  9. 모델 고르기 같은 창의 Model 칸에 이미 이름이 적혀 있어도, 목록을 열어 models/gemini-3.8-flash를 한 번 더 누릅니다. 목록에는 내 API 키로 쓸 수 있는 모델만 보이기 때문에, 내 키로 다시 골라 두는 것입니다.
    자주 하는 실수

    증상 Model 목록이 비어 있거나 원하는 모델이 없어요

    해결 자격 증명을 열어 API 키를 다시 붙여 넣으세요. models/gemini-3.8-flash가 없으면 models/gemini-3.5-flash-lite를 고르세요

  10. 실행하고 결과 세 곳 확인하기 열려 있는 창을 모두 닫고 캔버스로 돌아온 뒤, 아래쪽 Execute workflow를 누릅니다.

    모든 노드에 초록색 표시가 생기면, 아래 세 곳을 확인합니다.

    • 구글 시트 민원대장 연습에 홍길동 민원 한 줄이 생겼나요?
    • 내 Gmail(받은편지함에 없으면 스팸함도)에 제목이 민원 접수인 메일이 왔나요?
    • AI 안내문 작성 노드를 열었을 때 오른쪽 결과에 안내문이 보이나요?
    메일 본문이 담당팀께로 시작하는 것은 기초과정 본문을 그대로 쓴 것입니다. 실습에서는 결과 확인을 위해 내 주소로 받습니다.
    빨간 노드가 생겼을 때 빨간 노드를 두 번 눌러 열면 오른쪽에 오류 글이 보입니다. 시트에 기록이면 3~5단계, 접수 메일 보내기면 6·7단계, AI 안내문 작성이나 Google Gemini Chat Model이면 8·9단계로 돌아가 확인하세요. 오류 글에 사용량 초과(quota) 같은 말이 있으면 Model을 models/gemini-3.5-flash-lite로 바꾸고 다시 실행하세요.
    AI 안내문은 초안입니다 AI는 사실이 아닌 내용도 그럴듯하게 쓸 수 있습니다. 처리 기한·담당 부서·법령 같은 내용은 반드시 사람이 확인한 뒤 보냅니다.

    여기까지 오면 이 교시의 필수는 끝났습니다.

  11. 표현식과 샘플 민원 고쳐 보기 이름·연락처에는 본인이나 지인의 실제 정보 대신 가상 이름(홍길동·김민원 등)만 씁니다.

    ① 접수 메일 보내기를 열고 Subject 칸에 마우스를 올려 Expression을 누릅니다. 칸을 누르고 Ctrl+A로 글자를 모두 고른 뒤 Delete로 지우고, 아래 글을 붙여 넣습니다.

    [{{ $json.종류 }}] 민원 접수 - {{ $json.이름 }}

    ② 샘플 민원을 열어 이름을 김민원, 종류를 음식물, 상세설명을 매주 화요일 음식물 쓰레기 수거가 되지 않고 있습니다.로 바꿉니다.

    ③ 창을 닫고 다시 Execute workflow를 누릅니다. 시트에 줄이 하나 더 생기는 것은 정상입니다.

    시트의 새 줄과 AI 안내문이 김민원·음식물 내용으로 바뀌고, 메일 제목이 [음식물] 민원 접수 - 김민원이면 성공입니다. 재료(샘플 민원)를 바꾸면 결과 세 곳이 함께 바뀝니다. 오후에는 이 재료를 앱이 채웁니다.

    자주 하는 실수

    증상 메일 제목에 {{ $json.종류 }} 글자가 그대로 찍혀요
    원인 Subject 칸이 표현식 모드가 아니라 글자 그대로(Fixed) 모드예요
    해결 칸에 마우스를 올려 Expression을 누르세요. 칸 왼쪽에 fx가 보이면 표현식 모드입니다

Webhook 이해와 실습

앱과 자동화가 대화하는 방법 — n8n에 "부르면 답하는 주소"를 만듭니다

학습목표

  • Webhook을 "외부 앱이 n8n을 부르는 주소"로 설명할 수 있습니다.
  • Test URL로 시험하고, Publish한 뒤 Production URL을 쓰는 순서를 압니다.
  • Respond to Webhook 노드로 부른 쪽에 답을 돌려주고, 브라우저 주소창으로 확인합니다.

왜 이 단계가 필요한가

기초과정에서는 n8n이 만들어 준 입력 폼으로 민원을 받았습니다. 오늘 오후에는 우리가 직접 만든 앱 화면에서 민원을 보냅니다. 그러려면 앱이 n8n을 찾아와 문을 두드릴 수 있는 주소가 있어야 합니다. 그 주소가 Webhook(외부 앱이 n8n을 부르는 주소)입니다.

민원실에 비유하면 다음과 같습니다.

민원실오늘 배우는 것하는 일
민원실 입구의 초인종Webhook 주소누군가 누르면 n8n이 일을 시작합니다
창구 직원워크플로우받은 내용을 기록하고, 메일을 보내고, 안내문을 씁니다
접수증 건네기Respond to Webhook(부른 쪽에 "잘 받았어요"라고 답장을 보내는 노드)앱 화면에 접수번호 같은 답을 돌려줍니다
출입 허락 명단CORS(다른 주소의 앱이 n8n을 불러도 되는지 정하는 허락 규칙)브라우저가 "이 앱이 불러도 되나?"를 확인합니다

Webhook 주소는 두 개가 있습니다.

  • Test URL(만드는 중에 시험할 때 쓰는 주소) — 시험 버튼을 누르고 기다리는 동안 한 번만 동작합니다.
  • Production URL(워크플로우를 게시한 뒤 앱에 넣는 진짜 주소) — 화면 위쪽 Publish(워크플로우를 게시해 주소가 항상 동작하게 하는 버튼)를 누른 뒤부터 언제든 동작합니다.
한 문장 요약 만들 때는 Test URL로 시험하고, 다 만들면 Publish한 뒤 Production URL을 앱에 넣습니다. 이 순서만 지키면 "앱에서 눌렀는데 아무 일도 안 일어나요"의 대부분이 사라집니다.
CORS는 오늘 "설정만" 합니다 CORS 검사는 앱 화면이 n8n을 부를 때 브라우저가 합니다. 오늘은 주소창에 주소를 붙여 넣어 부르기 때문에 이 검사를 받지 않습니다. 그래서 오늘은 허락 명단을 미리 적어 두기만 하고, 실제로 효과를 확인하는 것은 6교시에 앱과 연결할 때 합니다.

따라하기

이름을 넣어 부르면 "안녕하세요, 홍길동님"이라고 답하는 작은 워크플로우를 만듭니다. 오후에 만들 민원 접수의 뼈대입니다.

  1. 새 워크플로우 만들기 n8n 첫 화면에서 Create workflow를 누릅니다.

    가운데에 +가 있는 빈 캔버스가 보이면 성공입니다.

  2. Webhook 노드 추가하기 캔버스 가운데의 +를 누르고 검색창에 Webhook을 입력합니다. 목록에 Respond to Webhook도 보이지만, 이름이 딱 Webhook인 것을 고릅니다.

    Webhook 설정 창이 열리면 성공입니다.

  3. 받는 방식과 주소 끝부분 정하기 HTTP Method가 GET인지 확인합니다. Path 칸의 글자를 모두 지우고 hello를 입력합니다. GET은 브라우저 주소창에 주소를 넣어 부르는 방식입니다. 오후에 앱이 민원을 보낼 때는 POST라는 다른 방식을 씁니다. Path는 주소의 맨 끝부분이며, 알아보기 쉬운 영어 단어로 정합니다.

    설정 창 위쪽 주소가 …/hello로 끝나면 성공입니다.

  4. 답장 방식 바꾸기 Respond를 Using 'Respond to Webhook' Node로 바꿉니다.

    Respond 칸에 Using 'Respond to Webhook' Node가 보이면 성공입니다.

    자주 하는 실수

    증상 우리가 쓴 인사말 대신 {"message":"Workflow was started"}만 보여요
    원인 Respond가 기본값 Immediately로 남아 있어요
    해결 Using 'Respond to Webhook' Node로 바꾸세요

  5. CORS 허락 명단 미리 적기 (체크리스트 1번) 설정 창 아래 Add Option을 누르고 Allowed Origins (CORS)를 고릅니다. 칸에 *가 들어 있는지 봅니다. 비어 있으면 *를 입력합니다. *는 "어느 주소의 앱이든 불러도 좋다"는 뜻입니다. 실습에서는 이 값을 씁니다. 실제 부서에 적용할 때는 우리 앱 주소만 적는 것이 안전합니다(2일차 3교시).

    Allowed Origins (CORS) 칸에 *가 보이면 성공입니다. 설정 창 바깥의 빈 곳을 누르거나 창을 닫아 캔버스로 돌아갑니다. Webhook 노드 하나가 보이면 됩니다.

  6. Respond to Webhook 노드 붙이기 Webhook 노드 오른쪽의 +를 누르고 Respond to Webhook을 검색해 고릅니다.

    두 노드가 선으로 이어지고 Respond to Webhook 설정 창이 열리면 성공입니다.

  7. 답장 글 넣기 Respond With를 JSON으로 바꿉니다. Response Body 글자 근처에 마우스를 올리면 Fixed와 Expression이 나타납니다. Expression을 누릅니다. 칸 안을 누르고 Ctrl+A로 이미 들어 있는 글자를 모두 고른 뒤 Delete로 지웁니다. 칸이 비었으면 아래 글을 복사해 붙여 넣습니다. 
    {
  "메시지": "안녕하세요, {{ $json.query.이름 }}님. 잘 받았습니다."
}

    {{ $json.query.이름 }}는 기초과정에서 배운 표현식(앞 노드의 값을 가져다 쓰는 문장)입니다. 다음 단계에서 주소 끝에 붙여 보낼 이름 값을 꺼내 옵니다.

    칸 아래 미리보기에서 이름 자리가 비어 보여도 괜찮습니다. 아직 이름을 보내지 않았기 때문이며, 다음 단계에서 채워집니다.

  8. Test URL로 시험하기 시간 제한이 있으므로 아래 순서대로 준비한 다음 시험합니다.
    1. Webhook 노드를 열고 위쪽에서 Test URL을 골라 주소를 복사합니다.
    2. 브라우저에서 새 탭을 열고, 주소창에 복사한 주소를 붙여 넣은 뒤 끝에 ?이름=홍길동을 이어서 씁니다. 아직 Enter는 누르지 않습니다.
    3. n8n 탭으로 돌아와 Listen for test event를 누릅니다.
    4. 2분 안에 새 탭으로 가서 Enter를 누릅니다.
    https://(내 n8n 주소)/webhook-test/hello?이름=홍길동
    위 주소는 모양을 보여 주는 예입니다. 직접 치지 말고 n8n에서 복사한 주소를 쓰세요. 주소 끝의 ?이름=홍길동은 "이름은 홍길동"이라는 값을 n8n에 함께 보내는 부분입니다. ?와 =는 영어 자판으로 입력하고 띄어 쓰지 않습니다. 이름 자리에는 본인 실명 대신 홍길동·김민원 같은 가상 이름만 넣습니다. 보낸 값은 실행 기록에 남습니다.

    브라우저 화면에 "안녕하세요, 홍길동님. 잘 받았습니다."라는 글이 보이면 성공입니다(앞뒤 기호 모양은 조금 달라도 됩니다). n8n 캔버스의 두 노드에도 초록색 표시가 생깁니다.

    자주 하는 실수

    증상 The requested webhook "…" is not registered.라는 글이 보여요
    원인 Listen for test event를 누르지 않았거나, 누른 뒤 2분이 지났거나, 이미 한 번 불렀어요(Test URL은 한 번만 동작)
    해결 Listen for test event를 다시 누르고 곧바로 새 탭에서 Enter를 누르세요

    증상 "안녕하세요, 님."처럼 이름이 빠져 있어요
    원인 주소 끝의 이름과 표현식 $json.query.이름의 글자가 서로 달라요(예: ?이룸=)
    해결 두 곳 모두 "이름" 두 글자로 똑같이 맞추고, Listen for test event를 다시 누른 뒤 부르세요

  9. Publish하기 화면 위쪽의 Publish를 누르고, 뜨는 창에서 다시 Publish를 누릅니다.

    확인 창이 닫히고 위쪽 Publish 버튼 자리의 모양이 [그림 1-3-8]처럼 바뀌면 성공입니다.

    설정을 바꾸면 다시 Publish Publish한 뒤에 설정을 고치면, Production URL은 다시 Publish할 때까지 예전 설정으로 동작합니다. "고쳤는데 그대로예요"라고 느껴지면 Publish부터 다시 누르세요.
  10. Production URL로 시험하기 Webhook 노드를 열고 위쪽에서 Production URL을 골라 주소를 복사합니다. 새 탭 주소창에 붙여 넣고 끝에 ?이름=김민원을 붙여 Enter를 누릅니다. 이번에는 기다리는 버튼을 누르지 않아도 되고, 시간 제한도 없습니다. 
    https://(내 n8n 주소)/webhook/hello?이름=김민원

  2. n8n에서 가져오기 새 워크플로우 화면 오른쪽 위 … → Import → From file을 누르고 내려받은 파일을 고릅니다. 파일 내용을 복사해 빈 캔버스에 Ctrl+V로 붙여 넣어도 됩니다.
  3. 자격 증명 확인하기 이 연습 워크플로우에는 자격 증명(n8n이 내 구글·텔레그램 계정을 대신 쓰도록 맡겨 둔 열쇠)이 필요한 노드가 없어서 다시 연결할 것이 없습니다. 다른 교시에서는 이 단계에서 경고 표시가 뜬 노드를 열어 내 자격 증명을 고릅니다.
  4. Publish하고 시험하기 화면 위쪽 Publish를 누르고, 뜨는 창에서 다시 Publish를 누릅니다. Webhook 노드를 열어 위쪽에서 Production URL을 골라 주소를 복사합니다. 새 탭 주소창에 붙여 넣고 끝에 ?이름=홍길동을 붙여 Enter를 누릅니다. 인사말이 보이면 복구 완료입니다.

AI 앱 빌더 첫 체험

Google AI Studio의 Build 모드에서 문장만으로 민원 접수 화면을 만듭니다

학습목표

  • Build 모드 화면의 입력창, 미리보기, Code 탭을 구분합니다.
  • 문장(프롬프트)으로 앱이 만들어지는 원리를 설명할 수 있습니다.
  • 프롬프트 템플릿으로 민원 접수 화면을 만듭니다.

왜 이 단계가 필요한가

오전에 만든 n8n 워크플로우는 일을 하는 사람이고, 3교시에 만든 Webhook(외부 앱이 n8n을 부르는 주소)은 그 사람을 부르는 초인종입니다. 그런데 민원인이나 동료가 직접 들어와 내용을 적을 창구 화면이 아직 없습니다. 이번 시간에는 그 화면을 만듭니다.

화면을 만들려면 원래 프로그래밍이 필요하지만, 오늘은 Google AI Studio(문장으로 앱 화면을 만들어 주는 구글의 무료 도구)가 대신 만듭니다. AI Studio 안에서 앱을 만드는 화면을 Build 모드라고 부릅니다. 우리는 어떤 화면이 필요한지 주문서를 씁니다. 이 주문서가 프롬프트(AI에게 시키는 일을 적은 문장)입니다.

우리가 하는 일AI Studio가 하는 일
어떤 칸과 버튼이 필요한지 한국어로 적는다그 화면을 만드는 코드를 쓴다
미리보기에서 눌러 보고 확인한다코드를 실행해 미리보기에 보여 준다
고칠 점을 다시 문장으로 요청한다(5교시)코드를 고친다

좋은 주문서는 구체적입니다. 오늘 쓰는 템플릿은 세 부분으로 되어 있습니다.

  • [화면] — 제목, 입력 칸의 이름과 순서, 버튼
  • [접수하기를 눌렀을 때] — 누른 뒤 일어날 일. 6교시에 n8n 주소를 넣을 자리(WEBHOOK_URL)도 미리 만들어 둡니다
  • [넣지 말 것] — 필요 없는 기능을 빼라고 분명히 말합니다
한 문장 요약 화면은 AI가 코드로 만들고, 우리는 주문서(프롬프트)를 쓰고 확인만 합니다. 코드는 직접 고치지 않습니다.
옆 사람과 화면이 달라도 정상입니다 AI는 같은 주문서로도 매번 조금씩 다른 결과를 만듭니다. 색이나 배치가 달라도 괜찮습니다. 확인할 것은 3단계의 세 가지뿐입니다.

[화면]
- 맨 위 제목: 민원 접수
- 제목 아래 안내 한 줄: 아래 내용을 적고 접수하기를 누르세요.

  2. 연락처 (안내 글: 예) 010-1234-5678)
  3. 이메일 (안내 글: 예) minwon@example.com)
  4. 종류 — 생활, 음식물, 대형 세 가지 중에서 고르는 목록
  5. 상세설명 — 여러 줄을 쓸 수 있는 칸

[접수하기를 눌렀을 때]
- 빈 칸이 있으면 어느 칸이 비었는지 알려 줘.
- 코드 맨 위에 WEBHOOK_URL 이라는 상수를 만들고 값은 빈 문자열("")로 둬.
- WEBHOOK_URL이 비어 있으면 화면에 "아직 접수 창구와 연결되지 않았습니다. 6교시에 연결합니다."라고 보여 줘.
- WEBHOOK_URL이 비어 있지 않으면, 입력한 값을 JSON으로 WEBHOOK_URL에 POST 방식으로 보내.

- 응답으로 받은 JSON의 "접수번호"와 "메시지"를 접수 완료 화면에 크게 보여 주고, "새 민원 접수" 버튼으로 처음 화면에 돌아가게 해.
- 보내는 중에는 버튼을 "접수 중…"으로 바꾸고, 실패하면 "접수하지 못했습니다. 잠시 뒤 다시 시도해 주세요."를 보여 줘.

[넣지 말 것]

    [접수하기를 눌렀을 때]에 나오는 WEBHOOK_URL, 상수, JSON, POST는 AI에게 하는 말입니다. 뜻을 몰라도 그대로 붙여 넣으면 됩니다. 위 상자에서 복사가 잘 안 될 때만 프롬프트 파일을 여세요. 연 뒤에는 브라우저의 뒤로 가기(←)로 이 교안에 돌아옵니다.

    붙여 넣은 뒤 입력창 오른쪽 아래의 보내기 버튼(화살표 모양)을 누릅니다. Enter는 줄만 바뀔 수 있으니 버튼을 누르세요.

    왼쪽에 AI의 작업 과정 글(영어일 수 있습니다)이 올라오기 시작하면 성공입니다. 읽지 않아도 됩니다. 앱이 완성될 때까지 1~3분쯤 걸립니다. 기다리는 동안 다른 요청을 보내지 않습니다.

    원인 프롬프트의 일부만 복사해 붙여 넣었어요
    해결 위 상자 안의 글을 처음부터 끝까지 다시 복사해 새 앱으로 만들거나, 왼쪽 아래 입력창에 "빠진 칸을 추가해 줘"라고 요청하세요

한 번에 너무 많이 요청하지 않기 AI Studio는 무료지만 사용량 한도가 있습니다. 결과가 마음에 들지 않는다고 새 앱을 여러 번 만들지 말고, 5교시에 배우는 "고쳐 달라고 요청하기"를 쓰세요. 한도에 걸리면 사용량을 넘었다는 영어 안내가 뜹니다. 이때는 강사에게 알리세요.

  3. 강사가 준비한 경우에는 Gemini 앱의 Canvas로 같은 프롬프트를 넣어 화면을 만들어 볼 수 있습니다.

첫 앱 다듬기

화면은 문장으로 고치고, 오류는 정해진 루틴으로 AI에게 고치게 합니다

학습목표

  • 원하는 화면 변경을 구체적인 문장으로 요청할 수 있습니다.
  • 오류가 나면 "오류 문구 복사 → AI에 붙여 넣고 고쳐 달라고 요청" 루틴을 스스로 해냅니다.

왜 이 단계가 필요한가

4교시에 만든 화면은 첫 초안입니다. 실제로 쓰려면 기관 이름을 넣고, 개인정보 동의를 받는 등 손볼 곳이 생깁니다. 또 AI가 만든 코드는 가끔 틀립니다. 오류가 나는 것은 내 잘못이 아니며, 알려 주면 AI가 고칩니다. 이번 시간에는 고쳐 달라고 말하는 법과 오류가 났을 때 알려 주는 법을 익힙니다.

고쳐 달라는 말도 AI에게 주는 프롬프트(AI에게 시키는 일을 적은 문장)입니다. 좋은 수정 요청에는 세 가지가 있습니다.

  • 한 번에 한 가지 — 여러 가지를 한꺼번에 바꾸면 무엇이 잘못됐는지 찾기 어렵습니다.
  • 어디를 · 어떻게 — "제목을", "접수하기 버튼을"처럼 위치를, "진한 파란색으로"처럼 결과를 적습니다.
  • 바꾸면 안 되는 것 — "입력 칸은 그대로 둬"를 덧붙입니다. 칸 이름과 WEBHOOK_URL은 6교시 연결 약속입니다.

오류 대처 루틴 (앞으로 계속 씁니다)
  1. 찾기 — 오른쪽 미리보기나 대화 패널에서 영어로 된 오류 글을 찾습니다([그림 1-5-3]).
  2. 신고 문장 먼저 — "오류 신고 문장"을 대화 입력창에 붙여 넣어 둡니다(아직 보내지 않음).
  3. 오류 글 끼워 넣고 보내기 — 오류 글을 복사해 신고 문장의 오류: 아래에 붙여 넣고 보냅니다.
  4. 확인 — 미리보기에서 다시 눌러 봅니다. 두 번 해도 안 되면 손을 듭니다.

2번과 3번의 순서가 중요합니다. Ctrl+C는 마지막에 복사한 것 하나만 기억하기 때문입니다.

따라하기

A. 화면 고쳐 달라고 요청하기

  1. 4교시 앱 다시 열기 AI Studio(aistudio.google.com/apps) 왼쪽 메뉴의 Apps를 누르고, 목록 맨 위(가장 최근)의 앱을 누릅니다. 앱 이름은 영어일 수 있습니다.

    오른쪽 미리보기에 민원 접수 화면이 보이면 성공입니다.

    앱을 찾지 못하면 4교시 따라하기 2단계의 프롬프트를 다시 붙여 넣어 새로 만듭니다(3분). 다 만들어지면 브라우저의 뒤로 가기(←)로 이 교안에 돌아옵니다.
  2. 요청 1 — 제목과 안내 문구 바꾸기 아래 글을 대화 입력창에 붙여 넣습니다. OO를 끌어서 고르고 기관 이름(예: 가나구)을 치면 됩니다. 바꾸지 않아도 됩니다. 그다음 보냅니다. 
    맨 위 제목을 "OO구 민원 접수"로 바꾸고, 제목 아래에 작은 글씨로 "평일 09:00~18:00 확인 후 연락드립니다."를 한 줄 더해 줘. 입력 칸과 버튼은 그대로 둬.

    미리보기의 제목과 안내 문구가 바뀌고 입력 칸은 그대로면 성공입니다.

  3. 요청 3 — 개인정보 동의 칸 넣기 아래 글을 대화 입력창에 붙여 넣고 보냅니다. 
    "접수하기" 버튼 바로 위에 "개인정보 수집·이용에 동의합니다(필수)" 체크 칸을 넣어 줘. 체크하지 않으면 접수되지 않고 "개인정보 수집·이용에 동의해 주세요."라고 알려 줘. 이 체크 여부는 보내는 JSON에 넣지 마.
    JSON, 함수, 괄호 같은 말은 AI에게 하는 말입니다. 뜻을 몰라도 그대로 붙여 넣으면 됩니다.

    미리보기에 가상 값(이름 홍길동, 연락처 010-1234-5678, 이메일 minwon@example.com, 종류 생활, 상세설명 보도블록이 깨져 있습니다.)을 모두 넣고, 동의 칸만 비운 채 접수하기를 누릅니다. "개인정보 수집·이용에 동의해 주세요."가 뜨면 성공입니다. 실제 이름·연락처는 넣지 않습니다.

  4. 접수하기로 확인하기 이번에는 동의 칸에 체크하고 접수하기를 누릅니다.

    "아직 접수 창구와 연결되지 않았습니다"가 뜨면 성공입니다.

  5. Code 탭에서 주소 자리 확인하기 미리보기 위쪽의 Code 탭을 누르고, 4교시 5단계([그림 1-4-4])처럼 코드 영역을 한 번 누른 뒤 Ctrl+F로 WEBHOOK_URL을 검색합니다. 코드 영역을 누른 뒤에는 글자를 치지 않습니다.

    WEBHOOK_URL이 보이면 성공입니다. 확인했으면 미리보기 탭을 눌러 돌아갑니다. 화면을 고칠 때마다 4·5단계 확인을 한 번씩 하는 습관을 들입니다.

    자주 하는 실수

    증상 입력 칸 이름이 바뀌었어요(예: 이름이 성함으로)
    원인 AI가 칸 이름까지 손봤어요
    해결 "입력 칸 이름을 이름, 연락처, 이메일, 종류, 상세설명으로 원래대로 되돌려 줘"라고 보내세요. 칸 이름이 다르면 6교시에 n8n이 값을 찾지 못합니다

    증상 WEBHOOK_URL이 코드에서 안 보여요
    원인 화면을 고치면서 AI가 그 줄을 옮기거나 지웠어요
    해결 먼저 다른 파일도 열어 Ctrl+F로 찾아보세요. 없으면 "코드 맨 위에 WEBHOOK_URL 상수를 빈 문자열로 다시 만들고, 접수하기를 누르면 그 주소로 보내게 해 줘"라고 보내세요

  6. (시간이 남으면) 요청 2와 되돌리기 연습 옆 사람보다 늦었다면 이 단계는 건너뛰고 B로 갑니다. 아래 요청 2를 보내 색과 버튼을 바꿔 봅니다. 
    배경을 아주 연한 하늘색으로, "접수하기" 버튼은 진한 파란색 바탕에 흰 글씨로 바꾸고 버튼을 화면 가로 폭에 꽉 차게 해 줘. 입력 칸의 이름과 순서는 바꾸지 마.

    색이 바뀌었으면, 마음에 들지 않는다고 생각하고 아래 글로 되돌립니다. 색이 원래대로 돌아가면 성공입니다.

    방금 바꾼 것을 되돌려서 바로 전 상태로 돌아가 줘.
    대화 패널에 Restore 같은 되돌리기 버튼이 보여도 오늘은 누르지 않습니다. 어느 요청의 버튼을 누르느냐에 따라 여러 단계가 한꺼번에 사라질 수 있습니다.

B. 오류 대처 루틴 연습 (두 번 반복)

  1. 연습용 오류 만들기 (1회차) 아래 글을 대화 입력창에 붙여 넣고 보냅니다. 
    연습을 위해 일부러 오류를 하나 만들어 줘. "접수하기" 버튼을 누르면 화면에 오류 문구가 뜨도록, 버튼을 눌렀을 때 실행되는 코드 안에서 존재하지 않는 함수를 부르게 바꿔 줘. 오류는 고치지 말고 그대로 둬. 다른 부분은 바꾸지 마.

    바뀐 뒤 A-3과 같은 가상 값을 넣고 동의에 체크한 다음 접수하기를 누릅니다. 미리보기나 대화 패널에 오류 글(보통 영어, 예: … is not defined)이 보이면 성공입니다. 읽지 않아도 됩니다.

    오류 대신 "아직 접수 창구와 연결되지 않았습니다"가 뜨면 AI가 오류를 만들지 않았거나 스스로 고친 것입니다. 이때는 2단계대로 신고 문장을 입력창에 붙여 넣고, 오류 글 대신 아래 연습용 오류 문구를 복사해 오류: 아래에 붙여 넣는 데까지만 연습합니다. 보내지 않습니다. 
    Uncaught ReferenceError: sendMinwonNow is not defined
    붙여 넣었으면 입력창을 누르고 Ctrl+A, Delete로 비웁니다. 입력창이 비면 이 연습은 끝입니다. 4단계(2회차)로 갑니다.
  2. 오류 신고 문장 먼저 붙여 넣기 아래 문장을 복사해 대화 입력창에 붙여 넣습니다. 아직 보내지 않습니다. 입력창 안의 (여기에 복사한 오류 문구를 붙여 넣기) 줄을 끌어서 고르고 Delete로 지웁니다. 
    아래 오류가 났어. 원인을 쉬운 말로 한 줄 설명하고 고쳐 줘. 입력 칸 이름과 WEBHOOK_URL은 바꾸지 마.

오류:
(여기에 복사한 오류 문구를 붙여 넣기)

    오류: 아래가 빈 줄이면 성공입니다.

  3. 오류 글 복사해 끼워 넣고 보내기 오류 글의 첫 글자 앞을 누른 채 끝까지 끌어서 고르고 Ctrl+C로 복사합니다. 입력창의 오류: 아래 빈 줄을 한 번 누르고 Ctrl+V로 붙여 넣은 뒤 보냅니다. 글이 선택되지 않으면 Win+Shift+S를 누릅니다. 화면이 조금 어두워지면 오류 부분을 네모로 끌어 고르고, 신고 문장이 들어 있는 입력창을 눌러 Ctrl+V로 그림을 붙여 보냅니다. F12 키로 열리는 화면(개발자 도구)은 쓰지 않습니다. 대화 패널에 오류를 고치는 버튼(예: Fix errors)이 보여도 오늘 연습에서는 누르지 않고 신고 문장을 씁니다.

    AI가 원인을 한 줄로 설명하고, 다시 접수하기를 눌렀을 때 "아직 접수 창구와 연결되지 않았습니다"가 뜨면 성공입니다.

    자주 하는 실수

    증상 입력창에 붙여 넣었더니 오류 글이 아니라 신고 문장이 또 들어가요
    원인 신고 문장을 나중에 복사해서, 복사해 둔 오류 글이 덮어써졌어요
    해결 입력창에 신고 문장이 이미 있으면 그대로 두고, 오류 글만 다시 복사해 오류: 아래에 붙여 넣으세요

    증상 대화 패널에 An internal error occurred. Retry. 같은 글이 떠요
    원인 앱이 아니라 AI 쪽에 잠깐 문제가 생겼어요
    해결 잠시 기다렸다가 같은 요청을 다시 보내세요. 이것은 오류 신고 문장을 쓸 상황이 아닙니다

  4. 두 번째 연습 (2회차) 이번에는 다른 오류로 1~3단계를 한 번 더 합니다. 아래 글을 붙여 넣고 보냅니다. 
    연습을 위해 일부러 오류를 하나 더 만들어 줘. 이번에는 앱이 열리자마자 미리보기에 오류가 보이도록, 화면을 그리는 코드에서 닫는 괄호 하나를 지워 줘. 오류는 고치지 말고 그대로 둬. 다른 부분은 바꾸지 마.

    미리보기가 다시 민원 접수 화면으로 돌아오면 성공입니다.

    미리보기가 하얗게 비어 있고 오류 글이 어디에도 보이지 않으면, 신고 문장의 오류: 아래에 "미리보기가 하얗게 비어 있고 아무것도 안 보여"라고 직접 적어서 보냅니다. 이것도 루틴 연습입니다.
  5. 6교시 준비 확인 가상 값을 넣고 동의 칸에 체크한 뒤 접수하기를 누릅니다. 이어서 Code 탭에서 WEBHOOK_URL을 찾습니다.

    "아직 접수 창구와 연결되지 않았습니다"가 뜨고 WEBHOOK_URL이 보이면 오늘 실습이 끝났습니다. 미리보기 탭으로 돌아가 둡니다.

오류가 끝내 안 고쳐질 때
  1. 아래 글을 보냅니다. 
    연습용으로 만든 오류를 모두 없애고, 오류 연습 요청을 보내기 전 상태로 되돌려 줘. 입력 칸 이름과 WEBHOOK_URL은 바꾸지 마.
  2. 그래도 안 되면 4교시 2단계 프롬프트로 새 앱을 만들고 요청 1·3을 다시 보냅니다(약 10분).
  3. 끝나면 B-5(6교시 준비 확인)를 합니다. 이 상태면 6교시를 시작할 수 있습니다.

앱 ↔ n8n 연동 ①

앱에 n8n 주소를 넣고, 앱에서 접수한 민원이 구글 시트에 한 줄로 쌓이게 합니다

학습목표

  • 앱에 n8n Production URL을 넣어 접수 데이터를 보낼 수 있습니다(Test URL로 먼저 시험한 뒤).
  • 받은 데이터가 구글 시트에 한 줄로 기록되는 것을 확인합니다.

왜 이 단계가 필요한가

지금까지 세 조각을 따로 만들었습니다. 2교시의 일하는 워크플로우, 3교시의 초인종인 Webhook(외부 앱이 n8n을 부르는 주소), 4·5교시의 창구 화면인 앱입니다. 이번 시간에 이 셋을 이어 붙여, 앱에서 누른 접수가 시트까지 가게 합니다.

순서누가무엇을
1앱(AI Studio)접수하기를 누르면 다섯 값을 봉투에 담아 n8n 주소로 보냅니다(이렇게 봉투에 담아 보내는 방식을 POST라고 부릅니다)
2민원 받기 (Webhook)봉투를 받습니다. 값은 봉투 안쪽 body에 들어 있습니다
3민원 정리 (Edit Fields)봉투에서 값을 꺼내 2교시와 같은 모양(이름, 연락처 …)으로 정리합니다
4시트에 기록2교시에 쓰던 노드를 그대로 가져와 한 줄을 적습니다

이번에는 앱 화면(AI Studio 주소)이 n8n(다른 주소)을 부르기 때문에, 브라우저가 "이 앱이 불러도 되나?"를 검사합니다. 이것이 CORS(다른 주소의 앱이 n8n을 불러도 되는지 정하는 허락 규칙)입니다. 3교시에 미리 적어 둔 허락 명단(Allowed Origins (CORS))이 오늘 처음으로 쓰입니다.

오늘의 순서: 시험 먼저, 그다음 사용 주소는 두 개입니다. 먼저 Test URL(만드는 중에 시험할 때 쓰는 주소)을 앱에 넣어 한 번 보내 보고, 잘 되면 Publish(워크플로우를 게시해 주소가 항상 동작하게 하는 버튼)를 누른 뒤 Production URL(워크플로우를 게시한 뒤 앱에 넣는 진짜 주소)로 바꿉니다.

시간 기준: 15시 35분까지 6단계(시트 확인)를 마치지 못했으면 이 교시 끝 "완성본 가져오기"로 n8n 쪽을 맞추고 7단계부터 함께 합니다. 늦어도 7교시에 따라잡을 수 있습니다.

개인정보 주의 앱에는 교안의 가상 값만 넣습니다. 내 이름·전화번호를 넣으면 시트와 n8n 실행 기록에 그대로 남습니다. Production URL은 다른 사람에게 알리지 않습니다.

    • HTTP Method: POST (앱은 POST로 보냅니다)
    • Path: 들어 있는 글자를 모두 지우고 minwon만 적습니다

    • Respond: 기본값 그대로(7교시에 바꿉니다)

    설정 창 위쪽 주소가 …/webhook-test/minwon으로 끝나면 성공입니다.

  2. 앱에 Test URL 넣기 주소를 나중에 복사해야 지워지지 않습니다. 아래 순서를 지킵니다.
    1. 아래 문장을 복사해 AI Studio 대화 입력창에 붙여 넣습니다. 아직 보내지 않습니다.
    2. 입력창에서 {Test URL} 글자(중괄호 포함)를 끌어서 고르고 지웁니다. 따옴표 " "는 남깁니다.
    3. n8n 탭의 민원 받기 설정 창 위쪽에서 Test URL이 골라져 있는지 보고, 그 주소를 복사합니다.
    4. AI Studio 탭으로 돌아와 따옴표 사이를 한 번 누르고 Ctrl+V를 누른 뒤 보냅니다.
    코드 맨 위 WEBHOOK_URL 값을 "{Test URL}"로 바꿔 줘. 다른 부분은 바꾸지 마.

    AI의 답이 끝나고 미리보기가 다시 나타나면, Code 탭에서 Ctrl+F로 WEBHOOK_URL을 찾습니다(4교시 5단계와 같음). 따옴표 안에 webhook-test가 들어간 주소가 보이면 성공입니다. 확인했으면 미리보기 탭으로 돌아옵니다.

  3. 첫 시험 — 앱에서 보내 보기 Listen for test event를 누르면 n8n은 2분 동안만 기다립니다. 그래서 앱 입력을 먼저 끝내 둡니다.
    1. AI Studio 미리보기에 가상 값(홍길동 / 010-1234-5678 / minwon@example.com / 생활 / 보도블록이 깨져 있습니다.)을 넣고 동의에 체크합니다. 아직 누르지 않습니다.
    2. n8n 탭에서 민원 받기를 열고 Listen for test event를 누릅니다.
    3. 곧바로 AI Studio 탭으로 와서 접수하기를 누릅니다. 2분이 지났으면 2번부터 다시 합니다.

    성공 여부는 n8n 쪽으로 판단합니다. n8n에 다섯 값이 보였다면 앱 화면에 무엇이 뜨든(빈 접수번호, 실패 문구 모두) 이 단계는 성공입니다. 앱 화면의 답은 7교시에 고칩니다.

  2. HTTP Method가 POST인가요?
  3. 시험 중이면 Listen for test event / Execute workflow를 누르고 2분 안에 보냈나요? 실제 사용이면 Publish했나요?
  4. 앱의 WEBHOOK_URL이 지금 쓰는 주소(Test 또는 Production)와 같나요?
  5. 민원 정리의 이름과 시트 머리글이 같은가요?

확인 문제

객관식Q1. 앱이 보낸 이름은 민원 받기 결과의 어디에 들어 있나요?

  1. headers
  2. body
  3. query
  4. 시트
정답 확인

정답: ② POST로 보낸 값은 body 안에 들어옵니다. 그래서 민원 정리에서 꺼내 줍니다. query는 3교시처럼 주소 뒤 ?이름=홍길동으로 보낸 값이 들어가는 곳입니다.

단답형Q2. 시험이 끝나고 실제로 쓰기 전에 n8n에서 눌러야 하는 버튼은?

정답 확인

정답: Publish — 그다음 앱의 주소를 Production URL로 바꿉니다.

정리

  • 앱 → 민원 받기 → 민원 정리 → 시트에 기록으로 이어져, 앱에서 누른 민원이 시트에 쌓입니다.
  • Test URL로 먼저 시험하고, Publish한 뒤 Production URL로 바꿉니다.
  • 앱에서 n8n을 부를 수 있었다면 CORS 허락 명단이 제 역할을 한 것입니다.
  • 다음: 7교시에는 접수번호를 만들어 앱 화면에 돌려주고, 1일차를 정리합니다.

완성본 가져오기(Import)

이 파일을 가져오면 n8n 쪽이 이 교시의 세 노드 연결 상태가 됩니다. 5단계까지 하면 앱에서 바로 접수할 수 있습니다.

먼저: 따라 만들던 워크플로우를 Publish했다면 그 워크플로우의 Publish 옆 목록에서 Unpublish를 누르세요. 같은 주소 끝부분(minwon)과 같은 방식(POST)을 쓰는 Webhook은 하나만 동작할 수 있습니다.
  1. 파일 내려받기 워크플로우 내려받기 d1-p6.json
  2. n8n에서 가져오기 Create workflow → 오른쪽 위 … → Import → From file을 누르고 파일을 고릅니다.
  3. 자격 증명 다시 연결하기 시트에 기록을 열어 Credential 칸에서 2교시에 만든 내 구글 시트 자격 증명을 고릅니다.
  4. 자리표시자 바꾸기 시트에 기록의 Document 칸 왼쪽 작은 목록(지금은 By ID)을 눌러 From list로 바꾼 뒤, 목록에서 민원대장 연습을 고릅니다. 여기에_본인_시트_ID 글자가 없어지면 됩니다. Sheet는 내 구글 시트 아래쪽 탭 이름과 같아야 합니다. 파일에는 시트1로 들어 있습니다. 내 탭 이름이 다르면(예: Sheet1) 목록에서 내 탭을 고릅니다.
  5. Publish하고 앱 주소 바꾸기 Publish → 확인 창의 Publish를 누르고, 따라하기 9단계 순서대로 민원 받기의 Production URL을 앱의 WEBHOOK_URL에 넣습니다. 앱에서 가상 민원을 접수해 시트에 줄이 생기면 복구 완료입니다.

앱 쪽이 망가졌다면 4교시 2단계의 주문 문장으로 앱을 새로 만들고 5교시 요청 1·3을 보낸 뒤, 위 5단계의 Production URL을 넣습니다.
