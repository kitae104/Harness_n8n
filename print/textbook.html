입과 안내 및 과정 소개

이틀 뒤에 손에 쥘 서비스를 먼저 봅니다 — 앱에서 접수하면 시트·메일·캘린더·AI 안내문까지

학습목표

  • 앱에서 민원을 접수하면 시트·메일·캘린더·텔레그램까지 이어지는 완성 서비스의 흐름을 말로 설명할 수 있습니다.
  • "화면은 AI가, 일은 n8n이" 역할 분담과, 가상 데이터만 쓰는 원칙·이틀간의 진행 방식을 압니다.
  • 사전조사한 자동화 희망 업무를 한 문장으로 공유합니다.

왜 이 과정이 필요한가

기초과정에서 n8n으로 민원 접수·기록·알림 자동화를 만들어 보셨습니다. 그런데 설문에서 가장 많이 나온 말은 "내 업무에 바로 쓰기는 어렵다"였습니다. 이유 하나는 입구가 없다는 것입니다. 워크플로우는 잘 돌아가도, 동료나 민원인이 들어와 내용을 적을 화면이 없으면 부서에서 함께 쓰기 어렵습니다.

이번 과정은 그 화면을 AI로 만들고, 기초과정에서 배운 n8n 자동화를 뒤에 붙여 하나의 서비스로 완성합니다.

역할누가하는 일
화면Google AI Studio(문장으로 앱 화면을 만들어 주는 구글의 무료 도구)입력 칸과 버튼이 있는 앱. 우리는 한국어 주문서만 씁니다
연결Webhook(외부 앱이 n8n을 부르는 주소)앱에서 누르면 n8n이 일을 시작하는 초인종
일n8n 워크플로우시트 기록, 메일, 캘린더, AI 안내문, 텔레그램 — 기초과정에서 배운 노드
한 문장 요약 화면은 AI가, 일은 n8n이 합니다. 우리는 코드를 한 줄도 쓰지 않고, 주문서를 쓰고 노드를 잇습니다.
개인정보 원칙 — 이틀 내내 지킵니다
  • 실습에는 교안에 나오는 가상 이름·연락처(홍길동, 010-1234-5678 등)만 씁니다.
  • 실제 민원 데이터, 공문, 동료·민원인의 실명과 연락처는 절대 넣지 않습니다. 입력한 값은 시트, n8n 실행 기록, AI 서비스에 남습니다.
  • 실제 부서에 적용하는 것은 2일차 3교시 점검표를 거쳐 기관 보안 담당과 협의한 뒤입니다.

활동

  1. 입과 안내 (5분) 강사·보조강사 소개, 쉬는 시간(매 교시 50분 수업 + 10분 휴식), 막혔을 때 손을 드는 방법을 안내합니다. 보조강사는 계정·권한 문제(구글 로그인, Gemini 키)와 오류 해결을 맡습니다.
  2. 완성 서비스 시연 (12분) 강사가 이틀 뒤의 완성본(2일차 2교시 결과)을 화면에 띄우고 차례로 보여 줍니다. 수강생은 따라 하지 않고 무엇이 어디서 일어나는지만 봅니다.
    1. 앱 화면에서 가상 민원(홍길동 / 010-1234-5678 / 생활 / 보도블록이 깨져 있습니다.)을 접수합니다.
    2. 앱에 접수번호(예: 2026-0922-001)와 AI가 쓴 안내문이 뜹니다.
    3. 구글 시트에 한 줄이 쌓입니다.
    4. 담당자 메일, 캘린더의 처리 마감 일정, 텔레그램 알림이 옵니다.
    5. 앱의 "처리 상태 조회"에 접수번호를 넣으면 처리 상태가 나옵니다.
    6. n8n 화면에서 이 모든 일을 한 워크플로우가 해냈다는 것을 보여 줍니다.
    강사 메모 시연 파일은 workflows/d2-p2.json입니다. 수업 전날 강사 계정 n8n Cloud에 가져와 계정 연결과 게시까지 마치고, 시연용 앱의 주소를 맞춰 둡니다(아래 "완성본 가져오기").
  3. 이틀 로드맵 (3분)
    시간1일차: n8n 다지기 + 첫 앱 + 연결2일차: 자동화 확장 + 내 업무 서비스
    1교시입과 안내·완성 서비스 시연담당자 메일·캘린더·AI 안내문
    2교시n8n 핵심 복습담당자 나누기·텔레그램·처리 상태 조회
    3교시Webhook 이해와 실습앱 배포·공유·보안
    4교시AI 앱 빌더 첫 체험내 업무 서비스 기획(설계서)
    5교시첫 앱 다듬기·오류 대처내 업무 서비스 제작 ①
    6교시앱 ↔ n8n 연동 ①내 업무 서비스 제작 ②
    7교시접수번호 회신·1일차 정리발표·피드백·적용 로드맵

    뒤처져도 괜찮습니다. 모든 교시 끝에 "완성본 가져오기"가 있습니다. 그 교시 끝 상태의 워크플로우 파일을 가져오면 다음 교시를 함께 시작할 수 있습니다.

  4. 준비물 점검 (10분) 아래를 하나씩 확인합니다. 안 되는 것은 바로 아래 "안 될 때" 박스를 보고, 그래도 안 되면 손을 듭니다. 보조강사가 돌아다니며 돕습니다.
    • 브라우저 오른쪽 위 프로필 사진을 눌렀을 때 보이는 이메일이 개인 Gmail인가요? (기관 메일이면 AI Studio나 구글 연결이 막힐 수 있습니다. AI Studio는 나이 확인이 된 성인 개인 계정만 쓸 수 있습니다)
    • n8n Cloud 계정에 로그인되나요? 무료 체험 기간이 이틀 안에 끝나지 않나요?
    • Gemini API 키(Gemini를 쓸 수 있게 해 주는 비밀 번호표)를 메모장 등에 저장해 두었나요?
    • aistudio.google.com/apps를 열었을 때 앱을 만드는 입력창이 보이나요?
    • 텔레그램 봇 토큰(내 알림 봇을 쓰는 비밀 번호)과 내 chat id(내 대화방 번호)가 있나요? 2일차 2교시에 씁니다. 없으면 기초과정 2일차 준비물을 보고 그 전까지 준비합니다.
    안 될 때
    • Gemini API 키가 없거나 어디 뒀는지 모르겠어요 → 개인 구글 계정으로 aistudio.google.com/apikey에 들어가 Create API Key를 누릅니다. 나온 키를 복사해 메모장에 붙여 넣고 바탕화면에 저장합니다. 2교시 시작 전까지만 있으면 됩니다.
    • n8n 체험 기간이 얼마나 남았는지 모르겠어요 → n8n 화면에 남은 기간 안내가 보이면 확인합니다. 이틀 이하로 남았거나 이미 끝났으면 보조강사에게 알립니다. 새 체험 계정을 만들어도 교시 끝 "완성본 가져오기"로 곧바로 따라올 수 있습니다.
    • 주소가 열리지 않아요(교육망 차단) → ① 주소 철자를 다시 봅니다. ② Chrome 브라우저로 다시 엽니다. ③ 그래도 안 되면 손을 듭니다. 강사가 준비한 다른 접속 방법으로 바꿔 드립니다. AI Studio는 4교시부터 쓰니 지금 안 열려도 1~3교시는 그대로 따라올 수 있습니다.
    비밀값은 나만 봅니다 API 키와 봇 토큰은 비밀번호와 같습니다. 화면을 찍어 공유하거나 메신저로 보내지 않습니다.
  5. 자동화 희망 업무 공유 (10분) 입과 전 사전조사에 적은 "자동화하고 싶은 업무"를 한 사람씩 1분 안에 말합니다. 
    나는 ○○ 업무에서, 지금은 ○○을 손으로 하는데, ○○이 저절로 되면 좋겠다.

    실제 민원인이나 동료의 이름, 실제 사건 내용은 말하지 않습니다. "민원 접수", "시설 점검"처럼 업무 이름으로만 말합니다.

    강사는 비슷한 업무끼리 칠판에 묶습니다(예: 신청 접수형, 현장 보고형, 문서 정리형). 이 묶음이 2일차 4교시 프로젝트의 팀과 주제가 됩니다.

    예: "나는 시설 점검 업무에서, 지금은 현장에서 사진 찍고 돌아와 보고서를 쓰는데, 현장에서 입력하면 팀장에게 바로 가면 좋겠다."

완성본 가져오기(Import) — 강사 시연 준비

이 교시의 시연 파일은 과정 최종 완성본인 2일차 2교시의 파일입니다. 수강생은 가져오지 않아도 됩니다. 궁금한 분은 수업 뒤에 가져와 둘러봐도 됩니다(Publish(워크플로우를 게시해 주소가 항상 동작하게 하는 버튼)는 하지 않습니다).

  1. 파일 내려받기 최종 완성본 내려받기 d2-p2.json
  2. n8n에서 가져오기 Create workflow → 오른쪽 위 … → Import → From file.
  3. 자격 증명 다시 연결하기 가져오면 여러 노드에 경고 표시가 보이는데, 연결 전이라 정상입니다. 노드 열여덟 개가 보이면 성공입니다. 둘러보기만 할 때는 연결하지 않아도 됩니다. 시연처럼 실제로 돌려 보려면 구글 시트·Gmail·캘린더·Gemini·텔레그램을 쓰는 노드마다 Credential 칸에서 내 자격 증명(n8n이 내 계정을 대신 쓰도록 맡겨 둔 열쇠)을 고릅니다. 노드 이름과 자리표시자(여기에_본인_시트_ID, 본인이메일@example.com, 여기에_본인_채팅_ID)는 2일차 2교시 완성본 가져오기에 모두 적혀 있습니다.

둘러보기가 끝났으면 이 워크플로우를 지워 둡니다. 2일차에 같은 이름의 워크플로우가 둘 생기는 것을 막기 위해서입니다.

n8n 핵심 복습

트리거–처리–결과, 표현식, 구글 시트·Gmail·Gemini — 모두 같은 완성본에서 출발합니다

학습목표

  • 트리거–처리–결과 3단 구조로 워크플로우를 읽고, 표현식 {{ }}로 앞 노드의 값을 가져다 쓸 수 있습니다.
  • 구글 시트 기록, Gmail 발송, Gemini 안내문 작성을 한 워크플로우로 실행합니다.
  • 완성본 JSON을 가져오고 자격 증명을 다시 연결할 수 있습니다.

왜 이 단계가 필요한가

오늘 오후에는 앱 화면에서 들어온 민원을 n8n이 받아 처리합니다. 이때 받은 뒤의 처리, 곧 시트에 적고 메일을 보내고 안내문을 쓰는 부분은 기초과정에서 만든 것을 거의 그대로 씁니다. 바뀌는 것은 맨 앞의 시작 신호 하나뿐입니다. 그래서 오전에 이 처리 부분을 다시 손에 익혀 둡니다.

단계하는 일오늘 오전오늘 오후
트리거워크플로우를 시작하게 하는 신호수동 실행 (버튼을 누르면 시작)Webhook(외부 앱이 n8n을 부르는 주소) — 앱에서 누르면 시작
처리일할 재료(민원 내용)를 준비샘플 민원 (미리 적어 둔 가상 민원)앱이 보낸 민원 내용
결과실제로 일을 해 냄시트에 기록 · 접수 메일 보내기 · AI 안내문 작성 — 오전·오후 같음

노드와 노드 사이로 값을 넘겨주는 것이 표현식({{ }} 안에 써서 앞 노드의 값을 가져오는 문장)입니다. 손으로 옮겨 적지 않고 앞 단계가 이미 알고 있는 값을 가져다 쓰기 때문에, 이름이 뒤바뀌는 실수가 생기지 않습니다.

표현식가져오는 값이 워크플로우에서의 결과
{{ $json.이름 }}앞 노드(샘플 민원)의 이름 칸홍길동
{{ $json.종류 }}앞 노드의 종류 칸생활

  • Respond to Webhook 노드로 답을 돌려주고 브라우저 주소창으로 확인하며, Allowed Origins(CORS)를 미리 설정해 둡니다(실제 확인은 6교시).

왜 이 단계가 필요한가

기초과정에서는 n8n이 만들어 준 입력 폼으로 민원을 받았습니다. 오늘 오후에는 우리가 직접 만든 앱 화면에서 민원을 보냅니다. 그러려면 앱이 n8n을 찾아와 문을 두드릴 수 있는 주소가 있어야 합니다. 그 주소가 Webhook(외부 앱이 n8n을 부르는 주소)입니다.

민원실에 비유하면 다음과 같습니다.

Webhook 주소는 두 개가 있습니다.

  • Test URL(만드는 중에 시험할 때 쓰는 주소) — 시험 버튼을 누르고 기다리는 동안 한 번만 동작합니다.
  • Production URL(워크플로우를 게시한 뒤 앱에 넣는 진짜 주소) — 화면 위쪽 Publish(워크플로우를 게시해 주소가 항상 동작하게 하는 버튼)를 누른 뒤부터 언제든 동작합니다.
한 문장 요약 만들 때는 Test URL로 시험하고, 다 만들면 Publish한 뒤 Production URL을 앱에 넣습니다. 이 순서만 지키면 "앱에서 눌렀는데 아무 일도 안 일어나요"의 대부분이 사라집니다.
CORS는 오늘 "설정만" 합니다 CORS 검사는 앱 화면이 n8n을 부를 때 브라우저가 합니다. 오늘은 주소창에 주소를 붙여 넣어 부르기 때문에 이 검사를 받지 않습니다. 그래서 오늘은 허락 명단을 미리 적어 두기만 하고, 실제로 효과를 확인하는 것은 6교시에 앱과 연결할 때 합니다.

따라하기

이름을 넣어 부르면 "안녕하세요, 홍길동님"이라고 답하는 작은 워크플로우를 만듭니다. 오후에 만들 민원 접수의 뼈대입니다.

  1. 새 워크플로우 만들기 n8n 첫 화면에서 Create workflow를 누릅니다.

    가운데에 +가 있는 빈 캔버스가 보이면 성공입니다.

  2. Webhook 노드 추가하기 캔버스 가운데의 +를 누르고 검색창에 Webhook을 입력합니다. 목록에 Respond to Webhook도 보이지만, 이름이 딱 Webhook인 것을 고릅니다.

    Webhook 설정 창이 열리면 성공입니다.

  3. 받는 방식과 주소 끝부분 정하기 HTTP Method가 GET인지 확인합니다. Path 칸의 글자를 모두 지우고 hello를 입력합니다. GET은 브라우저 주소창에 주소를 넣어 부르는 방식입니다. 오후에 앱이 민원을 보낼 때는 POST라는 다른 방식을 씁니다. Path는 주소의 맨 끝부분이며, 알아보기 쉬운 영어 단어로 정합니다.

    설정 창 위쪽 주소가 …/hello로 끝나면 성공입니다.

  4. 답장 방식 바꾸기 Respond를 Using 'Respond to Webhook' Node로 바꿉니다.

    Respond 칸에 Using 'Respond to Webhook' Node가 보이면 성공입니다.

    자주 하는 실수

    증상 우리가 쓴 인사말 대신 {"message":"Workflow was started"}만 보여요
    원인 Respond가 기본값 Immediately로 남아 있어요
    해결 Using 'Respond to Webhook' Node로 바꾸세요

  5. CORS 허락 명단 미리 적기 (체크리스트 1번) 설정 창 아래 Add option을 누르고 Allowed Origins (CORS)를 고릅니다. 칸에 *가 들어 있는지 봅니다. 비어 있으면 *를 입력합니다. *는 "어느 주소의 앱이든 불러도 좋다"는 뜻입니다. 실습에서는 이 값을 씁니다. 실제 부서에 적용할 때의 안전 설정은 2일차 3교시 점검표에서 다룹니다.

    Allowed Origins (CORS) 칸에 *가 보이면 성공입니다. 설정 창 바깥의 빈 곳을 누르거나 창을 닫아 캔버스로 돌아갑니다. Webhook 노드 하나가 보이면 됩니다.

  6. Respond to Webhook 노드 붙이기 Webhook 노드 오른쪽의 +를 누르고 Respond to Webhook을 검색해 고릅니다.

    두 노드가 선으로 이어지고 Respond to Webhook 설정 창이 열리면 성공입니다.

  7. 답장 글 넣기 Respond With를 JSON으로 바꿉니다. Response Body 글자 근처에 마우스를 올리면 Fixed와 Expression이 나타납니다. Expression을 누릅니다. 칸 안을 누르고 Ctrl+A로 이미 들어 있는 글자를 모두 고른 뒤 Delete로 지웁니다. 칸이 비었으면 아래 글을 복사해 붙여 넣습니다. 
    {
  "메시지": "안녕하세요, {{ $json.query.이름 }}님. 잘 받았습니다."
}

    {{ $json.query.이름 }}는 기초과정에서 배운 표현식(앞 노드의 값을 가져다 쓰는 문장)입니다. 다음 단계에서 주소 끝에 붙여 보낼 이름 값을 꺼내 옵니다.

    칸 아래 미리보기에서 이름 자리가 비어 보여도 괜찮습니다. 아직 이름을 보내지 않았기 때문이며, 다음 단계에서 채워집니다.

  8. Test URL로 시험하기 시간 제한이 있으므로 아래 순서대로 준비한 다음 시험합니다.
    1. Webhook 노드를 열고 위쪽에서 Test URL을 고른 뒤 아래 주소를 한 번 누릅니다. URL copied 알림이 뜨면 복사된 것입니다. 설정 창을 닫습니다.
    2. 브라우저에서 새 탭을 열고, 주소창에 복사한 주소를 붙여 넣은 뒤 끝에 ?이름=홍길동을 이어서 씁니다. 아직 Enter는 누르지 않습니다.
    3. n8n 탭으로 돌아와 캔버스 아래 Execute workflow를 누릅니다. 설정 창 안의 Listen for test event는 누르지 않습니다(그 버튼은 Webhook 노드만 실행해서 답장이 오지 않습니다).
    4. 2분 안에 새 탭으로 가서 Enter를 누릅니다.
    https://(내 n8n 주소)/webhook-test/hello?이름=홍길동
    위 주소는 모양을 보여 주는 예입니다. 직접 치지 말고 n8n에서 복사한 주소를 쓰세요. 주소 끝의 ?이름=홍길동은 "이름은 홍길동"이라는 값을 n8n에 함께 보내는 부분입니다. ?와 =는 영어 자판으로 입력하고 띄어 쓰지 않습니다. 이름 자리에는 본인 실명 대신 홍길동·김민원 같은 가상 이름만 넣습니다. 보낸 값은 실행 기록에 남습니다.

    브라우저 화면에 "안녕하세요, 홍길동님. 잘 받았습니다."라는 글이 보이면 성공입니다(앞뒤 기호 모양은 조금 달라도 됩니다). n8n 캔버스의 두 노드에도 초록색 표시가 생깁니다.

    증상 The requested webhook "…" is not registered.라는 글이 보여요
    원인 Execute workflow를 누르지 않았거나, 누른 뒤 2분이 지났거나, 이미 한 번 불렀어요(Test URL은 한 번만 동작)
    해결 캔버스 아래 Execute workflow를 다시 누르고 곧바로 새 탭에서 Enter를 누르세요

    원인 설정 창 안의 Listen for test event를 눌렀어요. 이 버튼은 Webhook 노드만 실행해서 Respond to Webhook이 답장을 만들지 못해요

    원인 앱에 Test URL을 넣었어요. 주소 안에 webhook-test가 있으면 Test URL입니다
    해결 앱에는 항상 /webhook/으로 된 Production URL을 넣으세요

  • 만들 때는 Test URL로 시험하고, Publish한 뒤에는 Production URL을 씁니다. 설정을 고치면 다시 Publish합니다.
  • CORS 허락 명단(Allowed Origins (CORS))은 오늘 미리 적어 두었습니다.

  3. 자격 증명 확인하기 이 연습 워크플로우에는 자격 증명(n8n이 내 구글·텔레그램 계정을 대신 쓰도록 맡겨 둔 열쇠)이 필요한 노드가 없어서 다시 연결할 것이 없습니다. 다른 교시에서는 이 단계에서 경고 표시가 뜬 노드를 열어 내 자격 증명을 고릅니다.
  4. Publish하고 시험하기 화면 위쪽 Publish를 누르고, 뜨는 창에서 다시 Publish를 누릅니다. Webhook 노드를 열어 위쪽에서 Production URL을 골라 주소를 복사합니다. 새 탭 주소창에 붙여 넣고 끝에 ?이름=홍길동을 붙여 Enter를 누릅니다. 인사말이 보이면 복구 완료입니다.

AI 앱 빌더 첫 체험

Google AI Studio의 Build 모드에서 문장만으로 민원 접수 화면을 만듭니다

학습목표

  • Build 모드 화면의 입력창, 미리보기, Code 탭을 구분합니다.
  • 문장(프롬프트)으로 앱이 만들어지는 원리를 설명할 수 있습니다.

왜 이 단계가 필요한가

오전에 만든 n8n 워크플로우는 일을 하는 사람이고, 3교시에 만든 Webhook(외부 앱이 n8n을 부르는 주소)은 그 사람을 부르는 초인종입니다. 그런데 민원인이나 동료가 직접 들어와 내용을 적을 창구 화면이 아직 없습니다. 이번 시간에는 그 화면을 만듭니다.

화면을 만들려면 원래 프로그래밍이 필요하지만, 오늘은 Google AI Studio(문장으로 앱 화면을 만들어 주는 구글의 무료 도구)가 대신 만듭니다. AI Studio 안에서 앱을 만드는 화면을 Build 모드라고 부릅니다. 우리는 어떤 화면이 필요한지 주문서를 씁니다. 이 주문서가 프롬프트(AI에게 시키는 일을 적은 문장)입니다.

학습목표

  • 원하는 화면 변경을 구체적인 문장으로 요청할 수 있습니다.

왜 이 단계가 필요한가

4교시에 만든 화면은 첫 초안입니다. 실제로 쓰려면 기관 이름을 넣고, 개인정보 동의를 받는 등 손볼 곳이 생깁니다. 또 AI가 만든 코드는 가끔 틀립니다. 오류가 나는 것은 내 잘못이 아니며, 알려 주면 AI가 고칩니다. 이번 시간에는 고쳐 달라고 말하는 법과 오류가 났을 때 알려 주는 법을 익힙니다.

고쳐 달라는 말도 AI에게 주는 프롬프트(AI에게 시키는 일을 적은 문장)입니다. 좋은 수정 요청에는 세 가지가 있습니다.

  • 한 번에 한 가지 — 여러 가지를 한꺼번에 바꾸면 무엇이 잘못됐는지 찾기 어렵습니다.
  • 어디를 · 어떻게 — "제목을", "접수하기 버튼을"처럼 위치를, "진한 파란색으로"처럼 결과를 적습니다.
  • 바꾸면 안 되는 것 — "입력 칸은 그대로 둬"를 덧붙입니다. 칸 이름과 WEBHOOK_URL은 6교시 연결 약속입니다.

  • 앱에 n8n Production URL을 넣어 접수 데이터를 보낼 수 있습니다(Test URL로 먼저 시험한 뒤).
  • 받은 데이터가 구글 시트에 한 줄로 기록되는 것을 확인합니다.

왜 이 단계가 필요한가

지금까지 세 조각을 따로 만들었습니다. 2교시의 일하는 워크플로우, 3교시의 초인종인 Webhook(외부 앱이 n8n을 부르는 주소), 4·5교시의 창구 화면인 앱입니다. 이번 시간에 이 셋을 이어 붙여, 앱에서 누른 접수가 시트까지 가게 합니다.

순서누가무엇을
1앱(AI Studio)접수하기를 누르면 다섯 값을 봉투에 담아 n8n 주소로 보냅니다(이렇게 봉투에 담아 보내는 방식을 POST라고 부릅니다)
2민원 받기 (Webhook)봉투를 받습니다. 값은 봉투 안쪽 body에 들어 있습니다
3민원 정리 (Edit Fields)봉투에서 값을 꺼내 2교시와 같은 모양(이름, 연락처 …)으로 정리합니다
4시트에 기록2교시에 쓰던 노드를 그대로 가져와 한 줄을 적습니다

이번에는 앱 화면(AI Studio 주소)이 n8n(다른 주소)을 부르기 때문에, 브라우저가 "이 앱이 불러도 되나?"를 검사합니다. 이것이 CORS(다른 주소의 앱이 n8n을 불러도 되는지 정하는 허락 규칙)입니다. 3교시에 미리 적어 둔 허락 명단(Allowed Origins (CORS))이 오늘 처음으로 쓰입니다.

오늘의 순서: 시험 먼저, 그다음 사용 주소는 두 개입니다. 먼저 Test URL(만드는 중에 시험할 때 쓰는 주소)을 앱에 넣어 한 번 보내 보고, 잘 되면 Publish(워크플로우를 게시해 주소가 항상 동작하게 하는 버튼)를 누른 뒤 Production URL(워크플로우를 게시한 뒤 앱에 넣는 진짜 주소)로 바꿉니다.

    1. 아래 문장을 복사해 AI Studio 대화 입력창에 붙여 넣습니다. 아직 보내지 않습니다.
    2. 입력창에서 {Test URL} 글자(중괄호 포함)를 끌어서 고르고 지웁니다. 따옴표 " "는 남깁니다.
    3. n8n 탭의 민원 받기 설정 창 위쪽에서 Test URL이 골라져 있는지 보고, 그 주소를 복사합니다.
    4. AI Studio 탭으로 돌아와 따옴표 사이를 한 번 누르고 Ctrl+V를 누른 뒤 보냅니다.
    코드 맨 위 WEBHOOK_URL 값을 "{Test URL}"로 바꿔 줘. 다른 부분은 바꾸지 마.

    AI의 답이 끝나고 미리보기가 다시 나타나면, Code 탭에서 Ctrl+F로 WEBHOOK_URL을 찾습니다(4교시 5단계와 같음). 따옴표 안에 webhook-test가 들어간 주소가 보이면 성공입니다. 확인했으면 미리보기 탭으로 돌아옵니다.

  3. 첫 시험 — 앱에서 보내 보기 Listen for test event를 누르면 n8n은 2분 동안만 기다립니다. 그래서 앱 입력을 먼저 끝내 둡니다.
    1. AI Studio 미리보기에 가상 값(홍길동 / 010-1234-5678 / minwon@example.com / 생활 / 보도블록이 깨져 있습니다.)을 넣고 동의에 체크합니다. 아직 누르지 않습니다.
    2. n8n 탭에서 민원 받기를 열고 Listen for test event를 누릅니다.
    3. 곧바로 AI Studio 탭으로 와서 접수하기를 누릅니다. 2분이 지났으면 2번부터 다시 합니다.

    민원 받기 설정 창 오른쪽 OUTPUT에서 body를 눌러 펼쳤을 때 다섯 값이 보이면 성공입니다. 앱이 n8n을 부르는 데 성공했다는 뜻이므로 CORS도 통과한 것입니다.

    성공 여부는 n8n 쪽으로 판단합니다. n8n에 다섯 값이 보였다면 앱 화면에 무엇이 뜨든(빈 접수번호, 실패 문구 모두) 이 단계는 성공입니다. 앱 화면의 답은 7교시에 고칩니다.

정답 확인

정답: ② POST로 보낸 값은 body 안에 들어옵니다. 그래서 민원 정리에서 꺼내 줍니다. query는 3교시처럼 주소 뒤 ?이름=홍길동으로 보낸 값이 들어가는 곳입니다.

먼저: 따라 만들던 워크플로우를 Publish했다면 그 워크플로우의 Publish 오른쪽 작은 화살표를 눌러 목록 맨 아래 Unpublish를 누르고, 뜨는 창에서 다시 Unpublish를 누르세요. 같은 주소 끝부분(minwon)과 같은 방식(POST)을 쓰는 Webhook은 하나만 동작할 수 있습니다.
  1. 파일 내려받기 워크플로우 내려받기 d1-p6.json
  2. n8n에서 가져오기 Create workflow → 오른쪽 위 … → Import → From file을 누르고 파일을 고릅니다.
  3. 자격 증명 다시 연결하기 시트에 기록을 열어 Credential 칸에서 2교시에 만든 내 구글 시트 자격 증명을 고릅니다. 자격 증명이나 시트 민원대장 연습이 없으면 1일차 2교시 따라하기대로 먼저 만듭니다.
  4. 자리표시자 바꾸기 시트에 기록의 Document 칸 왼쪽 작은 목록(지금은 By ID)을 눌러 From list로 바꾼 뒤, 목록에서 민원대장 연습을 고릅니다. 여기에_본인_시트_ID 글자가 없어지면 됩니다. Sheet는 내 구글 시트 아래쪽 탭 이름과 같아야 합니다. 파일에는 시트1로 들어 있습니다. 내 탭 이름이 다르면(예: Sheet1) 목록에서 내 탭을 고릅니다.
  5. Publish하고 앱 주소 바꾸기 Publish → 확인 창의 Publish를 누르고, 따라하기 9단계 순서대로 민원 받기의 Production URL을 앱의 WEBHOOK_URL에 넣습니다. 앱에서 가상 민원을 접수해 시트에 줄이 생기면 복구 완료입니다.

앱 쪽이 망가졌다면 4교시 2단계의 주문 문장으로 앱을 새로 만들고 5교시 요청 1·3을 보낸 뒤, 위 5단계의 Production URL을 넣습니다.

접수번호를 만들어 시트에 적고, 앱 화면에 돌려준 뒤 1일차를 정리합니다

학습목표

  • YYYY-MMDD-NNN 형식의 접수번호를 만들어 시트에 기록합니다.
  • Respond to Webhook으로 접수번호를 앱에 돌려주고 화면에 표시합니다.
  • 1일차에 만든 전체 흐름을 그림으로 정리합니다.

왜 이 단계가 필요한가

지금 앱은 접수를 보내기만 하고, 민원인은 "정말 접수됐나?" 알 수 없습니다. 민원실 창구라면 접수증을 건네는 순간입니다. 이번 시간에는 n8n이 접수번호를 만들어 시트에 함께 적고, 그 번호를 앱에 돌려주어 화면에 보이게 합니다. 답장을 보내는 노드가 3교시에 써 본 Respond to Webhook(부른 쪽에 "잘 받았어요"라고 답장을 보내는 노드)입니다.

  2. 시트에 머리글 두 칸 더하기 구글 시트 민원대장 연습의 G1 칸에 접수번호, H1 칸에 처리상태를 입력합니다(띄어 쓰지 않습니다).

    스위치가 켜진 모양이면 성공입니다. 창 바깥을 눌러 캔버스로 돌아갑니다.

  5. 접수번호 만들기 끼워 넣기 오늘 접수 조회와 시트에 기록 사이 선의 +를 누르고 Edit Fields (Set)를 고릅니다. 이름을 접수번호 만들기로 고칩니다.

    2. JSON 칸 글자 근처에 마우스를 올리면 나타나는 Expression을 누릅니다. 칸 안의 글자를 Ctrl+A, Delete로 지웁니다.

    이 줄은 "민원 정리의 다섯 값에, 오늘 번호 개수 + 1로 만든 접수번호와 처리상태를 붙여라"라는 뜻의 표현식(앞 노드의 값을 가져오는 문장)입니다. 뜻을 몰라도 그대로 붙여 넣으면 됩니다. Execute Once는 시트에서 읽은 줄이 여러 개여도 번호를 한 번만 만들게 합니다.

    JSON 칸이 {{ Object.assign(로 시작해 }) }}로 끝나고 Execute Once가 켜져 있으면 성공입니다.

가지(위에서부터)하는 일결과가 보이는 곳
① AI 안내문 작성 → 앱에 답하기Gemini가 안내문을 쓰고, 접수번호와 함께 앱에 돌려줌앱 화면
② 담당자 메일담당자(실습에서는 나)에게 접수 알림내 Gmail
③ 처리 마감 일정3일 뒤에 처리 마감 일정 등록내 구글 캘린더

세 가지 모두 시트에 기록에서 부챗살처럼 갈라집니다. 한 줄로 이어 붙이면 노드를 지날 때마다 값이 그 노드의 결과로 바뀌어, 뒤 노드가 민원 내용을 잃어버리기 때문입니다(1일차 2교시 복습).

왜 AI 가지를 맨 위에 두나 n8n은 갈라진 가지를 캔버스 위쪽 가지부터 차례로 실행합니다. 앱에 답을 보내는 Respond to Webhook(부른 쪽에 답장을 보내는 노드)이 AI 가지 끝에 있으므로, AI 가지를 맨 위에 두면 앱이 가장 먼저 답을 받습니다. 메일이나 캘린더에 문제가 생겨도 앱 접수는 막히지 않습니다.
AI 안내문은 초안입니다 AI는 처리 기한·담당 부서·법령을 그럴듯하게 지어낼 수 있습니다. 실습에서는 화면에 보여 주기만 하고, 실제 운영에서는 담당자가 확인한 뒤 보냅니다.

    AI의 답이 끝나고 미리보기가 다시 나타나면 성공입니다. 앱 주소(WEBHOOK_URL)는 바꾸지 않습니다.

  10. 접수하고 세 곳 확인하기
    개인정보 주의 아래 가상 값만 넣습니다. 이번에는 입력한 이름과 상세 설명이 Gemini(구글 AI)로 보내지고, 연락처는 메일로 전달됩니다. 실제 민원인의 이름·연락처·민원 내용은 실습에 넣지 않습니다.
    앱에서 새 민원 접수로 돌아가 가상 민원(이접수 / 010-0000-0005 / minwon@example.com / 대형 / 아파트 앞에 버려진 소파 수거를 요청합니다.)을 넣고 동의에 체크한 뒤 접수하기를 누릅니다. 안내문을 만드느라 10초쯤 걸릴 수 있습니다. 기다리는 동안 앱이 멈춘 것처럼 보이면, 시간이 남을 때 프롬프트 파일의 "기다리는 동안 안내" 문장을 AI Studio에 보내도 됩니다(선택).
    • 앱 화면: 접수번호와 AI 안내문이 보이나요?
    • 내 Gmail(스팸함 포함): 제목이 [대형] 민원 접수 …인 메일이 왔나요?
    • 구글 캘린더: 3일 뒤에 민원 처리 마감 - … 일정이 생겼나요?

    세 곳이 모두 확인되면 성공입니다.

    자주 하는 실수

    증상 앱에 오류가 떴는데 시트에는 줄이 생겼어요
    원인 앱이 답을 기다리다 지쳤을 수 있어요(n8n Cloud는 100초 넘게 답이 없으면 끊습니다). 접수 자체는 처리되었을 수 있어요
    해결 먼저 시트·메일·캘린더를 확인하세요. n8n Executions에서 AI 안내문 작성이 오래 걸렸거나 빨간지 봅니다

    원인 앱이 안내문 칸을 만들지 않았거나, 답장 한 줄(4단계)이 예전 것 그대로예요

    원인 Gemini 무료 사용량을 넘었어요. 이 가지가 맨 위라, 여기서 멈추면 앱에도 실패가 뜨고 메일·캘린더도 오지 않아요

연동 ② 완성

종류별 담당자 나누기, 텔레그램 알림, 그리고 민원인이 스스로 보는 처리 상태 조회 화면

학습목표

  • If 노드로 민원 유형별 담당자를 나눕니다.
  • 텔레그램으로 접수 알림을 보냅니다.
  • 접수번호로 처리 상태를 조회하는 GET Webhook과 조회 화면을 만듭니다.

왜 이 단계가 필요한가

지금은 모든 민원 메일이 한 담당자에게 갑니다. 실제로는 생활 민원과 쓰레기 수거 민원의 담당자가 다릅니다. 또 급한 민원은 메일보다 메신저가 빨리 눈에 띕니다. 그리고 민원인은 "내 민원 어떻게 됐나?"를 전화로 묻습니다. 이번 시간에는 이 세 가지를 해결해 민원 접수 서비스를 완성합니다.

더하는 것노드하는 일
담당자 나누기생활인가? (If)종류가 "생활"이면 담당자 메일(정담당), 아니면 일반 담당자 메일(강처리)
메신저 알림텔레그램 알림부서방(실습에서는 내 텔레그램)에 새 민원 알림
처리 상태 조회상태 조회 → 접수번호로 찾기 → 찾았나? → 답하기 둘앱에서 접수번호를 넣으면 처리상태·담당자·처리마감을 돌려줌

조회 흐름은 같은 워크플로우 안에 두 번째 입구를 하나 더 만드는 것입니다. 접수는 minwon 주소로 편지를 보내고(POST), 조회는 minwon-status 주소 뒤에 ?no=접수번호를 붙여 묻습니다(GET, 1일차 3교시에 주소창으로 불렀던 방식). 이 입구도 Webhook(외부 앱이 n8n을 부르는 주소)이고, 답은 Respond to Webhook(부른 쪽에 답장을 보내는 노드)으로 돌려줍니다. 앱이 부르므로 CORS(다른 주소의 앱이 불러도 되는지 정하는 허락 규칙) 명단이 필요합니다.

한 문장 요약 If로 길을 나누고, 텔레그램으로 알리고, 두 번째 입구(GET)로 조회에 답하면 — 접수부터 알림, 조회까지 이어지는 서비스가 완성됩니다.
강사 메모 이 교시의 결과(workflows/d2-p2.json)가 과정 전체의 최종 완성본이며, 1일차 1교시 시연에 이 파일을 씁니다.

따라하기

준비 1교시 워크플로우(노드 열 개)를 엽니다. 없으면 2일차 1교시 완성본 가져오기로 먼저 맞춥니다.

시간 기준: 이 교시는 A → C 순서로 합니다. B(텔레그램 알림)는 선택이며 C를 모두 마친 뒤 시간이 남으면 합니다. 10시 25분까지 A를 못 마쳤으면 A는 건너뛰고 C부터 합니다. 10시 35분까지 5단계를 못 마쳤으면 이 교시 끝 "완성본 가져오기"로 맞추고(10분쯤 걸립니다), 조회 화면(8단계)은 쉬는 시간에 마칩니다.

A. 종류별 담당자 나누기

  1. 생활인가? 끼워 넣기 시트에 기록과 담당자 메일 사이 선에 마우스를 올리면 나오는 +를 누르고 If를 고릅니다. 이름을 생활인가?로 고칩니다. Conditions에서 왼쪽 칸에 마우스를 올려 Expression을 누르고 {{ $json['종류'] }}, 가운데는 is equal to, 오른쪽 칸에 생활을 적습니다. 이 {{ }}는 앞 노드의 값을 가져오는 표현식(앞 노드의 값을 가져오는 문장)입니다. 기초과정 07강의 "생활인가?"와 같은 조건입니다.

    생활인가?의 true 갈래(위)가 담당자 메일로 이어져 있으면 성공입니다. 이어져 있지 않으면 true 점에서 담당자 메일로 끌어 잇습니다.

  2. 일반 담당자 메일 만들기 담당자 메일을 한 번 눌러 고르고 Ctrl+C, 빈 곳을 누르고 Ctrl+V로 복사본을 만듭니다. 이름을 일반 담당자 메일로 고칩니다. 생활인가?의 false 점(아래)에서 일반 담당자 메일로 끌어 잇습니다.

    일반 담당자 메일의 Subject를 지우고(Expression 상태 유지) 아래 한 줄을 붙여 넣어 두 메일을 구분합니다.

    [{{ $json.종류 }}·강처리] 민원 접수 {{ $json.접수번호 }}

    생활인가?에서 true → 담당자 메일, false → 일반 담당자 메일로 갈라지면 성공입니다. 실습에서는 두 메일 모두 내 주소로 옵니다.

C. 처리 상태 조회 — 두 번째 입구

  1. 상태 조회 만들기 캔버스 아래쪽 빈 곳을 한 번 누르고, 오른쪽 위 +(노드 추가)를 눌러 Webhook을 추가합니다. 이름을 상태 조회로 고칩니다.
    • HTTP Method: GET
    • Path: 글자를 모두 지우고 minwon-status
    • Respond: Using 'Respond to Webhook' Node
    • Add option → Allowed Origins (CORS): * — 체크리스트 1번, 이 입구도 앱이 부릅니다

    위쪽 주소가 …/minwon-status로 끝나면 성공입니다.

  2. 접수번호로 찾기 잇기 상태 조회 오른쪽 + → Google Sheets → Get Row(s). 이름을 접수번호로 찾기로 고칩니다.
    • Credential: 구글 시트 자격 증명(n8n이 내 계정을 대신 쓰도록 맡겨 둔 열쇠)
    • Document: From list에서 민원대장 연습, Sheet: 시트1(내 탭 이름)
    • Filters → Add Filter: Column = 접수번호, Value(Expression) = {{ $json.query.no }}
    • Add option → Return only First Matching Row 켜기
    • Settings 탭 → Always Output Data 켜기
    query.no는 주소 뒤 ?no=에 붙여 보낸 접수번호입니다.

    Filters에 한 줄, Always Output Data가 켜져 있으면 성공입니다.

  3. 찾았나?와 답하기 둘
    1. 접수번호로 찾기 오른쪽 + → If, 이름 찾았나?. 조건: 왼쪽 {{ $json['접수번호'] }}(Expression), 가운데 is not empty.
    2. true 점 오른쪽 +를 누르고 Respond to Webhook을 고릅니다. 이름을 조회 결과 답하기로 고치고 Respond With를 JSON으로 바꿉니다. Response Body에 마우스를 올려 Expression을 누르고, Ctrl+A, Delete로 원래 글을 지운 뒤 아래 [조회 결과 답하기] 줄을 붙여 넣습니다.
    3. false 점에서 같은 방법으로 없음 답하기를 만들고 [없음 답하기] 줄을 붙여 넣습니다.

    [조회 결과 답하기]

    {{ { "찾음": true, "접수번호": $json['접수번호'], "처리상태": $json['처리상태'], "담당자": $json['종류'] === '생활' ? '정담당' : '강처리', "처리마감": DateTime.fromISO($json['등록일']).plus({ days: 3 }).toFormat('yyyy-MM-dd') } }}

    [없음 답하기]

    {{ { "찾음": false, "오류": "접수번호를 찾을 수 없습니다" } }}
    긴 줄은 세 번 빠르게 눌러 한 줄 전체를 고른 뒤 복사합니다(인쇄본은 줄이 잘리므로 웹 교안에서 복사). 처리마감은 등록일에 3일을 더한 날이며, 법정 처리 기한이 아닙니다.

    찾았나?에서 두 답하기로 갈라지면 성공입니다.

허락 명단(CORS)은 자물쇠가 아니라 "안내판"입니다 Allowed Origins (CORS)는 다른 웹사이트 화면이 내 n8n의 답을 읽지 못하게 하는 브라우저용 안내판입니다. 주소를 아는 사람이 다른 방법으로 요청을 보내는 것까지 막는 자물쇠는 아닙니다. 실제 자물쇠는 Webhook 노드의 Authentication(비밀번호처럼 약속한 글자를 함께 보내야만 받아 주는 설정)인데, 그 비밀 글자를 앱 화면 코드에 넣으면 공유받은 사람이 볼 수 있어 앱의 서버 쪽(보이지 않는 뒤편)에서 처리해야 합니다. 실습에서는 하지 않아도 괜찮습니다. 가상 데이터만 쓰기 때문입니다. 실제 운영 전에 기관 보안 담당과 정합니다.
기관 설치형 n8n — 한 줄 결론: 운영은 기관이 승인한 환경에서 교육에 쓴 n8n Cloud는 n8n 회사의 서버를 빌려 쓰는 것이고, n8n은 기관 서버에 직접 설치해 쓸 수도 있습니다(무료판). 설치와 보안 관리는 전산 담당 부서가 맡습니다. 무료판은 조직 내부 업무용으로 쓸 수 있지만 여러 사람이 함께 관리하는 기능 등은 빠져 있고, 구글 연결 설정을 따로 해야 하며, 앱이 부르려면 인터넷 주소가 열려 있어야 합니다. 도입 여부와 사용 조건은 기관 보안·전산·법무 담당과 협의합니다. 참고: n8n 설치 안내(영문)
AI Studio Publish는 소개만 합니다 Publish는 앱을 Google Cloud Run에 올려 누구나 여는 공개 주소를 만드는 기능입니다. 조건이 맞는 개인 계정은 결제 등록 없이 앱 2개까지 올릴 수 있지만, 기관 계정이거나 예전에 Google Cloud 결제 계정을 만든 적이 있으면 결제 계정이 필요하고 사용량에 따라 요금이 나올 수 있습니다. 이 과정에서는 실습하지 않습니다.

왜 순서대로 점검하나

앱과 n8n 사이에는 확인할 곳이 여러 군데 있습니다. "안 돼요"에서 멈추지 않으려면 늘 같은 순서로 하나씩 확인합니다. 이 순서는 이틀 동안 겪은 실수를 모은 것입니다. 앞에서부터 확인하면 대부분 세 번째 안에 원인이 나옵니다.

용어 다시 보기
  • Webhook: 외부 앱이 n8n을 부르는 주소 / Respond to Webhook: 부른 쪽에 답장을 보내는 노드
  • Test URL: 만드는 중에 시험할 때 쓰는 주소 / Production URL: 게시한 뒤 앱에 넣는 진짜 주소
  • Publish: 워크플로우를 게시해 주소가 항상 동작하게 하는 버튼
  • CORS: 다른 주소의 앱이 n8n을 불러도 되는지 정하는 허락 규칙
  • 자격 증명: n8n이 내 계정을 대신 쓰도록 맡겨 둔 열쇠 / 표현식: {{ }} 안에 써서 앞 노드의 값을 가져오는 문장
  • API 키: Gemini 같은 서비스를 쓸 수 있게 해 주는 비밀 번호표

먼저 한 곳만 봅니다. n8n 워크플로우 화면 위쪽의 Executions 탭을 누르고, 왼쪽 목록 맨 위(방금 시각) 줄을 한 번 누릅니다. 그리고 아래 셋 중 어느 경우인지 고릅니다.

  • ① 목록에 방금 시각 줄이 없다 → 앱이 n8n에 닿지 못했습니다. 아래 표 가의 1~3번을 봅니다.
  • ② 빨간 노드가 있다 → 그 노드 이름을 보고 아래 표 나에서 같은 이름 줄을 봅니다.
  • ③ 모두 초록인데 결과가 안 보인다 → 앱 화면이 실패면 표 가의 4번, 메일·알림만 안 오면 보수필요인가? 같은 If 노드를 눌러 false 쪽으로 갔는지 봅니다.

왜 발표하고 로드맵을 쓰나

교육장에서 동작한 서비스가 부서에서 쓰이려면 두 가지가 더 필요합니다. 하나는 동료가 알아듣는 설명, 다른 하나는 실제 적용까지의 순서입니다. 발표는 설명을 연습하는 자리이고, 로드맵은 교육이 끝난 뒤 무엇부터 할지 정하는 한 장입니다.

한 문장 요약 "무엇이 불편했고, 이렇게 바꿨고, 이만큼 줄었다"를 5분에 보여 주고, 실제 데이터는 점검과 협의를 거친 뒤에 넣습니다.

PDF 공문 요약 앱

앱에서 PDF 공문을 올리면 n8n이 글자를 뽑아 Gemini로 요약하고, 앱·메일·텔레그램으로 돌려줍니다

학습목표

  • 앱에서 PDF 공문을 올리면 n8n이 받아 Gemini로 요약합니다.
  • 요약을 메일과 텔레그램으로 보냅니다.

왜 이 실습인가

용어 다시 보기 Webhook(외부 앱이 n8n을 부르는 주소), Test URL(시험할 때만 쓰는 주소), Production URL(게시한 뒤 앱에 넣는 진짜 주소), Publish(워크플로우를 게시하는 버튼), CORS(다른 주소의 앱이 불러도 되는지 정하는 허락 규칙), Respond to Webhook(부른 쪽에 답장을 보내는 노드), 표현식({{ }}로 앞 노드의 값을 가져오는 문장), 자격 증명(n8n이 내 계정을 대신 쓰도록 맡겨 둔 열쇠), 프롬프트(AI에게 시키는 일을 적은 문장), API 키(서비스를 쓸 수 있게 해 주는 비밀 번호표)

기초과정 P1에서는 n8n 입력 폼으로 공문을 올렸습니다. 이번에는 내가 만든 앱에서 올립니다. 민원 접수와 다른 점은 글자 대신 파일을 보낸다는 것 하나입니다.

새로 나오는 말 두 가지: Binary(n8n이 받은 파일을 담아 두는 칸. 노드 결과 화면의 Binary 탭에서 봅니다), Extract from File(파일 안의 글자를 꺼내는 노드).

순서노드하는 일
1공문 받기 (Webhook)앱이 보낸 PDF를 file이라는 이름표로 받음
2글자 뽑기 (Extract from File)PDF 안의 글자를 꺼냄(text)
3AI 공문 요약 (+ Gemini)목적·주요 내용·지원 사항·대상·일정 다섯 줄 요약
4앱에 답하기 / 요약 메일 / 텔레그램 알림앱에 요약 표시, 메일·텔레그램으로 전달

비유: 서류를 봉투에 넣어 보내는 것과 같습니다. 앱은 PDF를 file이라고 적힌 봉투에 넣어 보내고, n8n은 file 봉투를 찾아 엽니다. 봉투 이름이 다르면 n8n은 "받은 서류가 없다"고 합니다. 여기서 file은 PDF의 파일 이름이 아니라 봉투(칸) 이름표입니다. 내 파일 이름이 무엇이든 이름표는 늘 file입니다.

실습에는 가상 공문만 실제 공문·내부 문서는 올리지 않습니다. PDF 내용이 n8n 실행 기록과 AI 서비스(Gemini)에 남습니다. 아래 1단계의 가상 공문을 씁니다.
한 문장 요약 파일은 앱이 file이라는 이름표로 보내고, n8n은 그 이름표로 받아 글자를 뽑은 뒤 기존처럼 AI·메일·텔레그램으로 처리합니다. 사진으로 찍은(스캔) PDF는 글자가 없어 읽지 못합니다.

따라하기

걸리는 시간과 빠른 길 직접 만들면 약 50분, 완성본을 가져오면 약 25분 걸립니다. 2일차 6교시 안에서 한다면 완성본 가져오기를 권합니다.

  1. 가상 공문 PDF 만들기 가상 공문 링크를 마우스 오른쪽 버튼으로 눌러 새 탭에서 링크 열기로 엽니다. Ctrl+P를 누르고 대상(프린터)을 PDF로 저장으로 바꿉니다. 설정 더보기에서 머리글 및 바닥글 체크를 끕니다(켜 두면 내 PC 폴더 경로가 PDF에 찍힙니다). 저장을 누르고 바탕 화면에 가상공문.pdf로 저장합니다. 인쇄 창의 글자는 브라우저마다 조금 다릅니다. 크롬·엣지 모두 "PDF로 저장"이 대상 목록에 있습니다.

    저장한 PDF를 열어 글자를 마우스로 끌어 고를 수 있으면 성공입니다(글자가 들어 있는 PDF라는 뜻입니다).

  2. 새 워크플로우 만들고 이름 붙이기 n8n 첫 화면에서 Create workflow를 누릅니다. 맨 위 제목(My workflow)을 눌러 PDF 공문 요약으로 바꿉니다.

    맨 위 제목이 PDF 공문 요약이면 성공입니다. 이후 단계마다 Ctrl+S로 저장합니다.

  3. 공문 받기 만들기 가운데 +를 누르고 검색 칸에 Webhook을 쳐서 고릅니다. 설정 창 맨 위 이름을 눌러 공문 받기로 고친 뒤 칸을 채웁니다.
    • HTTP Method: POST, Path: gongmun-summary
    • Respond: Using 'Respond to Webhook' Node
    • 설정 창 맨 아래 Add option → Allowed Origins (CORS): *
    Add option 목록의 Field Name for Binary Data는 넣지 않습니다. 넣으면 봉투 이름표가 file이 아니라 다른 이름으로 바뀝니다.

    설정 창 위쪽 주소가 …/gongmun-summary로 끝나면 성공입니다.

  4. 글자 뽑기 잇기 설정 창을 닫고 공문 받기 오른쪽 +를 눌러 Extract from File을 찾아 고르고, 이름을 글자 뽑기로 고칩니다. Operation: Extract From PDF, Input Binary Field: file(기본값 data를 지우고 적습니다).

    Input Binary Field에 data가 아니라 file이 적혀 있으면 됩니다. 실제로 글자가 뽑히는지는 12단계에서 확인합니다.

    {{ }}가 들어 있는 글은 모두 칸에 마우스를 올려 Expression을 누른 뒤 붙여 넣습니다. 그냥 붙여 넣으면 메일에 {{ … }} 글자가 그대로 찍힙니다.
  9. 텔레그램 알림 잇기(봇이 있을 때만) 2일차 2교시에서 텔레그램 봇을 만들지 않았다면 이 단계는 건너뜁니다. 8단계처럼 AI 공문 요약의 작은 점을 끌어 Telegram → Send a text message를 고르고 이름을 텔레그램 알림으로 고칩니다. 맨 위 Credential에서 내 봇 자격 증명을 고르고, Chat ID에 내 chat id(숫자, 2일차 2교시에서 확인한 것)를 적습니다. Text는 Expression으로 바꾸고 [상자 라]를 붙여 넣습니다.

    [상자 라] 알림 글 — Text에 붙여 넣기

    공문 요약이 도착했습니다. 메일을 확인해 주세요.
    텔레그램 알림에는 요약 본문과 파일 이름을 넣지 않습니다. 글이나 파일 이름에 든 _ 같은 기호 때문에 전송이 실패할 수 있기 때문입니다.

    AI 공문 요약에서 갈래가 나뉘고 앱에 답하기가 맨 위면 성공입니다. Ctrl+S로 저장합니다.

  10. 앱 만들기 AI Studio(aistudio.google.com/apps)에서 새 앱을 만듭니다. PDF 공문 요약 앱 주문서를 열어 "1) 새 앱 만들기" 아래 ```text 줄과 ``` 줄 사이의 글만 복사해 붙여 넣고 보냅니다(기호 줄과 제목은 복사하지 않습니다).

    오른쪽 미리보기에 공문 요약 제목, 파일 고르는 칸, 요약하기 버튼이 보이면 성공입니다. 다 만들어지기 전에는 다음 문장을 보내지 않습니다.

  11. 앱에 Test URL 넣기 — 문장 먼저, 주소 나중
    1. 주문서 "2) 주소 넣기" 문장을 복사해 AI Studio 입력창에 붙여 넣습니다. 아직 보내지 않습니다. {Production URL} 글자를 중괄호까지 지웁니다(따옴표는 남깁니다). 주문서에 Production URL이라고 적혀 있어도 지금은 Test URL을 넣고, Production URL은 13단계에서 넣습니다.
    2. n8n 탭으로 가서 공문 받기를 두 번 눌러 열고, 위쪽 Test URL을 눌러 주소를 복사합니다.
    3. AI Studio 탭으로 돌아와 따옴표 사이를 한 번 누르고 Ctrl+V를 누른 뒤 보냅니다.

    Code 탭의 WEBHOOK_URL에 webhook-test가 들어간 주소가 보이면 성공입니다.

  12. 시험하기
    1. 앱에서 바탕 화면의 가상공문.pdf를 고릅니다. 아직 요약하기를 누르지 않습니다.
    2. n8n 캔버스 아래 Execute workflow를 누릅니다. 이때부터 2분 안에 다음을 해야 합니다.
    3. 앱에서 요약하기를 누르고 30초쯤 기다립니다. 1분 반(100초)이 넘도록 답이 없으면 실패로 보고 아래 박스를 봅니다.

    앱에 목적·주요 내용·지원 사항·대상·일정 요약이 보이고, 메일(과 텔레그램)이 오면 성공입니다. n8n에서도 확인합니다: 공문 받기를 두 번 눌러 열고, 오른쪽 결과(OUTPUT) 칸 위쪽의 Binary 탭을 누르면 file 이름표 아래 가상공문.pdf가 보입니다.

    자주 하는 실수

    증상 요약하기를 누르자마자 앱에 실패가 떠요
    원인 n8n에서 Execute workflow를 누르지 않았거나 2분이 지났어요. 또는 공문 받기의 Allowed Origins (CORS)에 *가 없어요
    해결 공문 받기를 열어 Allowed Origins (CORS)가 *인지 보고, Execute workflow를 다시 누른 뒤 2분 안에 요약하기를 누르세요

    증상 글자 뽑기가 빨갛고 파일을 찾을 수 없다고 해요
    원인 앱이 보낸 봉투 이름표가 file이 아니에요(공문 받기의 Binary 탭에서 이름 확인)
    해결 주문서의 "3) 막혔을 때" 문장을 AI Studio에 보낸 뒤, n8n에서 Execute workflow를 다시 누르고 다시 올립니다. Binary 탭에 file이 보일 때까지 앱 쪽을 고칩니다(n8n 쪽 이름은 바꾸지 않습니다. 뒤 노드들의 표현식이 모두 file을 씁니다)

    증상 요약이 엉뚱하거나 "문서에 없음"만 나와요
    원인 스캔(사진) PDF라 글자가 뽑히지 않았어요. 오류 없이 빈 글자로 넘어갑니다
    해결 글자를 마우스로 고를 수 있는 PDF를 쓰세요(1단계 방법)

    증상 오래 기다리다 앱에 실패가 떠요
    원인 PDF가 커서 100초 안에 끝나지 않았어요
    해결 몇 쪽짜리 작은 PDF로 다시 해 보세요

  13. Publish하고 Production URL로 바꾸기
    1. n8n 화면 오른쪽 위 Publish를 누르고, 확인 창에서 다시 Publish를 누릅니다.
    2. AI Studio에 주문서 "2) 주소 넣기" 문장을 붙여 넣고(아직 보내지 않음) {Production URL}을 중괄호까지 지웁니다.
    3. n8n에서 공문 받기를 열고 위쪽 Production URL을 눌러 주소를 복사합니다(끝이 webhook/gongmun-summary, 가운데에 test가 없습니다).
    4. AI Studio로 돌아와 따옴표 사이에 붙여 넣고 보냅니다.

    Code 탭의 WEBHOOK_URL에 webhook-test가 없고, n8n에서 아무것도 누르지 않고 앱에서 PDF를 올려 요약이 오면 완성입니다.

    자주 하는 실수

    증상 시험 때는 됐는데 이제 실패해요
    원인 앱에 아직 Test URL이 들어 있거나 Publish를 하지 않았어요
    해결 Code 탭의 WEBHOOK_URL에 webhook-test가 있으면 이 단계 2부터 다시 하세요. n8n 오른쪽 위 버튼이 게시된 상태인지 확인합니다

파일 보내기가 끝내 안 될 때 먼저 1단계의 가상 공문 PDF로 다시 해 보고, 12단계 자주 하는 실수 박스를 차례로 확인합니다. 파일을 글자(base64)로 바꿔 보내는 다른 방법도 있지만 설정이 복잡합니다. 교육 중이라면 강사와 함께 해 봅니다.

정리

  • 파일은 앱이 file이라는 이름표로 보내고, n8n은 Extract from File로 글자를 뽑습니다.
  • 그 뒤는 민원 접수와 같습니다 — AI 요약, 앱에 답하기(맨 위), 메일, 텔레그램.
  • 스캔 PDF는 글자가 없어 요약하지 못합니다. AI 요약은 초안이므로 원문과 대조합니다.
  • 다음: 선택 실습 ②에서는 파일 대신 말로 민원을 넣어 봅니다. 현장점검 앱에 사진을 붙이고 싶다면 오늘 배운 파일 보내기(file)를 응용합니다.

  2. n8n에서 가져오기 Create workflow → 오른쪽 위 … → Import → From file. 노드 일곱 개가 보이면 성공입니다.
  3. 자격 증명 다시 연결하기 Google Gemini Chat Model(Gemini API 키), 요약 메일(Gmail), 텔레그램 알림(봇 토큰, 봇이 없으면 이 노드를 눌러 Delete로 지웁니다)을 차례로 두 번 눌러 열고 내 자격 증명을 고릅니다.
  4. 자리표시자 바꾸기 요약 메일의 To: 본인이메일@example.com → 내 Gmail 주소. 텔레그램 알림의 Chat ID: 여기에_본인_채팅_ID → 내 chat id. Gemini Model: models/gemini-3.8-flash 다시 고르기.

음성 입력 민원 접수

민원 접수 앱에 "음성으로 입력" 버튼을 더합니다 — n8n은 그대로 둡니다

학습목표

  • 민원 접수 앱에 "음성으로 입력" 버튼을 추가합니다.
  • 말한 내용이 텍스트로 바뀌어 기존 워크플로우로 접수되는 것을 확인합니다.

왜 이 실습인가

용어 다시 보기 Webhook(외부 앱이 n8n을 부르는 주소), Production URL(게시한 뒤 앱에 넣는 진짜 주소), Publish(워크플로우를 게시해 주소가 항상 동작하게 하는 버튼), API 키(서비스를 쓸 수 있게 해 주는 비밀 번호표) — 이 교시에서는 앱이 없거나 n8n을 되살릴 때만 나옵니다.

현장이나 전화 응대 중에는 긴 글을 치기 어렵습니다. 브라우저에는 말을 글로 바꿔 주는 기능이 들어 있어, 앱에 버튼 하나만 더하면 말로 상세설명을 채울 수 있습니다. 받아쓴 글은 상세설명 칸에 들어가 기존과 똑같이 보내지므로 n8n 워크플로우는 한 곳도 고치지 않습니다.

비유: 음성 입력 버튼은 옆자리의 받아쓰기 담당과 같습니다. 내가 말하면 받아 적어 상세설명 칸에 올려 두고, 접수 창구(n8n)는 누가 적었는지 상관없이 평소처럼 받습니다.

바뀌는 곳그대로인 곳
앱 화면: 상세설명 옆 "음성으로 입력" 버튼, 마이크 권한보내는 칸 이름, n8n 주소, 워크플로우 전체

마이크 권한은 두 겹입니다. 앱 설정 파일에 "마이크를 쓰겠다"고 적어 두는 것(3단계)과, 브라우저가 "이 사이트에 마이크를 허락할까요?"라고 묻는 것(4단계)입니다.

알아 둘 점
  • 크롬·엣지에서만 됩니다. 파이어폭스는 음성 입력을 지원하지 않습니다. 다른 브라우저(웨일 등)는 확인되지 않았으므로 크롬이나 엣지를 씁니다.
  • 말소리는 글로 바꾸기 위해 인터넷(구글 서버)으로 보내집니다. 실제 민원인 이름·연락처·사연은 말로 입력하지 않고, 아래의 가상 문장만 말합니다.
  • 교육망에서 막히면 인터넷 문제 안내가 뜰 수 있습니다. 그때는 손으로 입력합니다.
한 문장 요약 앱에 마이크 권한과 음성 인식 버튼을 주문하면, 말한 내용이 상세설명 칸에 글로 들어가고 나머지는 이틀 동안 만든 서비스가 그대로 처리합니다.

따라하기

걸리는 시간 25분쯤입니다(완성본을 다시 가져와야 하면 20분 더). 2일차 6교시에 한다면 내 프로젝트가 처음부터 끝까지 한 번 돌아간 뒤에 시작합니다.
  1. 준비하기 — 브라우저·마이크·앱
    • 브라우저: 작업 표시줄의 브라우저 아이콘을 봅니다. 크롬(빨강·노랑·초록 원)이나 엣지(파란 물결)가 아니면 둘 중 하나로 다시 엽니다.
    • 마이크: PC에 마이크(또는 마이크 달린 헤드셋)가 연결되어 있는지 봅니다. 없으면 강사에게 알리고, 4·5단계는 건너뛰어 상세설명을 손으로 입력한 뒤 6단계만 합니다.
    • 앱: AI Studio(aistudio.google.com/apps) 왼쪽 메뉴의 Apps를 누르고 민원 접수 앱을 엽니다. 2일차 5교시의 현장점검 앱이나 선택 실습 ①의 PDF 앱이 아닌지 꼭 확인합니다. 이름이 영어라 헷갈리면 하나씩 열어 미리보기에 이름·연락처·종류·상세설명 칸이 있는 앱을 고릅니다.

    미리보기에서 가상 값을 넣고 접수하기를 눌러 접수번호와 안내문이 보이면 준비된 것입니다.

    준비가 안 될 때
    • 앱은 있는데 접수가 안 되면: 이 교안 끝 "완성본 가져오기"로 n8n을 되살립니다.
    • 앱이 아예 없으면: 1일차 4교시 주문서로 새 앱을 만들고, 1일차 6교시 9단계 방법으로 WEBHOOK_URL에 내 Production URL을 넣습니다. 이 실습에는 접수 화면만 있으면 됩니다.
  2. 음성 입력 버튼 주문하기 음성 입력 주문서를 엽니다. "1) 음성 입력 버튼 더하기" 아래 상자에서 "민원 접수 화면의"로 시작해 "브라우저 음성 인식만 써 줘."로 끝나는 글만 복사합니다(위아래의 ```text 줄은 빼고). AI Studio 대화 입력창에 붙여 넣고 보내기(화살표) 버튼을 누릅니다. 주문서의 9가지 조건(마이크 권한, 브라우저 음성 인식 사용, 한국어, 듣는 중 표시, 이어 붙이기, 지원 안 되는 브라우저 안내, 오류 안내, 칸 이름 유지, AI 받아쓰기 넣지 않기)은 하나도 빼지 않고 그대로 보냅니다. 영어 단어는 AI에게 전하는 말이라 뜻을 몰라도 됩니다.

    AI의 답이 끝나 미리보기가 다시 나타날 때까지 1~2분 기다립니다. 그동안 다른 요청은 보내지 않습니다.

    미리보기의 상세설명 칸 옆에 음성으로 입력 버튼이 보이면 성공입니다. 버튼이 없거나 미리보기에 오류 글이 보이면 1일차 5교시 오류 신고 루틴 문장을 보냅니다.

  3. 마이크 권한이 들어갔는지 확인하기 미리보기 위쪽의 Code 탭을 누릅니다. 왼쪽 파일 목록에서 metadata.json(앱의 설정 파일)을 누릅니다. 목록이 길면 아래로 내려 찾습니다.

    "requestFramePermissions": ["microphone"]처럼 microphone이라는 글자가 보이면 성공입니다. 확인했으면 미리보기 탭을 눌러 돌아갑니다.

    없으면 주문서의 "3) 마이크 권한이 빠졌을 때" 문장을 보내고, AI의 답이 끝나면 이 단계를 한 번 더 합니다.

  4. 마이크 허용하기 미리보기에서 음성으로 입력을 누릅니다. 처음에는 마이크 사용을 묻는 창이 두 번(AI Studio 확인 창 → 브라우저 허용 창) 뜰 수 있습니다. 두 창 모두 허용을 누릅니다. 허용 버튼이 여러 개면 "방문할 때마다 허용"에 해당하는 버튼을, 영어 창이면 Allow를 누릅니다.

    버튼이 "듣는 중…"으로 바뀌면 성공입니다.

  5. 말로 입력해 보기 "듣는 중…"이 보이는 동안 아래 문장을 또박또박 말합니다. 
    주민센터 앞 보도블록이 깨져 있어 걷기가 위험합니다
    말을 마치고 2~3초 기다리면 "듣는 중…"이 사라집니다. 사라지지 않으면 버튼을 한 번 더 눌러 끝냅니다. 주변이 시끄러우면 마이크에 가까이 대고 말하고, 다른 사람 말이 섞여 들어가면 칸에서 지웁니다.

    상세설명 칸에 말한 문장이 글로 들어가면 성공입니다. 틀린 글자는 칸에서 손으로 고칩니다.

    자주 하는 실수

    증상 "마이크 사용을 허용해 주세요"가 떠요
    원인 허용 창에서 거부를 눌렀거나, 브라우저의 마이크 설정이 차단으로 되어 있어요
    해결 주소창 맨 왼쪽의 작은 표시(자물쇠나 조절 모양)를 누릅니다. 목록에서 마이크를 찾아 허용으로 바꾸고 F5로 새로고침한 뒤 버튼을 다시 누릅니다. AI Studio 확인 창에서 거부했다면 새로고침 뒤 다시 물어볼 때 허용합니다

    증상 "말소리가 들리지 않았습니다" 또는 "마이크를 찾을 수 없습니다"가 떠요
    원인 마이크가 연결되어 있지 않거나, 헤드셋 마이크가 꺼져 있거나, 말을 시작하기 전에 듣기가 끝났어요
    해결 헤드셋 선의 음소거 스위치를 확인하고 버튼을 다시 눌러 바로 말합니다. 마이크가 없으면 손으로 입력하고 6단계로 갑니다

    증상 같은 문장이 두 번 들어가요
    원인 말하는 중간 글자가 칸에 그대로 남았어요
    해결 칸에서 한 번 지우고, 주문서의 "4) 글이 두 번 들어갈 때" 문장을 보냅니다

    증상 "이 브라우저에서는 음성 입력을 쓸 수 없습니다"가 떠요
    원인 파이어폭스 등 지원하지 않는 브라우저예요
    해결 크롬이나 엣지로 앱을 여세요

    증상 "인터넷 연결을 확인해 주세요"가 떠요
    원인 음성 인식 서버에 닿지 못했어요(교육망에서 막혔을 수 있어요)
    해결 이번에는 손으로 입력하고, 강사에게 알립니다

  6. 접수하고 시트 확인하기 이름 김민원, 연락처 010-0000-0009, 이메일 minwon@example.com을 넣고, 종류는 생활을 고릅니다. 동의 칸이 있으면 체크하고 접수하기를 누릅니다.

    앱에 접수번호가 보이고, 시트 민원대장 연습의 시트1 탭 맨 아래 새 줄의 상세설명 칸에 말로 입력한 문장이 보이면 완성입니다. 담당자 메일과 텔레그램 알림도 평소처럼 옵니다. n8n은 한 곳도 고치지 않았습니다. 음성 입력이 막혀 손으로 적었다면, 적은 문장이 시트에 들어가면 성공입니다.

    이 실습은 AI Studio 편집 화면의 미리보기에서 합니다. 2일차 3교시에 만든 공유 링크에 바로 반영되는지는 강사 안내를 따릅니다.
    자주 하는 실수

    증상 음성 버튼을 넣은 뒤 접수가 안 돼요
    원인 AI가 앱을 고치면서 WEBHOOK_URL이나 보내는 칸 이름을 바꿨을 수 있어요
    해결 Code 탭에서 Ctrl+F로 WEBHOOK_URL을 찾아 /webhook/minwon으로 끝나는 내 Production URL인지 봅니다. 맞으면 2일차 6교시 점검 순서표를 따릅니다

정리

  • 앱에 마이크 권한과 음성 인식 버튼을 주문해 말로 상세설명을 채웠습니다.
  • 보내는 칸 이름을 바꾸지 않았으므로 n8n 쪽은 그대로 동작합니다.
  • 크롬·엣지에서만 되고, 말소리는 인터넷으로 보내지므로 실제 개인정보는 말로 넣지 않습니다.

완성본 가져오기(Import)

이 실습은 n8n을 바꾸지 않습니다. 연결된 워크플로우가 없으면 과정 최종 완성본(2일차 2교시)을 가져와 씁니다. 앱이 없을 때는 1단계의 "준비가 안 될 때"를 봅니다.

먼저: 예전 워크플로우를 Unpublish하세요 전에 Publish해 둔 민원 접수 워크플로우를 열어 Publish 오른쪽 작은 화살표를 눌러 목록 맨 아래 Unpublish를 누르고, 뜨는 창에서 다시 Unpublish를 누릅니다. 같은 주소(minwon)를 쓰는 Webhook은 하나만 동작할 수 있습니다.
  1. 파일 내려받기 최종 완성본 내려받기 d2-p2.json
  2. n8n에서 가져오기 n8n 첫 화면 오른쪽 위 Create workflow → 캔버스 오른쪽 위 … → Import → From file. 노드 열여덟 개가 보이면 성공입니다.
  3. 자격 증명 다시 연결하기 아래 노드를 차례로 두 번 눌러 열고 내 자격 증명(n8n이 내 계정을 대신 쓰도록 맡겨 둔 열쇠)을 고릅니다. 오늘 접수 조회, 시트에 기록, 접수번호로 찾기(구글 시트), Google Gemini Chat Model(Gemini API 키), 담당자 메일, 일반 담당자 메일(Gmail), 처리 마감 일정(캘린더), 텔레그램 알림(봇 토큰, 봇이 없으면 이 노드를 지웁니다).
  4. 자리표시자 바꾸기 시트 노드 세 개의 Document: 여기에_본인_시트_ID 대신 From list에서 민원대장 연습, Sheet는 시트1. 메일 두 개의 To: 본인이메일@example.com 대신 내 Gmail 주소. 텔레그램 알림의 Chat ID: 여기에_본인_채팅_ID 대신 내 chat id. 처리 마감 일정의 Calendar: 목록에서 내 캘린더. 더 자세한 설명은 2일차 2교시 완성본 가져오기에 있습니다.
  5. Publish하고 앱 주소 확인하기 Publish를 누릅니다. 민원 받기 노드를 열어 Production URL을 누르고 주소를 복사합니다. 앱의 Code 탭에서 Ctrl+F로 WEBHOOK_URL을 찾아 두 주소가 같은지 봅니다. 다르면 1일차 6교시 9단계 순서로 바꿔 넣습니다.

    미리보기에서 가상 민원을 접수해 접수번호가 보이면 복구가 끝났습니다.
