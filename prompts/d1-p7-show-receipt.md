# 접수 완료 화면에 접수번호 보여 주기

- 사용 교시: d1-p7 (1일차 7교시 연동 ① 완성)
- 전제: d1-p4 프롬프트로 만든 앱은 이미 "응답 JSON의 `접수번호`와 `메시지`를 접수 완료 화면에 보여 주기"가 들어 있다. n8n이 `Respond to Webhook`으로 `{"접수번호": "...", "메시지": "..."}`를 돌려주면 **앱을 고치지 않아도** 번호가 보이는 것이 정상이다.
- 이 파일의 문장은 번호가 보이지 않거나 더 보기 좋게 바꾸고 싶을 때만 쓴다.
- 응답 키 이름은 `docs/data-contract.md`의 "응답" 표(d1-p7: `접수번호`, `메시지`)와 같다.

## 복사할 프롬프트

### 번호가 보이지 않을 때 (우선 이것)

```text
접수하기를 누르면 n8n이 {"접수번호": "2026-0922-017", "메시지": "접수되었습니다"} 모양의 JSON을 돌려줘. 접수 완료 화면에 "접수번호"를 크게, "메시지"를 그 아래에 보여 줘. 입력 칸 이름과 WEBHOOK_URL은 바꾸지 마.
```

### 더 보기 좋게 (시간이 남으면)

```text
접수 완료 화면을 다듬어 줘. 맨 위에 초록색 체크 표시와 "접수가 완료되었습니다", 그 아래 상자 안에 "접수번호"를 아주 크게 보여 주고, "접수번호를 메모해 두시면 처리 상태를 문의할 때 편합니다."라는 안내를 한 줄 넣어 줘. "새 민원 접수" 버튼은 그대로 둬. 입력 칸 이름과 WEBHOOK_URL은 바꾸지 마.
```

## 바꿀 자리

- 없음. `2026-0922-017`은 AI에게 모양을 알려 주는 예시이며 실제로는 n8n이 만든 번호가 들어간다.

## 예상 결과

- n8n에서 `Respond to Webhook`을 연결하고 다시 `Publish`한 뒤 앱에서 접수하면, 완료 화면에 `2026-0925-001`처럼 오늘 날짜와 순번이 보인다.
- 같은 날 두 번째 접수는 `…-002`가 된다.
- 번호 대신 빈칸이나 `undefined`가 보이면 첫 번째 문장을 보낸다. 그래도 안 되면 n8n `Executions`에서 `앱에 답하기` 노드가 실행되었는지 본다.
