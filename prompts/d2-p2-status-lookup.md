# 처리 상태 조회 화면 만들기

- 사용 교시: d2-p2 (2일차 2교시 연동 ② 완성)
- 전제: n8n에 조회용 GET Webhook `상태 조회`(경로 `minwon-status`)가 있고, 주소 뒤에 `?no=접수번호`를 붙여 부른다(`docs/data-contract.md`, D44).
- 응답: 찾으면 `{"찾음": true, "접수번호", "처리상태", "담당자", "처리마감"}`, 없으면 `{"찾음": false, "오류": "접수번호를 찾을 수 없습니다"}` — 항상 200.
- 순서: n8n에서 **주소창으로 먼저 시험**(`Test URL?no=접수번호`, d1-p3 방식) → `Publish` → 앱에는 `{조회용 Production URL}`을 바로 넣는다. 앱 수정 요청이 한 번으로 줄어든다.

## 복사할 프롬프트

### 1) 조회 화면 추가 (n8n에서 Publish한 뒤)

```text
이 앱에 "처리 상태 조회" 화면을 하나 더 만들어 줘. 맨 위에 "민원 접수"와 "처리 상태 조회" 두 개의 탭(또는 버튼)을 두고 오갈 수 있게 해 줘.

[처리 상태 조회 화면]
- 입력 칸 1개: 접수번호 (안내 글: 예) 2026-0925-001)
- "조회하기" 버튼
- 코드 맨 위에 STATUS_URL 이라는 상수를 새로 만들고 값은 "{조회용 Production URL}"로 해 줘.
- 조회하기를 누르면 STATUS_URL 뒤에 ?no=입력한접수번호 를 붙여 GET 방식으로 불러 줘. (접수번호는 주소에 넣을 수 있게 인코딩해 줘)
- 응답 JSON의 "찾음"이 true면 접수번호, 처리상태, 담당자, 처리마감을 표로 보여 줘.
- "찾음"이 false면 "오류" 글을 빨간색으로 보여 줘.
- 응답이 오지 않으면 "조회하지 못했습니다. 잠시 뒤 다시 시도해 주세요."를 보여 줘.

[바꾸지 말 것]
- 민원 접수 화면, 입력 칸 이름, WEBHOOK_URL은 그대로 둬.
```

### 2) 막혔을 때 — 브라우저에서 n8n을 부르지 못할 때만 (d1-p6과 같은 우회)

```text
조회하기를 누르면 "조회하지 못했습니다"가 떠. n8n 주소 호출은 서버 쪽 코드에서 하도록 바꿔 줘. STATUS_URL과 WEBHOOK_URL 값은 바꾸지 마.
```

## 바꿀 자리

- `{조회용 Production URL}`: `Publish` 뒤 n8n `상태 조회` 노드의 `Production URL`(주소 끝이 `webhook/minwon-status`). `?no=`는 넣지 않는다 — 앱이 붙인다.
- 중괄호 `{ }`는 지우고 주소만 따옴표 안에 넣는다. 주소는 d1-p6처럼 **문장을 먼저 붙여 넣은 뒤** 복사해 끼워 넣는다.

## 예상 결과

- 앱 위쪽에 두 탭이 생기고, 조회 화면에서 오늘 받은 접수번호를 넣으면 처리상태 `접수`, 담당자, 처리마감(등록일 + 3일)이 보인다.
- 없는 번호(예: `2026-0101-999`)를 넣으면 "접수번호를 찾을 수 없습니다"가 빨간색으로 보인다.
