# 현장점검 보고 앱 만들기 (프로젝트 예시)

- 사용 교시: d2-p5 (2일차 5교시 프로젝트 제작 ①) — 설계서 예시 "현장점검 보고 앱"의 주문서
- 연결 약속: `docs/data-contract.md`의 "현장점검 보고 앱" 표(경로 `field-check`, 칸 `점검장소`·`점검결과`·`특이사항`·`점검자`)
- 예시 워크플로우: `workflows/d2-p5.json`(기본형), `workflows/d2-p6.json`(확장형)
- 내 서비스는 `prompts/d2-p4-design-to-prompt.md`의 빈 템플릿을 설계서로 채워 쓴다.

## 복사할 프롬프트

```text
시설과 점검 담당자가 쓰는 "현장점검 보고" 웹 앱을 만들어 줘. 화면의 모든 글자는 한국어로 써 줘.

[화면]
- 맨 위 제목: 현장점검 보고
- 입력 칸 4개 (모두 꼭 채워야 하는 칸)
  1. 점검장소 (안내 글: 예) OO동 체육공원)
  2. 점검결과 — 양호, 보수필요 두 가지 중에서 고르는 목록
  3. 특이사항 — 여러 줄을 쓸 수 있는 칸
  4. 점검자 (안내 글: 예) 오점검)
- 맨 아래 "보고하기" 버튼
- 글자는 크게, 버튼은 크고 누르기 쉽게, 휴대폰 화면에서도 보기 좋게

[보고하기를 눌렀을 때]
- 빈 칸이 있으면 어느 칸이 비었는지 알려 줘.
- 코드 맨 위에 WEBHOOK_URL 이라는 상수를 만들고 값은 빈 문자열("")로 둬.
- WEBHOOK_URL이 비어 있으면 "아직 연결되지 않았습니다."를 보여 줘.
- 비어 있지 않으면 입력한 값을 JSON으로 WEBHOOK_URL에 POST 방식으로 보내. JSON의 키 이름은 한글 그대로 점검장소, 점검결과, 특이사항, 점검자 로 해.
- 응답 JSON의 "접수번호"와 "메시지"를 완료 화면에 크게 보여 주고, "새로 입력" 버튼으로 처음 화면에 돌아가게 해.

[넣지 말 것]
- 로그인, 회원가입, 데이터베이스, Gemini(AI) 기능은 넣지 마.
- 실제 사람의 이름이나 연락처를 예시로 넣지 마.
```

### 주소 넣기 (n8n에서 Publish한 뒤)

```text
코드 맨 위 WEBHOOK_URL 값을 "{Production URL}"로 바꿔 줘. 다른 부분은 바꾸지 마.
```

## 바꿀 자리

- `{Production URL}`: n8n `점검 받기` 노드의 Production URL(끝이 `webhook/field-check`). 시험은 d1-p6처럼 Test URL로 먼저 해도 된다.

## 예상 결과

- 제목 `현장점검 보고`, 칸 4개(점검결과는 양호/보수필요 목록), `보고하기` 버튼.
- 주소를 넣은 뒤 보고하면 `점검대장 연습` 시트에 한 줄이 생기고 앱에 접수번호와 "점검 보고가 접수되었습니다"가 보인다.
