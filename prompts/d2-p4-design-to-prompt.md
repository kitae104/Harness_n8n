# 설계서를 AI Studio 주문서(프롬프트)로 옮기기

- 사용 교시: d2-p4 (2일차 4교시 프로젝트 기획), 이어서 d2-p5에서 그대로 사용
- 입력: `print/forms/design-sheet.html`의 설계서(서비스 이름·누가 쓰나·입력·처리·출력)
- 구성은 d1-p4 민원 접수 템플릿과 같다: **[화면] · [눌렀을 때] · [넣지 말 것]**. `WEBHOOK_URL` 빈 자리를 미리 만들어 둔다.
- 보내는 JSON 키는 설계서의 "입력" 칸 이름 그대로(한글). n8n 쪽 `민원 정리`에 해당하는 노드에서 같은 이름을 쓴다.

## 복사할 프롬프트

### 빈 템플릿 (설계서 보고 채우기)

```text
{누가 쓰나}이(가) 쓰는 "{서비스 이름}" 웹 앱을 만들어 줘. 화면의 모든 글자는 한국어로 써 줘.

[화면]
- 맨 위 제목: {서비스 이름}
- 입력 칸 (5개 이하)
  1. {입력 칸 1} (안내 글: 예) {가상 예시})
  2. {입력 칸 2} — {고르는 목록이면 선택지를 쉼표로}
  3. {입력 칸 3}
- 맨 아래 "{보내기 버튼 이름}" 버튼
- 글자는 크게, 버튼은 크고 누르기 쉽게, 휴대폰 화면에서도 보기 좋게

[{보내기 버튼 이름}을 눌렀을 때]
- 빈 칸이 있으면 어느 칸이 비었는지 알려 줘.
- 코드 맨 위에 WEBHOOK_URL 이라는 상수를 만들고 값은 빈 문자열("")로 둬.
- WEBHOOK_URL이 비어 있으면 "아직 연결되지 않았습니다."를 보여 줘.
- 비어 있지 않으면 입력한 값을 JSON으로 WEBHOOK_URL에 POST 방식으로 보내. JSON의 키 이름은 한글 그대로 {입력 칸 이름들} 으로 해.
- 응답 JSON의 "접수번호"와 "메시지"를 완료 화면에 크게 보여 주고, "새로 입력" 버튼으로 처음 화면에 돌아가게 해.

[넣지 말 것]
- 로그인, 회원가입, 데이터베이스, Gemini(AI) 기능은 넣지 마.
- 실제 사람의 이름이나 연락처를 예시로 넣지 마.
```

### 작성 예 — 현장점검 보고 앱

```text
시설과 점검 담당자가 쓰는 "현장점검 보고" 웹 앱을 만들어 줘. 화면의 모든 글자는 한국어로 써 줘.

[화면]
- 맨 위 제목: 현장점검 보고
- 입력 칸 4개 (모두 꼭 채워야 하는 칸)
  1. 점검장소 (안내 글: 예) OO동 체육공원)
  2. 점검결과 — 양호, 보수필요 두 가지 중에서 고르는 목록
  3. 특이사항 — 여러 줄을 쓸 수 있는 칸
  4. 점검자 (안내 글: 예) 오점검)
- 맨 아래 "보고하기" 버튼
- 글자는 크게, 버튼은 크고 누르기 쉽게, 휴대폰 화면에서도 보기 좋게

[보고하기를 눌렀을 때]
- 빈 칸이 있으면 어느 칸이 비었는지 알려 줘.
- 코드 맨 위에 WEBHOOK_URL 이라는 상수를 만들고 값은 빈 문자열("")로 둬.
- WEBHOOK_URL이 비어 있으면 "아직 연결되지 않았습니다."를 보여 줘.
- 비어 있지 않으면 입력한 값을 JSON으로 WEBHOOK_URL에 POST 방식으로 보내. JSON의 키 이름은 한글 그대로 점검장소, 점검결과, 특이사항, 점검자 로 해.
- 응답 JSON의 "접수번호"와 "메시지"를 완료 화면에 크게 보여 주고, "새로 입력" 버튼으로 처음 화면에 돌아가게 해.

[넣지 말 것]
- 로그인, 회원가입, 데이터베이스, Gemini(AI) 기능은 넣지 마.
- 실제 사람의 이름이나 연락처를 예시로 넣지 마.
```

## 바꿀 자리

- `{…}` 자리를 설계서 내용으로 바꾼다. 중괄호는 지운다.
- 입력 칸 이름은 짧고 띄어쓰기 없이(예: `점검장소`) 쓴다. 이 이름이 시트 머리글과 n8n 표현식에 그대로 쓰인다.
- 사진·파일 칸은 이번 프로젝트에서는 넣지 않는다(D46). 필요하면 선택 실습 `opt-pdf`의 방법을 참고한다.

## 예상 결과

- d1-p4와 같은 모양의 입력 화면이 생기고, 보내기 버튼을 누르면 "아직 연결되지 않았습니다."가 보인다.
- `Code` 탭에 빈 `WEBHOOK_URL`이 있다. d2-p5에서 n8n 주소를 넣는다.
