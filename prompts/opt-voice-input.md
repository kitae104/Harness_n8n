# 민원 접수 앱에 음성 입력 버튼 더하기 (선택 실습)

- 사용 교시: opt-voice (선택 실습 ② — 2일차 6교시 중 희망자, 수료 후 자율학습)
- 전제: 1일차에 만든 민원 접수 앱(d2-p2까지 연결된 것). **n8n 워크플로우는 바꾸지 않는다** — 받아쓴 글이 `상세설명` 칸에 들어가 기존처럼 보내진다.
- 쓸 수 있는 브라우저: **크롬·엣지**(파이어폭스는 지원하지 않음, F217). 말소리는 인식을 위해 인터넷(구글 서버)으로 보내진다(F219).

## 복사할 프롬프트

### 1) 음성 입력 버튼 더하기

```text
민원 접수 화면의 "상세설명" 칸 옆에 "음성으로 입력" 버튼을 넣어 줘. 아래를 모두 지켜 줘.

1. 앱이 마이크를 쓸 수 있도록 metadata.json의 requestFramePermissions에 "microphone"을 넣어 줘.
2. 브라우저 음성 인식(SpeechRecognition 또는 webkitSpeechRecognition)을 써 줘.
3. 인식 언어는 한국어(ko-KR)로 해 줘.
4. 버튼을 누르면 "듣는 중…"을 보여 주고, 말하는 동안 중간 글자도 보여 줘. 다시 누르거나 말을 멈추면 끝내 줘.
5. 인식한 글은 상세설명 칸에 이미 있는 내용 뒤에 이어 붙이고, 칸은 손으로 고칠 수 있게 그대로 둬.
6. 음성 인식을 지원하지 않는 브라우저면 버튼 대신 "이 브라우저에서는 음성 입력을 쓸 수 없습니다. 크롬이나 엣지를 써 주세요."를 보여 줘.
7. 오류가 나면 한국어로 알려 줘: 마이크 권한을 거부했을 때 "마이크 사용을 허용해 주세요", 말소리가 없을 때 "말소리가 들리지 않았습니다", 인터넷 문제일 때 "인터넷 연결을 확인해 주세요", 마이크를 찾지 못했을 때 "마이크를 찾을 수 없습니다. 마이크 연결을 확인해 주세요".
8. 입력 칸 이름, 보내는 JSON의 키, WEBHOOK_URL은 바꾸지 마.
9. Gemini(AI)로 받아쓰는 기능은 넣지 마. 브라우저 음성 인식만 써 줘.
```

### 2) 막혔을 때 — 버튼을 눌러도 아무 일이 없을 때

```text
음성으로 입력 버튼을 눌러도 아무 반응이 없어. metadata.json에 microphone 권한이 들어 있는지 확인하고, 오류가 나면 화면에 오류 이름을 보여 주게 해 줘. 다른 부분은 바꾸지 마.
```

### 3) 마이크 권한이 빠졌을 때 — metadata.json에 microphone이 없을 때

```text
metadata.json의 requestFramePermissions에 "microphone"을 넣어 줘. 다른 부분은 바꾸지 마.
```

### 4) 글이 두 번 들어갈 때

```text
말하는 중간 글자는 칸에 남기지 말고, 말이 끝난 뒤 최종 글자만 한 번 이어 붙여 줘. 다른 부분은 바꾸지 마.
```

## 바꿀 자리

- 없음.

## 예상 결과

- 상세설명 옆에 `음성으로 입력` 버튼. 처음 누르면 AI Studio 확인 창과 브라우저 마이크 허용 창이 차례로 뜬다(F221, 강사 확인).
- "주민센터 앞 보도블록이 깨져 있어 걷기가 위험합니다"라고 말하면 상세설명 칸에 글이 들어가고, `접수하기`로 기존처럼 접수된다.
