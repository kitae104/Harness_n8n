# 화면 수정 요청 문장 모음

- 사용 교시: d1-p5 (1일차 5교시 첫 앱 다듬기)
- 사용 도구: Google AI Studio Build 모드 — 4교시에 만든 앱의 대화 입력창
- 원칙: **한 번에 한 가지**, **어디를 · 어떻게**를 구체적으로, **바꾸면 안 되는 것**을 함께 말한다
- 입력 칸 이름·순서와 `WEBHOOK_URL`은 6교시 연결 약속(`docs/data-contract.md`)이므로 바꾸지 않는다

## 복사할 프롬프트

아래 문장을 **하나씩** 보낸다. 요청 2는 시간이 남을 때만 보낸다. 앞 요청의 결과를 미리보기에서 확인한 뒤 다음 요청을 보낸다.

### 요청 1 — 제목과 안내 문구

```text
맨 위 제목을 "OO구 민원 접수"로 바꾸고, 제목 아래에 작은 글씨로 "평일 09:00~18:00 확인 후 연락드립니다."를 한 줄 더해 줘. 입력 칸과 버튼은 그대로 둬.
```

### 요청 2 — 색과 버튼 (시간이 남으면)

```text
배경을 아주 연한 하늘색으로, "접수하기" 버튼은 진한 파란색 바탕에 흰 글씨로 바꾸고 버튼을 화면 가로 폭에 꽉 차게 해 줘. 입력 칸의 이름과 순서는 바꾸지 마.
```

### 요청 3 — 개인정보 동의 칸

```text
"접수하기" 버튼 바로 위에 "개인정보 수집·이용에 동의합니다(필수)" 체크 칸을 넣어 줘. 체크하지 않으면 접수되지 않고 "개인정보 수집·이용에 동의해 주세요."라고 알려 줘. 이 체크 여부는 보내는 JSON에 넣지 마.
```

## 나쁜 예 → 좋은 예

| 나쁜 예 | 왜 안 되나 | 좋은 예 |
|---|---|---|
| 예쁘게 해 줘 | "예쁘게"의 기준을 AI가 마음대로 정해 칸·버튼까지 바꿀 수 있다 | 배경을 아주 연한 하늘색으로, 제목 글자를 지금보다 크게 해 줘. 입력 칸은 그대로 둬 |
| 버튼 고쳐 줘 | 어느 버튼을 어떻게 고칠지 없다 | "접수하기" 버튼을 진한 파란색 바탕에 흰 글씨로 바꾸고 가로 폭에 꽉 차게 해 줘 |
| 동의 받게 해 줘 | 어디에, 무엇을, 동의 안 하면 어떻게 할지 없다 | "접수하기" 버튼 바로 위에 개인정보 동의 체크 칸을 넣고, 체크하지 않으면 접수되지 않게 해 줘 |
| 제목 바꾸고 색도 바꾸고 칸도 하나 더 넣어 줘 | 한 번에 여러 가지를 바꾸면 무엇이 잘못됐는지 찾기 어렵다 | 한 가지씩 나누어 보내고, 하나 확인한 뒤 다음을 보낸다 |

## 바꿀 자리

- `OO구`: 수강생 기관 이름으로 바꿔도 된다(실제 기관명 사용 가능, 개인정보 아님).
- 색·문구는 자유롭게 바꿔도 된다. **입력 칸 이름(이름·연락처·이메일·종류·상세설명)과 `WEBHOOK_URL`은 바꾸지 않는다.**

## 예상 결과

- 요청 1: 제목과 안내 문구가 바뀌고 칸은 그대로다.
- 요청 2: 배경·버튼 색이 바뀐다.
- 요청 3: 체크 칸이 생기고, 체크하지 않고 누르면 동의 안내가 뜬다. 체크하고 누르면 4교시처럼 "아직 접수 창구와 연결되지 않았습니다"가 뜬다.
