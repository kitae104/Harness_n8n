# PDF 공문 요약 앱 만들기 (선택 실습)

- 사용 교시: opt-pdf (선택 실습 ① — 2일차 6교시 중 희망자, 수료 후 자율학습)
- 연결 약속: `docs/data-contract.md` — 경로 `gongmun-summary`(POST), 파일 필드 이름 `file`, 응답 `{"파일", "요약"}` (D47)
- n8n 쪽: `workflows/opt-pdf.json`
- 핵심: 파일은 **FormData에 `file`이라는 이름으로** 담아 보내고, **Content-Type 헤더는 직접 쓰지 않는다**(브라우저가 알아서 붙인다, F215).

## 복사할 프롬프트

### 1) 새 앱 만들기

```text
공무원이 쓰는 "공문 요약" 웹 앱을 새로 만들어 줘. 화면의 모든 글자는 한국어로 써 줘.

[화면]
- 맨 위 제목: 공문 요약
- 안내 한 줄: PDF 공문을 올리면 핵심을 5줄로 요약해 드립니다. (스캔한 사진 PDF는 읽지 못합니다)
- PDF 파일 1개를 고르는 칸 (PDF만 고를 수 있게)
- "요약하기" 버튼
- 글자는 크게, 버튼은 크고 누르기 쉽게

[요약하기를 눌렀을 때]
- 파일을 고르지 않았으면 "PDF 파일을 골라 주세요."를 보여 줘.
- 코드 맨 위에 WEBHOOK_URL 이라는 상수를 만들고 값은 빈 문자열("")로 둬. 비어 있으면 "아직 연결되지 않았습니다."를 보여 줘.
- 비어 있지 않으면, 고른 PDF를 FormData에 file 이라는 이름으로 담아 WEBHOOK_URL에 POST로 보내. Content-Type 헤더는 직접 지정하지 마.
- 보내는 동안 "요약 중입니다. 30초쯤 걸릴 수 있습니다."를 보여 줘.
- 응답 JSON의 "파일"(파일 이름)과 "요약"(여러 줄)을 줄바꿈 그대로 보여 주고, "다른 공문 요약" 버튼으로 처음 화면에 돌아가게 해.
- 실패하면 "요약하지 못했습니다. 파일이 너무 크거나 스캔본인지 확인해 주세요."를 보여 줘.

[넣지 말 것]
- 로그인, 데이터베이스, 앱 안에서 직접 Gemini를 부르는 기능은 넣지 마.
```

### 2) 주소 넣기

```text
코드 맨 위 WEBHOOK_URL 값을 "{Production URL}"로 바꿔 줘. 다른 부분은 바꾸지 마.
```

### 3) 막혔을 때 — n8n에서 Binary 탭에 file이 보이지 않을 때

```text
PDF를 보낼 때 FormData의 파일 이름이 정확히 file 인지 확인해 줘. Content-Type 헤더를 직접 넣었다면 지워 줘. 다른 부분은 바꾸지 마.
```

## 바꿀 자리

- `{Production URL}`: 처음 시험 때는 `공문 받기`의 **Test URL**을, Publish한 뒤에는 Production URL(끝이 `webhook/gongmun-summary`)을 넣는다. 문장을 먼저 붙여 넣고 주소는 나중에 복사한다(교안 11·13단계).

## 예상 결과

- 파일 고르는 칸과 `요약하기` 버튼이 있는 화면.
- 가상 공문 PDF(`assets/samples/gongmun-sample.html`을 PDF로 저장한 것)를 올리면 목적·주요 내용·지원 사항·대상·일정 다섯 줄 요약이 보인다.
- 스캔 PDF는 글자를 뽑지 못해 엉뚱한 요약이 나올 수 있다.
