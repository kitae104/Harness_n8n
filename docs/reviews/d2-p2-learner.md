# d2-p2 수강생 관점 리뷰 (2026-09-25)

리뷰 대상: `lessons/d2-p2.html`, `prompts/d2-p2-status-lookup.md`, `workflows/d2-p2.json`(Import 안내와 대조)
관점: 54세 주무관, 기초과정 수료 후 석 달, 영어 화면은 단어를 하나씩 맞춰 봄, 텔레그램 봇은 석 달 전 준비물로 만들었음(토큰은 어디 뒀는지 가물가물).

## 요약
- 막힘 8건 / 헷갈림 18건 / 사소 7건
- 가장 먼저 고칠 곳: **단계 번호가 A·B·C마다 1부터 다시 시작합니다.** `ol.steps`가 세 개로 나뉘어 있고 CSS가 `ol.steps`마다 `counter-reset: s`를 하므로 화면에는 A 1·2, B 1·2, C 1~7로 보입니다. 그런데 본문은 "7단계", "10단계부터", "텔레그램(4단계)", "9단계 ①", Import의 "따라하기 10단계"로 부릅니다. 뒤처진 수강생이 "10단계부터 함께 합니다"를 들으면 찾을 곳이 없습니다. 그다음은 **분량**입니다(아래 시간 어림).

### 시간 어림(느린 수강생 기준, 텔레그램 봇·토큰이 이미 손에 있다고 가정)

| B. 텔레그램 | B-1 노드 추가 / B-2 자격 증명·Chat ID·글·Attribution | 7~8분 (토큰을 찾아야 하면 +5~10분, 봇이 없으면 +10~15분) |

- 결론: **그대로는 50분 안에 끝나지 않습니다.** 빠른 수강생도 실습 40분을 넘깁니다.
- 게다가 "10시 35분 체크포인트 → Import"는 Import 자체가 느린 수강생에게 8~10분 걸립니다(Unpublish, 가져오기, 자격 증명 **일곱 노드** 다시 연결, 자리표시자 여섯 곳, Publish). 10시 45분에야 C-6(앱 조회 화면)을 시작하게 되어 복구 경로로서 제 역할을 못 합니다.
- 선택으로 돌릴 것(권장 순서):
  1. **B. 텔레그램 전체를 "선택"으로** 돌립니다. 학습목표 3개 중 핵심(조회 입구·조회 화면)과 무관하고, 토큰·chat id 찾기가 사람마다 편차가 가장 큽니다. 교시 끝 "시간이 남으면" 박스로 옮기거나, B를 C 뒤로 옮기고 "(선택)"을 붙입니다. 완성본 JSON에 텔레그램 노드가 들어 있으므로 Import 안내에 "봇이 없으면 이 노드를 지웁니다"를 함께 둡니다.
  2. **A-2의 제목 두 개 고치기 → 한 개만.** `담당자 메일`의 제목은 1교시 것(`[{{ $json.종류 }}] …`)을 그대로 두고 `일반 담당자 메일`만 `[{{ $json.종류 }}·강처리] …`로 고치면, 확인할 때 ①은 `[생활]`, ②는 `[음식물·강처리]`로 충분히 구분됩니다.
  3. C-4의 "없는 번호로 한 번 더"와 C-7의 "처리상태를 처리중으로 고쳐 다시 조회"는 "(시간이 남으면)"으로 표시합니다.
  4. 체크포인트를 **10시 25분(A 끝났는지)**, **10시 35분(C-3 끝났는지)** 두 번 두고, 10시 35분에 못 마친 사람은 Import 대신 **강사 화면을 보며 C-6·C-7만 함께 하기**(앱 조회 화면은 강사의 완성본 URL로 체험) 같은 가벼운 경로가 있으면 좋습니다(강사 판단 필요).

## 잘된 점(유지)
- 불안을 주는 말("간단히", "쉽게", "당연히", "누구나")이 없습니다.
- 개인정보: 가상 인명·`010-0000-XXXX`·`minwon@example.com`만 쓰고, "이름은 텔레그램으로도 전달됩니다" 경고와 "상세 설명을 알림에 넣지 않는 이유"가 있어 좋습니다. 실습 알림을 "내 텔레그램"으로 보내게 한 것도 좋습니다.

- 앱을 고치기 전에 주소창으로 먼저 시험하게 한 순서 덕분에 앱 수정 요청이 한 번으로 줄어듭니다.
- Import 안내의 자격 증명 노드 목록(일곱 개)과 자리표시자(`여기에_본인_시트_ID`, `본인이메일@example.com`, `여기에_본인_채팅_ID`)가 JSON과 일치합니다.
