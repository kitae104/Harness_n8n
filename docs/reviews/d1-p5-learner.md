# d1-p5 수강생 관점 리뷰 (2026-09-25)

검토 대상: `lessons/d1-p5.html`, `prompts/d1-p5-edit-requests.md`, `prompts/d1-p5-error-routine.md` (앞 교시 `lessons/d1-p4.html`과 대조)
관점: 54세 주무관, 프로그래밍 경험 없음, 영어 화면은 글자를 하나씩 맞춰 찾음. 워크플로우가 없는 교시라 Import 섹션이 없는 것은 정상으로 보고, 대신 **앱이 망가졌을 때 교시 끝 상태로 돌아오는 길**을 확인했다.

## 요약
- 막힘 5건 / 헷갈림 12건 / 사소 8건
- 가장 먼저 고칠 곳: **B-3 단계의 복사 순서.** B-2에서 오류 글을 복사한 뒤 B-3에서 "오류 신고 문장"을 복사하면, 먼저 복사한 오류 글이 지워지고 신고 문장으로 바뀝니다(Ctrl+C는 마지막에 복사한 것 하나만 기억함). 그러면 "(여기에 …)" 자리에 붙여 넣을 오류 글이 없습니다. 루틴의 핵심 단계라 오늘 교시 목표 2번이 여기서 막힙니다. 순서를 "신고 문장 먼저 입력창에 붙여 넣기 → 오류 글 복사 → '오류:' 아래에 붙여 넣기"로 바꿔야 합니다.
- 그다음: A-5에서 `Code` 탭을 연 뒤 `Preview`로 돌아가라는 말이 없음, B-4(2회차)에서 미리보기가 하얗게 비면 복사할 오류 글이 없음, A-6 되돌리기에서 어느 `Restore`를 누를지와 무엇이 보이면 성공인지 모름, 오류가 끝내 안 고쳐졌을 때 스스로 되돌리는 길이 없음.
- 조건부 문장("~이 보이면")에 대한 의견: `Fix errors`처럼 **"없으면 문장을 쓴다"는 대안이 바로 붙은 곳은 괜찮습니다.** 문제는 (1) 대안이 있어도 버튼을 먼저 찾느라 시간을 쓰는 곳(A-6 `Restore`), (2) 버튼을 누른 결과가 교안의 성공 문장과 달라지는 곳(A-6, B-3), (3) "오류 글이 보이면"처럼 **보이지 않을 때 무엇을 할지 없는 곳**(B-1, B-4)입니다. 수강생이 할 일을 "문장 보내기" 하나로 정하고, 버튼은 "눈에 띄면 써도 된다" 정도로 낮추기를 권합니다.
- 시간: 느린 수강생 기준 실습이 40~45분으로 어림됩니다(AI 응답 대기 8~9회 포함). 30~35분을 넘습니다(지적 #15).
- 불안을 주는 말("간단히", "쉽게", "당연히", "누구나")은 없습니다. "오류가 나는 것은 내 잘못이 아니며"는 좋습니다. 개인정보는 가상 값 안내가 충분합니다.
