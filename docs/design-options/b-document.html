    4. 실습 자료: 가상 자료만 사용(실제 민원·공문·실명·연락처 입력 금지)

확인설명실습마침

왜 이 단계가 필요한가

지금까지 세 조각을 따로 만들었습니다. 2교시의 일하는 워크플로우, 3교시의 초인종인 Webhook, 4·5교시의 창구 화면인 앱입니다. 이번 시간에 이 셋을 이어 붙여, 앱에서 누른 접수가 시트까지 가게 합니다.

따라하기

  1. 새 워크플로우에 민원 받기 만들기

    n8n에서 Create workflow를 누르고 Webhook 노드를 추가한 뒤 아래와 같이 바꿉니다.

    1. HTTP Method: POST
    2. Path: 글자를 모두 지우고 minwon만 적음
    3. Allowed Origins (CORS): *

    확인 설정 창 위쪽 주소가 …/webhook-test/minwon으로 끝나면 성공입니다.

  2. 앱에 Test URL 넣기

    아래 요청문을 AI Studio 입력창에 붙여 넣고, {Test URL} 자리에 n8n에서 복사한 주소를 넣어 보냅니다.

    요청문코드 맨 위 WEBHOOK_URL 값을 "{Test URL}"로 바꿔 줘. 다른 부분은 바꾸지 마.

    확인 Code 탭의 WEBHOOK_URL에 webhook-test 주소가 보이면 성공입니다.

  3. 첫 시험 — 앱에서 보내 보기

    1. 앱에 가상 값(홍길동 / 010-1234-5678)을 넣고 동의에 체크합니다. 아직 누르지 않습니다.
    2. n8n에서 Listen for test event를 누릅니다(2분 동안만 기다림).
    3. 곧바로 앱의 접수하기를 누릅니다.
    ※ 유의사항(자주 하는 실수)
    증상
    n8n에 아무것도 오지 않음
    원인
    2분 경과, 주소 오류, CORS 설정 누락 중 하나
    조치
    세 가지를 차례로 확인한 뒤 가.~다.를 다시 함
    막혔을 때의 조치 AI Studio에 “n8n 주소 호출은 서버 쪽 코드에서 하도록 바꿔 줘”라고 보낸 뒤 다시 시험합니다. 그래도 안 되면 손을 들어 강사에게 알립니다.

    확인 OUTPUT의 body에 다섯 값이 보이면 성공입니다.
