F4 시험 체크리스트

AI Studio 앱 → n8n Webhook 호출이 되는가 · 기본 15분 + 추가 10분 · 강사용(수강생 배포 아님)

이 시험으로 정해지는 것

1일차 6교시부터 2일차까지 모든 "앱 → n8n 연결" 단계가 이 결과를 전제로 합니다. 시험하면서 이 페이지의 칸에 체크하고, 맨 아래 "대화에 붙여 넣을 결과"를 채워 Claude 세션에 붙여 넣으면 교안·fact-check에 반영합니다. 자세한 이유와 결과별 조치는 f4-test.md에 있습니다.

시험 중 지킬 것
  • 입력값은 가상 데이터만: 홍길동 / 010-1234-5678 / minwon@example.com / 생활 / 시험
  • 캡처할 때 본인 이메일, API 키, n8n 주소의 고유 부분(xxxx.app.n8n.cloud)은 가립니다.
  • n8n 설정 창 안의 Listen for test event는 누르지 않습니다(⑥ 덤 시험 때만). 대기는 늘 캔버스 아래 Execute workflow.

0. 준비물 (시작 전 5분)

  • 크롬 브라우저. 장소 기록: 집 / 사무실 / 교육장 PC
  • n8n Cloud 계정 로그인(수강생과 같은 무료 체험 계정이면 더 좋음)
  • 민원 접수 앱 — AI Studio Build에서 1일차 4교시 주문서로 만든 것. Code 탭에서 코드 맨 위에 WEBHOOK_URL = ""가 보이는지 확인
    없으면 주문서를 붙여 넣어 새로 만든다(약 3분). 이때 화면 글자가 한국어인지, 칸 5개인지도 메모(F76)
  • 시험용 워크플로우 파일 f4-test-workflow.json(노드 2개, 경로 f4-test, CORS *)
  • 메모할 곳(이 페이지 인쇄본 또는 메모장)

A. n8n 준비 (3분)

  1. 가져오기 Create workflow → 오른쪽 위 … → Import → From file → f4-test-workflow.json
    • 확인 노드 2개(앱에서 받기 → 앱에 답하기)가 선으로 이어져 보인다
    • 확인 메뉴 글자가 교안과 같다(Import / From file). 다르면 실제 글자:
  2. n8n 버전 적기 왼쪽 아래 Help → About n8n(또는 Settings). 버전: (못 찾으면 비워 둠)
  3. Test URL 복사 앱에서 받기를 두 번 눌러 열고, 위쪽에서 Test URL을 고른 뒤 주소를 한 번 누릅니다.
    • 확인 URL copied 알림이 뜬다(F60)
    • 확인 주소에 webhook-test/f4-test가 들어 있다
    • 확인 설정 창을 닫는 방법(창 바깥 누르기 / Back to canvas) 메모(F59):

B. 앱에 주소 넣기 (3분)

  1. 주소 넣기 요청 AI Studio 대화 입력창에 아래 문장을 붙여 넣고, 따옴표 안에 Test URL을 붙여 넣어 보냅니다. 
    코드 맨 위 WEBHOOK_URL 값을 "(복사한 Test URL)"로 바꿔 줘. 다른 부분은 바꾸지 마.
    • 확인 AI 수정이 끝난 뒤 Code 탭에서 WEBHOOK_URL에 붙여 넣은 주소가 그대로 있다
    • 확인 화면 배치·탭 이름 메모(F82): 대화창 위치 , 탭 이름
    • 확인 수정에 걸린 시간: 약 ○초
  2. 가상 값 미리 넣기 미리보기에 홍길동 / 010-1234-5678 / minwon@example.com / 생활 / 시험을 넣습니다. 아직 접수하기는 누르지 않습니다.

C. 시험 ① 미리보기 → Test URL (2분) ★ 핵심

  1. 대기 시작 n8n 탭에서 캔버스 아래 Execute workflow를 누릅니다. 여기서부터 2분 안에 다음 단계.
    • 확인 버튼 위치가 캔버스 아래이고, 누르면 기다리는 표시가 보인다. 표시 모양:
  2. 접수하기 AI Studio 탭으로 가서 접수하기를 누릅니다.
  3. 결과 보기
    • 성공이면 앱에 TEST-001과 "시험 성공 — 받은 이름: 홍길동 / origin: ○○○"이 보인다 → origin 값을 그대로 적기:
    • 실패면 앱에 뜬 글: → F12 → Console 탭의 빨간 글 첫 줄 복사. 글에 있는 말: □ CORS □ Content Security Policy □ blocked □ 기타
    • 어느 쪽이든 n8n 캔버스의 두 노드에 초록 표시가 생겼나? □ 예(= n8n까지 도착) □ 아니오
    • 가능하면 캡처: 앱에서 받기 출력의 headers.origin과 body(이름 등 다섯 값)
    • 확인 접수하기를 누르고 답이 올 때까지 걸린 시간: 약 ○초
    • (선택) 지금 E의 ⑥ 덤 시험을 하면 편합니다 — 아직 Publish 전이라 Test URL이 동작합니다
    이상할 때
    • 앱에 바로 실패가 뜨고 n8n에 초록 표시도 없다 → 2분이 지났거나 Execute workflow를 안 눌렀을 수 있음. 6~7을 한 번 더 해 보고, 그래도 같으면 그대로 기록
    • n8n은 초록인데 앱이 실패 → 브라우저가 응답을 막은 경우(CORS/CSP). 콘솔 글이 가장 중요한 기록

D. 시험 ② Production URL (3분)

  1. Publish n8n 위쪽 Publish → 확인 창에서 다시 Publish.
    • 확인 확인 창이 뜬다. 창 제목·버튼 글자:
    • 확인 게시 뒤 버튼 글자가 Published로 바뀐다(F61). 옆 표시 모양:
  2. Production URL로 바꾸기 앱에서 받기를 열어 Production URL을 고르고 주소를 누른 뒤(URL copied), 4단계 문장으로 앱의 WEBHOOK_URL을 바꿉니다.
    • 확인 주소가 /webhook/f4-test로 끝나고 test가 없다
  3. 접수하기 n8n에서 아무것도 누르지 않고 앱에서 접수하기.

    • 실패면 콘솔 빨간 글 첫 줄:

E. 추가 확인 (가능한 만큼, 각 2~3분)

  1. ③ 공유 링크 AI Studio 오른쪽 위 Share → 링크를 만들어 크롬 시크릿 창(Ctrl+Shift+N)에서 엽니다.
    • 확인 Share 창의 공개 범위 선택지 글자(F127):
    • 확인 시크릿 창에서 로그인을 요구하나? □ 예 □ 아니오
    • 열리면 접수하기 → □ 성공 □ 실패 · origin 값:
  2. ④ Allowed Origins를 좁혔을 때 앱에서 받기 → Allowed Origins (CORS)를 https://example.com으로 바꾸고 Publish → 앱에서 접수하기.
    • 확인 설정을 바꾸자 버튼이 다시 Publish로 바뀐다
    • 앱 결과 □ 실패(정상) □ 성공(이상 — 꼭 기록)
    • Executions에 실행이 남았나? □ 예 □ 아니오 (어느 쪽이든 정상, 기록만)
    • 끝나면 *로 되돌리고 다시 Publish
  3. ⑤ 서버 쪽 호출 우회 (① 또는 ②가 실패했을 때만) AI Studio에 아래 문장을 보내고 11단계를 다시 합니다. 
    n8n 주소 호출은 서버 쪽 코드에서 하도록 바꿔 줘. WEBHOOK_URL 값과 보내는 JSON의 키 이름은 바꾸지 마.
    • 결과 □ 성공 □ 실패 · origin 값(있으면):
  4. ⑥ 덤: 1일차 3교시 확인 (1분) 게시 중에는 Test URL이 등록되지 않을 수 있으므로, ① 직후(9단계 Publish 전)에 하거나 F의 Unpublish 뒤에 합니다. 앱에서 받기 설정 창 안의 Listen for test event를 누른 뒤 앱의 WEBHOOK_URL이 Test URL일 때 접수하기(또는 브라우저 주소창에 Test URL 입력).
    • 결과 □ 빈 응답·하얀 화면(교안 예상대로) □ 정상 응답(교안 수정 필요)
  5. ⑦ 덤: 같은 주소 두 번 게시 (2분, F62) 워크플로우 … → Duplicate로 복제한 뒤, 복제본도 Publish.
    • 확인 Duplicate 메뉴·이름 입력 창 모양(F203):
    • 두 번째 Publish 결과 □ 오류(문구: ) □ 그냥 됨
    • 복제본은 지운다

F. 정리 (1분)

  • Publish 오른쪽 작은 화살표 → 목록 맨 아래 Unpublish → 확인 창에서 다시 Unpublish. 확인 확인 창이 뜨는가(F225): □ 예 □ 아니오
  • ⑥을 아직 안 했다면 지금(게시 해제 상태에서) 합니다
  • 시험용 워크플로우는 지워도 됨. 민원 접수 앱의 WEBHOOK_URL은 그대로 두어도 됨(교안 실습 때 다시 바꿈)
  • 캡처 파일을 한 폴더에 모아 두기(경로를 결과에 적기)
