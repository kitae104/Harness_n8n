[1. 설명]
앱에서 민원을 접수하면 구글 시트에 접수번호(예: 2026-0922-001)와 함께 기록되고, 민원 종류별 담당자 메일 발송, 구글 캘린더 처리 마감 등록, 텔레그램 알림이 이어지며, Gemini가 쓴 안내문과 접수번호가 앱 화면에 표시됨. 접수번호로 처리 상태를 조회하는 화면까지 포함

[1. 실습 전 / 실습 후 그림 캡션]
실습 전: 기초과정의 n8n 폼 민원 접수 워크플로우(민원인이 쓸 앱 화면 없음)
실습 후: AI Studio로 만든 민원 접수 앱(입력 → 접수 완료 → 상태 조회) + 이를 처리하는 n8n 워크플로우(18개 노드)와 시트·메일·캘린더·텔레그램 결과

[2. 제목]
2. 나만의 업무 자동화 서비스 프로젝트 결과물 예시 — 현장점검 보고 앱

[2. 설명]
수강생(팀)별로 입력–처리–출력 설계서를 쓰고, 민원 접수 완성 파일을 고쳐 자신의 업무 서비스를 완성해 발표함. 예시: 점검장소·점검결과·특이사항·점검자를 앱에 입력 → 점검대장 시트 기록·접수번호 회신 → "보수필요"면 Gemini가 조치 요약을 써서 팀장 메일·텔레그램 부서 알림(자동화 전 수기 보고서 30분 → 현장에서 2분 입력). 기타 주제 예: 교육·행사 신청 접수, 회의록 정리, 부서 지침 Q&A

[2. 실습 전 / 실습 후 그림 캡션]
실습 전: 입력–처리–출력 설계서(현장점검 보고 앱)
실습 후: 완성된 현장점검 보고 앱 화면과 n8n 워크플로우

[3. 제목]
3. (선택 실습) 공문 요약·음성 접수 앱 결과물 예시

[1. 개요]
• 선행 과정(「AI를 활용한 나만의 비서 만들기(n8n)」 1·2기)에서 공무원들이 n8n으로 민원 접수·기록·알림 자동화를 경험하였으나, 수료 설문에서 현업도움 문항이 가장 낮았고(2.04), 수준별(초급→중급) 과정, 교육시간 확대, 실무 적용 사례, 앱 제작까지 이어지는 과정을 요청함
• 자동화 워크플로우만으로는 동료·민원인이 직접 쓸 수 있는 "입구(화면)"가 없어 부서 단위 확산이 어려움. 무료 AI 앱 빌더(Google AI Studio)는 프로그래밍 없이 문장만으로 앱 화면을 만들 수 있어, 비개발자도 "앱 + 자동화" 형태의 완성된 서비스를 구축할 수 있음
• 본 과정은 AI 앱 빌더로 업무용 화면을 만들고 n8n 자동화와 연동하여, 접수부터 기록·알림·회신·조회까지 이어지는 서비스를 수강생이 직접 완성하는 실습 중심 심화 과정임
• 입과 전 사전조사로 모은 수강생의 실제 업무를 프로젝트 주제로 삼아, 교육 종료 시 설계서·서비스·적용 로드맵을 가지고 돌아가는 것을 목표로 함

[2. 특징]
• "화면은 AI가, 일은 n8n이": 수강생은 코드를 쓰지 않고 한국어 문장으로 앱 화면을 만들며, 기록·발송·AI 생성은 선행 과정에서 배운 n8n 노드로 처리
• 교시별 웹 교안 16개와 인쇄 교재 제공: 교시마다 학습목표 → 개념 설명(10분) → 따라하기 → 확인 문제 → 정리 순서이며, 단계마다 성공 조건·자주 하는 실수·막혔을 때 대처를 안내
• 누적형 완성 파일: 교시 끝 상태의 워크플로우 JSON을 제공하여 진도가 밀린 수강생도 가져오기(Import)로 즉시 따라잡음(1일차 6교시 → 7교시 → 2일차 1교시 → 2교시로 이어지는 하나의 서비스)
• 강사가 검증한 AI Studio 프롬프트 템플릿 11종과 "오류 문구 복사 → AI에 수정 요청" 루틴으로 결과 편차를 줄임
• 2일차 오후 4시간(기획 1 + 제작 2 + 발표 1)을 개인·팀 프로젝트에 배정하고, 예시 완성본(현장점검 보고 앱)을 고쳐 쓰는 방식으로 현업 적용성 강화
• 실습은 가상 데이터만 사용하고, 공유·비밀값·개인정보 점검표와 부서 적용 로드맵까지 다루어 교육 후 안전한 실제 적용을 준비
• 무료 도구만 사용(유료 계정 불필요), 보조강사 1명 배치

(세부) ◦ 트리거–처리–결과 구조와 표현식 복습, 구글 시트·Gmail·Gemini 노드 재점검(완성본 가져오기) ◦ Webhook 개념(외부 앱이 n8n을 부르는 주소) 이해 ◦ Webhook·Respond to Webhook 노드, Test/Production URL과 Publish, Allowed Origins(CORS) 설정 실습

(교과목) 배포·보안·운영
(세부) ◦ 공유 링크 생성과 동료 상호 시험 ◦ API 키 등 비밀값 관리(AI Studio Secrets·n8n 자격 증명), 앱 코드 점검 ◦ 실행 기록에 남는 개인정보 확인, 개인정보·보안 점검표, 기관 설치형 n8n 전환 안내

(교과목) 나만의 업무 자동화 서비스 프로젝트
(세부) ◦ 사전조사 기반 부서별 시나리오 확정과 입력–처리–출력 설계서 작성 ◦ 설계서를 프롬프트로 옮겨 앱 생성 → 완성 파일 변형으로 워크플로우 구성 → 연동·테스트·오류 수정 ◦ 발표·상호 피드백, 부서 적용 로드맵 작성

(교과목) 파일·음성 기능 확장(선택 실습)

  - n8n의 "활성화(Active)" → 현재 버전 화면 이름인 "Publish"로 표기
  - 1일차 3교시 Webhook 시험은 브라우저 주소창 호출로 하고, CORS는 설정만 한 뒤 실제 확인은 6교시 앱 연결에서 함
  - 민원 종류는 기초과정과 같은 생활·음식물·대형, 담당자 분기는 "생활 / 그 외" 두 갈래
  - 텔레그램 알림은 2일차 2교시에서 조회 화면을 먼저 만든 뒤 시간이 남으면 하는 순서
  - 현장점검 예시에서 사진·위치 입력은 뺌(앱에서 파일 보내기는 선택 실습 PDF 방식을 참고하는 확장 과제로만 안내)
  - "업무 Q&A 응답 화면"은 별도 실습 없이 프로젝트 주제 예시로만 다룸
  - 기상청 API는 쓰지 않으므로 교육망 예외 목록에서 apis.data.go.kr를 뺌
  - AI Studio의 Publish(Cloud Run 게시)는 조건에 따라 결제 계정이 필요할 수 있어 소개만 하고, 실습은 무료 공유 링크(Share)로 함
