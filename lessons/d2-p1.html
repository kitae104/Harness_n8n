앱 ↔ n8n 연동 ②

접수와 동시에 담당자 메일, 캘린더 처리 마감, AI 안내문까지 — 앱 화면에는 안내문을 함께 돌려줍니다

강사 준비·확인이 교시에서 수업 전에 강사가 할 일입니다. 수강생용 내용이 아니며, 준비가 끝나면 python scripts/strip_inotes.py로 모두 지웁니다.
  • 교안 그대로 9:30까지 5단계, 20명 동시 접수 시 Gemini 429, 캘린더 동의 화면(F116)
  • 이 교안 안의 강사 확인 표시 3곳(노란 점선 상자)
  • 캡처 3장 촬영 → assets/img/에 넣고 python scripts/apply_captures.py
  • 확인이 끝나면 docs/instructor-checklist.md의 이 교시 행에 체크

학습목표

  • 접수된 민원을 담당자에게 Gmail로 보냅니다.
  • 처리 마감일을 구글 캘린더에 등록합니다.
  • Gemini로 민원인 안내문을 만들어 앱 화면에 함께 표시합니다.

왜 이 단계가 필요한가

어제는 앱에서 접수하면 시트에 적히고 접수번호가 돌아왔습니다. 하지만 담당자는 시트를 계속 들여다봐야 새 민원을 알 수 있고, 처리 기한도 따로 챙겨야 합니다. 오늘은 접수와 동시에 담당자에게 메일이 가고, 캘린더에 처리 마감이 잡히고, AI가 민원인 안내문 초안을 써서 앱 화면에 보여 주게 합니다. 기초과정 04~06강에서 만든 일을 이번에는 앱 접수에 붙이는 것입니다.

가지(위에서부터)하는 일결과가 보이는 곳
① AI 안내문 작성 → 앱에 답하기Gemini가 안내문을 쓰고, 접수번호와 함께 앱에 돌려줌앱 화면
② 담당자 메일담당자(실습에서는 나)에게 접수 알림내 Gmail
③ 처리 마감 일정3일 뒤에 처리 마감 일정 등록내 구글 캘린더

세 가지 모두 시트에 기록에서 부챗살처럼 갈라집니다. 한 줄로 이어 붙이면 노드를 지날 때마다 값이 그 노드의 결과로 바뀌어, 뒤 노드가 민원 내용을 잃어버리기 때문입니다(1일차 2교시 복습).

왜 AI 가지를 맨 위에 두나 n8n은 갈라진 가지를 캔버스 위쪽 가지부터 차례로 실행합니다. 앱에 답을 보내는 Respond to Webhook(부른 쪽에 답장을 보내는 노드)이 AI 가지 끝에 있으므로, AI 가지를 맨 위에 두면 앱이 가장 먼저 답을 받습니다. 메일이나 캘린더에 문제가 생겨도 앱 접수는 막히지 않습니다.
AI 안내문은 초안입니다 AI는 처리 기한·담당 부서·법령을 그럴듯하게 지어낼 수 있습니다. 실습에서는 화면에 보여 주기만 하고, 실제 운영에서는 담당자가 확인한 뒤 보냅니다.

따라하기

준비 n8n 첫 화면 목록에서 어제 마지막으로 Publish(워크플로우를 게시해 주소가 항상 동작하게 하는 것)한 워크플로우(노드가 여섯 개이고 앱에 답하기로 끝나는 것)를 엽니다. 없으면 1일차 7교시 완성본 가져오기로 먼저 맞춥니다.

시간 기준: 9시 30분까지 5단계(담당자 메일)를 못 마쳤으면 이 교시 끝 "완성본 가져오기"로 맞춥니다. 가져오기에서 캘린더 연결이 없으면 6단계처럼 새로 만들어야 하므로 5분쯤 더 걸립니다. 가져오기를 마치면 9단계부터 함께 합니다.

  1. 앱에 답하기 떼어 두기 시트에 기록과 앱에 답하기 사이 선에 마우스를 올리면 나오는 휴지통 모양을 눌러 선을 지웁니다. 앱에 답하기 노드는 지우지 말고 오른쪽 위 빈 곳으로 끌어 옮겨 둡니다.

    시트에 기록 오른쪽이 비고, 앱에 답하기가 따로 떨어져 있으면 성공입니다.

  2. AI 안내문 작성 추가하기
    1. 시트에 기록 오른쪽 +를 누르고, 노드 고르는 창의 검색 칸에 Basic LLM을 쳐서 Basic LLM Chain을 누릅니다.
    2. 설정 창 맨 위 이름을 한 번 눌러 AI 안내문 작성으로 고칩니다.
    3. Source for Prompt (User Message)(AI에게 줄 글을 어디서 가져올지 고르는 칸)를 Define below(아래에 직접 적기)로 바꿉니다.
    4. Prompt (User Message) 칸에 마우스를 올려 Expression을 누르고, 아래 글을 붙여 넣습니다.
    당신은 친절한 시청 민원 담당 공무원입니다.
아래 민원 접수 내용을 바탕으로, 민원인에게 보낼 정중한 '접수 확인 안내문'을 작성해 주세요.

[작성 규칙]
- 존댓말을 사용하고, 4~6문장으로 작성합니다.
- 접수번호를 안내문에 꼭 넣습니다.
- 민원이 정상적으로 접수되었음을 안내합니다.
- 처리에는 다소 시간이 걸릴 수 있음을 부드럽게 안내합니다.
- 처리 기한·담당 부서·법령은 지어내지 않습니다.
- 마지막은 '감사합니다.'로 끝맺습니다.

[민원 접수 내용]
- 접수번호: {{ $json.접수번호 }}
- 접수자명: {{ $json.이름 }}
- 민원 종류: {{ $json.종류 }}
- 상세 설명: {{ $json.상세설명 }}
    이 글은 AI에게 주는 프롬프트(AI에게 시키는 일을 적은 문장)입니다. 기초과정 06강 글에 접수번호 줄과 "지어내지 않습니다" 규칙을 더했습니다.

    칸에 글이 들어가고 fx 표시가 보이면 성공입니다. 창을 닫고, 노드를 캔버스 위쪽으로 끌어 옮겨 둡니다(가지 순서를 위해).

  3. Gemini 모델 붙이기 AI 안내문 작성 아래 Model 자리의 +를 누르고 Google Gemini Chat Model을 고릅니다. Credential은 1일차 2교시에 만든 Gemini 자격 증명(n8n이 내 계정을 대신 쓰도록 맡겨 둔 열쇠)을 목록에서 고릅니다. 이 자격 증명에는 API 키(Gemini를 쓸 수 있게 해 주는 비밀 번호표)가 들어 있습니다. Model은 models/gemini-3.8-flash를 고릅니다(목록에 없으면 models/gemini-3.5-flash-lite). 강사 확인 F42새 API 키 계정의 Gemini Model 목록에 models/gemini-3.8-flash가 있고 실행되는지. 없으면 교안 모델 이름을 바꿔야 함

    AI 안내문 작성 아래에 작은 동그라미 Google Gemini Chat Model이 붙으면 성공입니다.

  4. 앱에 답하기 다시 잇고 답장 바꾸기 AI 안내문 작성의 오른쪽 점에서 앱에 답하기의 왼쪽 점으로 끌어 선을 잇습니다. 앱에 답하기를 열어 Response Body 칸을 누르고 Ctrl+A, Delete로 글을 모두 지웁니다(칸 왼쪽 fx 표시는 그대로 둡니다). 아래 상자 안 글을 마우스로 빠르게 세 번 눌러 한 줄 전체를 고른 뒤 Ctrl+C, 칸에 Ctrl+V로 붙여 넣습니다. 인쇄본은 줄이 잘려 보이므로 웹 교안에서 복사합니다. 
    {{ { "접수번호": $('시트에 기록').first().json.접수번호, "메시지": "접수되었습니다", "안내문": $json.text } }}
    AI 안내문에는 줄바꿈과 따옴표가 들어 있어서, 어제처럼 "{{ }}" 안에 넣으면 답장이 깨집니다. 그래서 답장 전체를 이렇게 한 덩어리 표현식({{ }} 안에 써서 값을 가져오는 문장)으로 씁니다. $json.text는 AI가 쓴 글입니다.

    시트에 기록 → AI 안내문 작성 → 앱에 답하기로 이어지면 성공입니다.

  5. 담당자 메일 추가하기 시트에 기록 오른쪽의 작은 동그란 점을 마우스로 누른 채 오른쪽 아래 빈 곳으로 끌었다가 놓습니다. 노드 고르는 창이 열리면 검색 칸에 Gmail을 치고 메일 보내기(Send a message)를 고릅니다(점 옆에 +가 보이면 그것을 눌러도 됩니다). 강사 확인 F200연결된 출력 점을 끌어 빈 곳에 놓으면 새 가지가 생기는지, Gmail 동작 이름 Send a message 이름을 담당자 메일로 고칩니다.
    • Credential: 1일차 2교시에 만든 Gmail 자격 증명
    • To: {본인 이메일} — 내 Gmail 주소를 글자 그대로 적습니다(실습에서는 내가 담당자입니다)
    • Subject: 마우스를 올려 Expression을 누르고 [{{ $json.종류 }}] 민원 접수 {{ $json.접수번호 }}
    • Email Type: Text
    • Message: 마우스를 올려 Expression을 누르고 아래 글을 붙여 넣기
    • 설정 창을 맨 아래까지 내려 Add option → Append n8n Attribution을 고르고 끄기
    담당자님께,

아래와 같이 민원이 접수되었습니다.

- 접수번호: {{ $json.접수번호 }}
- 접수자명: {{ $json.이름 }}
- 연락처: {{ $json.연락처 }}
- 민원 종류: {{ $json.종류 }}
- 상세 설명: {{ $json.상세설명 }}
- 등록일: {{ $json.등록일 }}

처리 마감은 접수일로부터 3일입니다. 캘린더 일정을 확인해 주세요.

    To에 내 주소, Subject·Message에 fx 표시, Email Type이 Text면 성공입니다.

    자주 하는 실수

    증상 메일이 오지 않거나 The email address '…' in the 'To' field isn't valid가 떠요
    원인 To에 {{ $json.이메일 }}을 넣었어요. 앱에서 온 이메일은 가상 주소(minwon@example.com)이거나 비어 있을 수 있어요
    해결 To에는 내 Gmail 주소를 글자 그대로 적으세요

  6. 처리 마감 일정 추가하고 캘린더 연결하기 5단계처럼 시트에 기록의 점에서 아래쪽 빈 곳으로 끌어 노드 고르는 창을 열고, Google Calendar를 검색해 일정 만들기(Create an event)를 고릅니다. 이름을 처리 마감 일정으로 고칩니다.

    캘린더용 자격 증명은 이 교시에서 새로 만드는 유일한 것입니다.

    1. Credential 칸 목록에서 Create new credential을 누릅니다.
    2. 열린 창에서 Sign in with Google을 누릅니다.
    3. 새로 뜬 구글 창에서 시트·메일 때와 같은 계정을 고르고, 권한을 묻는 화면에서 허용 버튼을 누릅니다. 강사 확인 F116캘린더 Sign in with Google 권한 동의 화면, 캘린더 목록 이름, 3일 뒤 일정이 한국 시각인지
    4. n8n 창에 연결되었다는 표시(Account connected)가 보이면 X로 닫습니다.

    Credential 칸에 새 캘린더 자격 증명 이름이 보이면 성공입니다.

    자주 하는 실수

    증상 구글 창이 뜨지 않아요
    원인 브라우저가 새 창(팝업)을 막았어요
    해결 주소창 오른쪽의 막힘 표시를 눌러 "항상 허용"을 고른 뒤 다시 누르세요

  7. 처리 마감 일정 설정하기
    • Calendar: 칸 왼쪽 목록을 목록에서 고르기로 두고, 오른쪽 목록에서 내 캘린더(보통 내 이메일 주소 이름)를 고릅니다
    • Start: 마우스를 올려 Expression을 누르고 아래 첫 줄
    • End: 같은 방법으로 아래 둘째 줄
    • Additional Fields → Add Field → Summary: Expression으로 아래 셋째 줄
    {{ $now.plus(3,'days').toISO() }}
    {{ $now.plus(3,'days').plus(1,'hour').toISO() }}
    민원 처리 마감 - {{ $json.접수번호 }} {{ $json.이름 }}

    Calendar에 내 캘린더 이름이 보이고, Start·End·Summary에 fx 표시가 있으면 성공입니다.

    자주 하는 실수

    증상 Calendar parameter's value is invalid가 떠요
    원인 Calendar 칸에 글자를 직접 적었어요(ID로 적기)
    해결 칸 왼쪽 목록을 목록에서 고르기로 바꾸고, 오른쪽 목록에서 내 캘린더를 고르세요

  8. 가지 순서 확인하고 Publish하기 캔버스에서 세 가지가 위에서부터 ① AI 안내문 작성(→ 앱에 답하기) ② 담당자 메일 ③ 처리 마감 일정 순서인지 봅니다. 아니면 노드를 끌어 위아래를 맞춥니다.

    순서가 맞으면 위쪽 Publish → 확인 창의 Publish를 누릅니다. 확인 창이 닫히고 버튼이 게시된 모양(1일차 3교시 [그림 1-3-8])이면 성공입니다.

  9. 앱에 안내문 칸 만들기 AI Studio(aistudio.google.com/apps) 왼쪽 메뉴의 Apps를 누르고, 어제 만든 민원 접수 앱을 누릅니다(목록 맨 위, 이름은 영어일 수 있습니다). 오른쪽 미리보기에 민원 접수 화면이 보이면, 대화 입력창에 아래 글을 붙여 넣고 보냅니다. 
    n8n이 이제 {"접수번호": "...", "메시지": "...", "안내문": "..."} 모양의 JSON을 돌려줘. 접수 완료 화면에서 "메시지" 아래에 "안내문"을 여러 줄 그대로(줄바꿈 유지) 보여 줘. 안내문이 없거나 비어 있으면 그 칸은 보이지 않게 해 줘. 입력 칸 이름과 WEBHOOK_URL은 바꾸지 마.

    AI의 답이 끝나고 미리보기가 다시 나타나면 성공입니다. 앱 주소(WEBHOOK_URL)는 바꾸지 않습니다.

  10. 접수하고 세 곳 확인하기
    개인정보 주의 아래 가상 값만 넣습니다. 이번에는 입력한 이름과 상세 설명이 Gemini(구글 AI)로 보내지고, 연락처는 메일로 전달됩니다. 실제 민원인의 이름·연락처·민원 내용은 실습에 넣지 않습니다.
    앱에서 새 민원 접수로 돌아가 가상 민원(이접수 / 010-0000-0005 / minwon@example.com / 대형 / 아파트 앞에 버려진 소파 수거를 요청합니다.)을 넣고 동의에 체크한 뒤 접수하기를 누릅니다. 안내문을 만드느라 10초쯤 걸릴 수 있습니다. 기다리는 동안 앱이 멈춘 것처럼 보이면, 시간이 남을 때 프롬프트 파일의 "기다리는 동안 안내" 문장을 AI Studio에 보내도 됩니다(선택).
    • 앱 화면: 접수번호와 AI 안내문이 보이나요?
    • 내 Gmail(스팸함 포함): 제목이 [대형] 민원 접수 …인 메일이 왔나요?
    • 구글 캘린더: 3일 뒤에 민원 처리 마감 - … 일정이 생겼나요?

    세 곳이 모두 확인되면 성공입니다.

    자주 하는 실수

    증상 앱에 접수번호만 나오고 안내문이 없으며, 메일과 캘린더 일정도 없어요
    원인 노드를 고친 뒤 Publish를 다시 누르지 않아 어제 모습 그대로 동작해요
    해결 화면 위쪽 Publish → 확인 창의 Publish를 누르고 다시 접수하세요

    증상 메일이나 안내문에 접수번호·등록일이 비어 있어요
    원인 노드 이름이 시트에 기록과 한 글자라도 다르거나, 표현식이 잘려 붙었어요
    해결 n8n 위쪽 Executions에서 방금 실행을 열어 시트에 기록의 결과에 접수번호가 있는지 봅니다

    증상 앱에 오류가 떴는데 시트에는 줄이 생겼어요
    원인 앱이 답을 기다리다 지쳤을 수 있어요(n8n Cloud는 100초 넘게 답이 없으면 끊습니다). 접수 자체는 처리되었을 수 있어요
    해결 먼저 시트·메일·캘린더를 확인하세요. n8n Executions에서 AI 안내문 작성이 오래 걸렸거나 빨간지 봅니다

    증상 앱에 접수번호는 보이는데 안내문이 없어요
    원인 앱이 안내문 칸을 만들지 않았거나, 답장 한 줄(4단계)이 예전 것 그대로예요
    해결 4단계의 답장 한 줄을 다시 붙여 넣고 Publish한 뒤, 9단계 요청을 한 번 더 보내세요

    증상 AI 안내문 작성이 빨갛고 사용량 초과(quota) 같은 글이 보여요
    원인 Gemini 무료 사용량을 넘었어요. 이 가지가 맨 위라, 여기서 멈추면 앱에도 실패가 뜨고 메일·캘린더도 오지 않아요
    해결 Model을 models/gemini-3.5-flash-lite로 바꾸고 다시 Publish하세요

완성본 가져오기(Import)

이 파일을 가져오면 n8n 쪽이 이 교시 끝 상태(열 개 노드)가 됩니다. 앱은 따라하기 9단계 요청만 하면 됩니다.

먼저: 어제 워크플로우를 Unpublish하세요 어제 Publish한 워크플로우는 지금도 게시 중입니다. n8n 첫 화면에서 그 워크플로우를 열어 Publish 오른쪽 작은 화살표를 눌러 목록 맨 아래 Unpublish를 누르고, 뜨는 창에서 다시 Unpublish를 누릅니다. 같은 주소 끝부분(minwon)과 같은 방식(POST)을 쓰는 Webhook은 하나만 동작할 수 있습니다.
  1. 파일 내려받기 워크플로우 내려받기 d2-p1.json
  2. n8n에서 가져오기 Create workflow → 오른쪽 위 … → Import → From file을 누르고 내려받은 d2-p1.json을 고릅니다. 캔버스에 노드 열 개가 보이면 성공입니다. 시간대(서울)는 파일에 들어 있습니다.
  3. 자격 증명 다시 연결하기 아래 다섯 노드를 차례로 열어 Credential 칸에서 내 자격 증명을 고릅니다.
    • 오늘 접수 조회, 시트에 기록 — 구글 시트용
    • Google Gemini Chat Model — Gemini API 키
    • 담당자 메일 — Gmail용
    • 처리 마감 일정 — 캘린더용(없으면 6단계처럼 새로 만듭니다)
  4. 자리표시자 바꾸기
    • 오늘 접수 조회·시트에 기록의 Document: 왼쪽 목록을 From list로 바꾸고 민원대장 연습(여기에_본인_시트_ID 대신), Sheet: 내 탭 이름
    • 담당자 메일의 To: 본인이메일@example.com → 내 Gmail 주소
    • 처리 마감 일정의 Calendar: 목록에서 내 캘린더
    • Google Gemini Chat Model의 Model: models/gemini-3.8-flash 다시 고르기
  5. Publish하고 접수해 보기 Publish → 확인 창의 Publish를 누릅니다. 앱의 WEBHOOK_URL은 어제 넣은 Production URL(워크플로우를 게시한 뒤 앱에 넣는 진짜 주소) 그대로 둡니다. 앱에서 오류가 나면 민원 받기를 열어 Production URL을 복사해 앱에 다시 넣습니다(1일차 6교시 9단계). 그다음 따라하기 9단계 요청을 보내고 10단계처럼 접수해, 접수번호와 안내문이 보이면 복구 완료입니다.
