Webhook 이해와 실습

앱과 자동화가 대화하는 방법 — n8n에 "부르면 답하는 주소"를 만듭니다

강사 준비·확인이 교시에서 수업 전에 강사가 할 일입니다. 수강생용 내용이 아니며, 준비가 끝나면 python scripts/strip_inotes.py로 모두 지웁니다.
  • 교안 그대로 따라 하기: 캔버스 Execute workflow → 주소창 호출 → 인사말 확인(F223), 설정 창 Listen for test event로는 빈 화면인지
  • 이 교안 안의 강사 확인 표시 4곳(노란 점선 상자)
  • 캡처 9장 촬영 → assets/img/에 넣고 python scripts/apply_captures.py
  • 확인이 끝나면 docs/instructor-checklist.md의 이 교시 행에 체크

학습목표

  • Webhook을 "외부 앱이 n8n을 부르는 주소"로 설명할 수 있습니다.
  • Test URL로 시험하고, Publish한 뒤 Production URL을 쓰는 순서를 압니다.
  • Respond to Webhook 노드로 답을 돌려주고 브라우저 주소창으로 확인하며, Allowed Origins(CORS)를 미리 설정해 둡니다(실제 확인은 6교시).

왜 이 단계가 필요한가

기초과정에서는 n8n이 만들어 준 입력 폼으로 민원을 받았습니다. 오늘 오후에는 우리가 직접 만든 앱 화면에서 민원을 보냅니다. 그러려면 앱이 n8n을 찾아와 문을 두드릴 수 있는 주소가 있어야 합니다. 그 주소가 Webhook(외부 앱이 n8n을 부르는 주소)입니다.

민원실에 비유하면 다음과 같습니다.

민원실오늘 배우는 것하는 일
민원실 입구의 초인종Webhook 주소누군가 누르면 n8n이 일을 시작합니다
창구 직원워크플로우받은 내용을 기록하고, 메일을 보내고, 안내문을 씁니다
접수증 건네기Respond to Webhook(부른 쪽에 "잘 받았어요"라고 답장을 보내는 노드)앱 화면에 접수번호 같은 답을 돌려줍니다
출입 허락 명단CORS(다른 주소의 앱이 n8n을 불러도 되는지 정하는 허락 규칙)브라우저가 "이 앱이 불러도 되나?"를 확인합니다

Webhook 주소는 두 개가 있습니다.

  • Test URL(만드는 중에 시험할 때 쓰는 주소) — 시험 버튼을 누르고 기다리는 동안 한 번만 동작합니다.
  • Production URL(워크플로우를 게시한 뒤 앱에 넣는 진짜 주소) — 화면 위쪽 Publish(워크플로우를 게시해 주소가 항상 동작하게 하는 버튼)를 누른 뒤부터 언제든 동작합니다.
한 문장 요약 만들 때는 Test URL로 시험하고, 다 만들면 Publish한 뒤 Production URL을 앱에 넣습니다. 이 순서만 지키면 "앱에서 눌렀는데 아무 일도 안 일어나요"의 대부분이 사라집니다.
CORS는 오늘 "설정만" 합니다 CORS 검사는 앱 화면이 n8n을 부를 때 브라우저가 합니다. 오늘은 주소창에 주소를 붙여 넣어 부르기 때문에 이 검사를 받지 않습니다. 그래서 오늘은 허락 명단을 미리 적어 두기만 하고, 실제로 효과를 확인하는 것은 6교시에 앱과 연결할 때 합니다.

따라하기

이름을 넣어 부르면 "안녕하세요, 홍길동님"이라고 답하는 작은 워크플로우를 만듭니다. 오후에 만들 민원 접수의 뼈대입니다.

  1. 새 워크플로우 만들기 n8n 첫 화면에서 Create workflow를 누릅니다.

    가운데에 +가 있는 빈 캔버스가 보이면 성공입니다.

  2. Webhook 노드 추가하기 캔버스 가운데의 +를 누르고 검색창에 Webhook을 입력합니다. 목록에 Respond to Webhook도 보이지만, 이름이 딱 Webhook인 것을 고릅니다. 강사 확인 F55노드 검색 칸에 Webhook을 쳤을 때 나오는 항목 표기

    Webhook 설정 창이 열리면 성공입니다.

  3. 받는 방식과 주소 끝부분 정하기 HTTP Method가 GET인지 확인합니다. Path 칸의 글자를 모두 지우고 hello를 입력합니다. 강사 확인 F56Webhook HTTP Method 기본값이 GET인지, Path 칸 표기 GET은 브라우저 주소창에 주소를 넣어 부르는 방식입니다. 오후에 앱이 민원을 보낼 때는 POST라는 다른 방식을 씁니다. Path는 주소의 맨 끝부분이며, 알아보기 쉬운 영어 단어로 정합니다.

    설정 창 위쪽 주소가 …/hello로 끝나면 성공입니다.

  4. 답장 방식 바꾸기 Respond를 Using 'Respond to Webhook' Node로 바꿉니다.

    Respond 칸에 Using 'Respond to Webhook' Node가 보이면 성공입니다.

    자주 하는 실수

    증상 우리가 쓴 인사말 대신 {"message":"Workflow was started"}만 보여요
    원인 Respond가 기본값 Immediately로 남아 있어요
    해결 Using 'Respond to Webhook' Node로 바꾸세요

  5. CORS 허락 명단 미리 적기 (체크리스트 1번) 설정 창 아래 Add option을 누르고 Allowed Origins (CORS)를 고릅니다. 칸에 *가 들어 있는지 봅니다. 비어 있으면 *를 입력합니다. *는 "어느 주소의 앱이든 불러도 좋다"는 뜻입니다. 실습에서는 이 값을 씁니다. 실제 부서에 적용할 때의 안전 설정은 2일차 3교시 점검표에서 다룹니다.

    Allowed Origins (CORS) 칸에 *가 보이면 성공입니다. 설정 창 바깥의 빈 곳을 누르거나 창을 닫아 캔버스로 돌아갑니다. Webhook 노드 하나가 보이면 됩니다. 강사 확인 F59설정 창을 닫고 캔버스로 돌아가는 방법(창 바깥 누르기 / Back to canvas) 표기

  6. Respond to Webhook 노드 붙이기 Webhook 노드 오른쪽의 +를 누르고 Respond to Webhook을 검색해 고릅니다.

    두 노드가 선으로 이어지고 Respond to Webhook 설정 창이 열리면 성공입니다.

  7. 답장 글 넣기 Respond With를 JSON으로 바꿉니다. Response Body 글자 근처에 마우스를 올리면 Fixed와 Expression이 나타납니다. Expression을 누릅니다. 칸 안을 누르고 Ctrl+A로 이미 들어 있는 글자를 모두 고른 뒤 Delete로 지웁니다. 칸이 비었으면 아래 글을 복사해 붙여 넣습니다. 
    {
  "메시지": "안녕하세요, {{ $json.query.이름 }}님. 잘 받았습니다."
}

    {{ $json.query.이름 }}는 기초과정에서 배운 표현식(앞 노드의 값을 가져다 쓰는 문장)입니다. 다음 단계에서 주소 끝에 붙여 보낼 이름 값을 꺼내 옵니다.

    칸 아래 미리보기에서 이름 자리가 비어 보여도 괜찮습니다. 아직 이름을 보내지 않았기 때문이며, 다음 단계에서 채워집니다.

  8. Test URL로 시험하기 시간 제한이 있으므로 아래 순서대로 준비한 다음 시험합니다.
    1. Webhook 노드를 열고 위쪽에서 Test URL을 고른 뒤 아래 주소를 한 번 누릅니다. URL copied 알림이 뜨면 복사된 것입니다. 설정 창을 닫습니다.
    2. 브라우저에서 새 탭을 열고, 주소창에 복사한 주소를 붙여 넣은 뒤 끝에 ?이름=홍길동을 이어서 씁니다. 아직 Enter는 누르지 않습니다.
    3. n8n 탭으로 돌아와 캔버스 아래 Execute workflow를 누릅니다. 설정 창 안의 Listen for test event는 누르지 않습니다(그 버튼은 Webhook 노드만 실행해서 답장이 오지 않습니다).
    4. 2분 안에 새 탭으로 가서 Enter를 누릅니다.
    https://(내 n8n 주소)/webhook-test/hello?이름=홍길동
    위 주소는 모양을 보여 주는 예입니다. 직접 치지 말고 n8n에서 복사한 주소를 쓰세요. 주소 끝의 ?이름=홍길동은 "이름은 홍길동"이라는 값을 n8n에 함께 보내는 부분입니다. ?와 =는 영어 자판으로 입력하고 띄어 쓰지 않습니다. 이름 자리에는 본인 실명 대신 홍길동·김민원 같은 가상 이름만 넣습니다. 보낸 값은 실행 기록에 남습니다.

    브라우저 화면에 "안녕하세요, 홍길동님. 잘 받았습니다."라는 글이 보이면 성공입니다(앞뒤 기호 모양은 조금 달라도 됩니다). n8n 캔버스의 두 노드에도 초록색 표시가 생깁니다.

    자주 하는 실수

    증상 The requested webhook "…" is not registered.라는 글이 보여요
    원인 Execute workflow를 누르지 않았거나, 누른 뒤 2분이 지났거나, 이미 한 번 불렀어요(Test URL은 한 번만 동작)
    해결 캔버스 아래 Execute workflow를 다시 누르고 곧바로 새 탭에서 Enter를 누르세요

    증상 브라우저 화면이 아무 글자 없이 하얗게 나와요
    원인 설정 창 안의 Listen for test event를 눌렀어요. 이 버튼은 Webhook 노드만 실행해서 Respond to Webhook이 답장을 만들지 못해요
    해결 설정 창을 닫고 캔버스 아래 Execute workflow를 누른 뒤 다시 부르세요

    증상 "안녕하세요, 님."처럼 이름이 빠져 있어요
    원인 주소 끝의 이름과 표현식 $json.query.이름의 글자가 서로 달라요(예: ?이룸=)
    해결 두 곳 모두 "이름" 두 글자로 똑같이 맞추고, Execute workflow를 다시 누른 뒤 부르세요

  9. Publish하기 화면 위쪽의 Publish를 누르고, 뜨는 창에서 다시 Publish를 누릅니다.

    확인 창이 닫히고 위쪽 버튼 글자가 Published로 바뀌면 성공입니다([그림 1-3-8]).

    설정을 바꾸면 다시 Publish Publish한 뒤에 설정을 고치면, Production URL은 다시 Publish할 때까지 예전 설정으로 동작합니다. "고쳤는데 그대로예요"라고 느껴지면 Publish부터 다시 누르세요.
  10. Production URL로 시험하기 Webhook 노드를 열고 위쪽에서 Production URL을 골라 주소를 복사합니다. 새 탭 주소창에 붙여 넣고 끝에 ?이름=김민원을 붙여 Enter를 누릅니다. 이번에는 기다리는 버튼을 누르지 않아도 되고, 시간 제한도 없습니다. 
    https://(내 n8n 주소)/webhook/hello?이름=김민원

    "안녕하세요, 김민원님"이 보이면 성공입니다. 실행 기록은 캔버스가 아니라 위쪽 Executions 탭에 남습니다.

    자주 하는 실수

    증상 오후에 앱에 주소를 넣었는데 가끔만 동작하거나 전혀 동작하지 않아요
    원인 앱에 Test URL을 넣었어요. 주소 안에 webhook-test가 있으면 Test URL입니다
    해결 앱에는 항상 /webhook/으로 된 Production URL을 넣으세요

    증상 This webhook is not registered for GET requests. Did you mean to make a POST request?가 보여요
    원인 이 Webhook의 HTTP Method가 POST예요. 주소창은 GET 방식으로만 부를 수 있어요
    해결 오늘 실습에서는 GET으로 바꾸고 다시 Publish하세요. POST는 6교시에 앱이 보냅니다

Webhook 실습 체크리스트

오후에 앱과 연결할 때도 이 순서로 확인합니다.

  1. Allowed Origins (CORS)를 적었나요? (실습 값 *)
  2. Respond가 Using 'Respond to Webhook' Node인가요?
  3. Respond to Webhook 노드가 Webhook 노드와 선으로 이어져 있나요?
  4. 시험은 Test URL, 앱에는 Production URL(/webhook/)을 넣었나요?
  5. Publish했나요? 설정을 고친 뒤 다시 Publish했나요?

확인 문제

객관식Q1. 오후에 만든 앱 화면에 넣어야 하는 주소는?

  1. 주소 안에 webhook-test가 있는 Test URL
  2. Publish한 뒤의 Production URL
  3. n8n 로그인 화면 주소
  4. 구글 시트 주소
정답 확인

정답: ② Test URL은 시험 버튼을 누른 동안 한 번만 동작합니다. 앱에는 Publish한 뒤 언제든 동작하는 Production URL을 넣습니다.

객관식Q2. 인사말 대신 Workflow was started만 보일 때 먼저 확인할 곳은?

  1. Webhook 노드의 Respond 설정
  2. 브라우저 글자 크기
  3. 구글 계정 로그인
  4. Path 글자 수
정답 확인

정답: ① Respond가 Using 'Respond to Webhook' Node여야 우리가 쓴 답장이 돌아갑니다.

단답형Q3. Publish한 뒤 Allowed Origins 값을 바꿨습니다. Production URL에 반영하려면 무엇을 해야 할까요?

정답 확인

정답: 다시 Publish를 누릅니다.

정리

  • Webhook은 외부 앱이 n8n을 부르는 주소이고, Respond to Webhook은 부른 쪽에 답장을 보냅니다.
  • 만들 때는 Test URL로 시험하고, Publish한 뒤에는 Production URL을 씁니다. 설정을 고치면 다시 Publish합니다.
  • CORS 허락 명단(Allowed Origins (CORS))은 오늘 미리 적어 두었습니다.
  • 다음: 4교시에는 이 주소를 부를 앱 화면을 만들고, 6교시에 둘을 연결하면서 CORS를 직접 확인합니다.

완성본 가져오기(Import)

따라오다 막혔다면 이 파일을 받아 내 n8n에 가져오면 이 교시 끝 상태에서 이어 갈 수 있습니다.

먼저: 따라 만들던 워크플로우를 Publish했다면 그 워크플로우의 Publish 오른쪽 작은 화살표를 눌러 목록 맨 아래 Unpublish를 누르고, 뜨는 창에서 다시 Unpublish를 누르세요. 같은 주소 끝부분(hello)과 같은 방식(GET)을 쓰는 Webhook은 하나만 동작할 수 있습니다. 강사 확인 F62같은 경로 Webhook이 게시된 상태에서 두 번째 워크플로우를 Publish할 때 나오는 오류 문구(Unpublish 안내의 근거)
  1. 파일 내려받기 워크플로우 내려받기 d1-p3.json
  2. n8n에서 가져오기 새 워크플로우 화면 오른쪽 위 … → Import → From file을 누르고 내려받은 파일을 고릅니다. 파일 내용을 복사해 빈 캔버스에 Ctrl+V로 붙여 넣어도 됩니다.
  3. 자격 증명 확인하기 이 연습 워크플로우에는 자격 증명(n8n이 내 구글·텔레그램 계정을 대신 쓰도록 맡겨 둔 열쇠)이 필요한 노드가 없어서 다시 연결할 것이 없습니다. 다른 교시에서는 이 단계에서 경고 표시가 뜬 노드를 열어 내 자격 증명을 고릅니다.
  4. Publish하고 시험하기 화면 위쪽 Publish를 누르고, 뜨는 창에서 다시 Publish를 누릅니다. Webhook 노드를 열어 위쪽에서 Production URL을 골라 주소를 복사합니다. 새 탭 주소창에 붙여 넣고 끝에 ?이름=홍길동을 붙여 Enter를 누릅니다. 인사말이 보이면 복구 완료입니다.
