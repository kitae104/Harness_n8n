학습목표

왜 이 단계가 필요한가

지금 앱은 접수를 보내기만 하고, 민원인은 "정말 접수됐나?" 알 수 없습니다. 민원실 창구라면 접수증을 건네는 순간입니다. 이번 시간에는 n8n이 접수번호를 만들어 시트에 함께 적고, 그 번호를 앱에 돌려주어 화면에 보이게 합니다. 답장을 보내는 노드가 3교시에 써 본 Respond to Webhook(부른 쪽에 "잘 받았어요"라고 답장을 보내는 노드)입니다.

접수번호뜻
2026연도
0925월일(9월 25일)
003그날 몇 번째 접수인지(001부터)

"그날 몇 번째"를 알려면 시트를 먼저 읽어 오늘 날짜로 시작하는 접수번호가 몇 개인지 세고, 거기에 1을 더합니다. 그래서 노드가 둘 늘어납니다.

노드하는 일
민원 받기 → 민원 정리6교시와 같음
오늘 접수 조회 (새로)시트의 줄을 모두 읽어 옵니다
접수번호 만들기 (새로)오늘 번호를 센 뒤 새 번호와 처리상태(접수)를 붙입니다
시트에 기록접수번호·처리상태 칸까지 함께 적습니다

한 문장 요약 접수번호는 "오늘 몇 번째인가"를 시트에서 세어 만들고, Respond to Webhook이 그 번호를 앱에 돌려주어 민원인이 접수증을 받게 됩니다.

노드를 고친 뒤에는 Publish(워크플로우를 게시해 주소가 항상 동작하게 하는 버튼)를 다시 눌러야, 앱이 쓰는 Production URL(워크플로우를 게시한 뒤 앱에 넣는 진짜 주소)에 고친 내용이 반영됩니다.

따라하기

준비 6교시 워크플로우(민원 받기 → 민원 정리 → 시트에 기록)를 엽니다. 6교시를 못 마쳤으면 6교시 완성본 가져오기로 먼저 맞춥니다.

시간 기준: 16시 30분까지 5단계를 못 마쳤으면 이 교시 끝 "완성본 가져오기"로 맞추고 10단계(앱에서 접수)부터 함께 합니다.

이번 교시에 바꾸는 설정 여섯 곳 (점검표)
  1. 워크플로우 Timezone = 서울 (1단계)
  2. 오늘 접수 조회 → Settings → Always Output Data 켜기 (4단계)
  3. 접수번호 만들기 → Settings → Execute Once 켜기 (5단계)
  4. 시트에 기록 → Cell Format (6단계)
  5. 민원 받기 → Respond = Using 'Respond to Webhook' Node (8단계)
  6. 마지막에 다시 Publish (9단계)
10단계에서 번호가 안 보이면 이 여섯 곳부터 다시 봅니다.
  1. 워크플로우 시간대를 서울로 맞추기 캔버스 오른쪽 위 … → Settings를 누르고 Timezone 목록에서 서울(Asia/Seoul)을 고른 뒤 저장 버튼을 누릅니다. 강사 확인 F100워크플로우 시간대 설정 화면(Settings → Timezone) 표기와 위치 이 설정이 없으면 n8n이 미국 시간을 써서, 오전에는 날짜가 하루 전으로 찍힙니다.

    Timezone에 서울이 보이면 성공입니다.

  2. 시트에 머리글 두 칸 더하기 구글 시트 민원대장 연습의 G1 칸에 접수번호, H1 칸에 처리상태를 입력합니다(띄어 쓰지 않습니다).

    1행이 이름~처리상태 여덟 칸이면 성공입니다.

  3. 오늘 접수 조회 끼워 넣기 n8n 캔버스에서 민원 정리와 시트에 기록 사이의 선에 마우스를 올리면 나오는 +를 누르고 Google Sheets를 고른 뒤, 동작 목록에서 행을 읽는 Get Row(s)를 고릅니다.
    • Credential: 2교시에 만든 구글 시트 자격 증명(n8n이 내 구글 계정을 대신 쓰도록 맡겨 둔 열쇠)
    • Document: From list에서 민원대장 연습, Sheet: 시트1(내 탭 이름)
    • Filters는 비워 둡니다(모든 줄을 읽습니다)
    설정 창 맨 위 이름을 한 번 눌러 오늘 접수 조회로 고칩니다.

    캔버스가 민원 정리 → 오늘 접수 조회 → 시트에 기록으로 이어지면 성공입니다.

  4. Always Output Data 켜기 오늘 접수 조회 설정 창 위쪽 Settings 탭을 누르고 Always Output Data를 켭니다. 시트에 오늘 줄이 하나도 없을 때도 다음 노드로 넘어가게 해 줍니다. 오늘 첫 접수를 위해 꼭 켭니다.

    스위치가 켜진 모양이면 성공입니다. 창 바깥을 눌러 캔버스로 돌아갑니다.

  5. 접수번호 만들기 끼워 넣기 오늘 접수 조회와 시트에 기록 사이 선의 +를 누르고 Edit Fields (Set)를 고릅니다. 이름을 접수번호 만들기로 고칩니다.
    1. Mode를 JSON으로 바꿉니다.
    2. JSON 칸 글자 근처에 마우스를 올리면 나타나는 Expression을 누릅니다. 칸 안의 글자를 Ctrl+A, Delete로 지웁니다.
    3. 아래 상자 안의 글자를 마우스로 빠르게 세 번 누르면 한 줄 전체가 골라집니다. 그 상태에서 Ctrl+C를 누르고, JSON 칸에 Ctrl+V로 붙여 넣습니다. 인쇄본에는 줄이 잘려 보이므로 반드시 웹 교안에서 복사합니다.
    4. 설정 창 위쪽 Settings 탭에서 Execute Once를 켭니다.
    {{ Object.assign({}, $('민원 정리').first().json, { "접수번호": $now.toFormat('yyyy-MMdd') + '-' + String($('오늘 접수 조회').all().filter(i => String(i.json['접수번호'] || '').startsWith($now.toFormat('yyyy-MMdd'))).length + 1).padStart(3, '0'), "처리상태": "접수" }) }}
    이 줄은 "민원 정리의 다섯 값에, 오늘 번호 개수 + 1로 만든 접수번호와 처리상태를 붙여라"라는 뜻의 표현식(앞 노드의 값을 가져오는 문장)입니다. 뜻을 몰라도 그대로 붙여 넣으면 됩니다. Execute Once는 시트에서 읽은 줄이 여러 개여도 번호를 한 번만 만들게 합니다.

    JSON 칸이 {{ Object.assign(로 시작해 }) }}로 끝나고 Execute Once가 켜져 있으면 성공입니다.

    자주 하는 실수

    증상 실행하면 접수번호 만들기가 빨갛게 멈춰요
    원인 표현식의 끝부분이 잘렸거나, 노드 이름이 민원 정리·오늘 접수 조회와 한 글자라도 달라요
    해결 JSON 칸을 비우고 세 번 눌러 다시 복사해 붙여 넣으세요. 노드 이름의 띄어쓰기도 확인하세요

  6. 시트에 기록에 두 칸 더하기 시트에 기록을 엽니다. 아래 열 목록에 접수번호·처리상태가 보이지 않으면 Mapping Column Mode를 다른 것으로 바꿨다가 다시 Map Each Column Manually로 고르면 새 열이 나타납니다.
    • 접수번호 칸: 마우스를 올려 Expression을 누르고 {{ $json.접수번호 }}
    • 처리상태 칸: 같은 방법으로 {{ $json.처리상태 }}
    • 설정 창을 맨 아래까지 내려 Add option을 누르고 Cell Format을 고른 뒤, 생긴 칸에서 Let n8n format을 고릅니다
    마지막 옵션은 시트가 2026-0925-001을 날짜로 바꿔 버리지 않게 합니다.

    여덟 칸 모두 fx 표시와 함께 채워져 있고 맨 아래 Cell Format 칸이 생겼으면 성공입니다.

  7. 앱에 답하기 붙이기 시트에 기록 오른쪽의 +를 누르고 Respond to Webhook을 고릅니다. 이름을 앱에 답하기로 고칩니다. Respond With를 JSON으로 바꾸고, Response Body에서 Expression을 누른 뒤 안의 글자를 지우고 아래를 붙여 넣습니다(3교시 7단계와 같은 방법). 
    {
  "접수번호": "{{ $json.접수번호 }}",
  "메시지": "접수되었습니다"
}

    여섯 노드가 한 줄로 이어지면 성공입니다.

  8. 민원 받기의 답장 방식 바꾸기 민원 받기를 열어 Respond를 Using 'Respond to Webhook' Node로 바꿉니다(3교시 4단계와 같음).

    Respond 칸에 Using 'Respond to Webhook' Node가 보이면 성공입니다.

  9. 다시 Publish하기 화면 위쪽 Publish → 확인 창의 Publish를 누릅니다. 설정을 여러 곳 바꿨으므로 꼭 다시 누릅니다. 앱에는 6교시에 넣은 Production URL이 그대로 있으므로 앱 주소는 바꾸지 않습니다.

    확인 창이 닫히고 버튼이 게시된 모양(3교시 [그림 1-3-8])이면 성공입니다.

  10. 앱에서 접수하고 접수번호 받기
    개인정보 주의 아래 가상 값만 넣습니다. 보낸 값은 시트와 실행 기록에 그대로 남습니다.
    앱에서 새 민원 접수로 입력 화면에 돌아가 박시민 / 010-0000-0003 / minwon@example.com / 생활 / 가로등이 꺼져 있습니다. 를 넣고 동의에 체크한 뒤 접수하기를 누릅니다.

    앱 화면에 오늘날짜-001 모양(예: 2026-0925-001)의 번호가 보이고, 시트의 새 줄에도 같은 접수번호와 접수가 적혀 있으면 성공입니다.

    한 번 더 새 민원 접수를 눌러 최주민 / 010-0000-0004 / minwon@example.com / 음식물 / 음식물 수거함이 넘칩니다. 로 접수합니다. 번호가 …-002로 늘어나면 성공입니다.

    2교시와 6교시에 쌓인 줄에는 접수번호가 없는데, 이 줄들은 순번에 세지 않으므로 괜찮습니다.
    자주 하는 실수

    증상 시트에는 쌓이는데 앱 화면의 접수번호가 비어 있어요
    원인 n8n이 번호를 돌려주지 않았거나, 앱이 받은 번호를 보여 주지 못해요
    해결 먼저 n8n 쪽을 봅니다 — 위 점검표 5·6번(Respond 변경, 다시 Publish)을 확인하세요. 그래도 비어 있으면 접수번호 표시 문장의 첫 문장을 AI Studio에 보냅니다

    증상 매번 …-001만 나와요
    원인 시트 머리글을 접수 번호처럼 띄어 썼거나, 접수번호가 날짜 모양으로 바뀌었거나, 오늘 접수 조회가 다른 시트를 읽어요

    원인 중간 노드에서 멈췄어요
    해결 n8n 위쪽 Executions에서 방금 실행을 열어 빨간 노드를 찾으세요. 오늘 접수 조회라면 Always Output Data가 켜져 있는지 봅니다

완성본 가져오기(Import)

이 파일을 가져오면 n8n 쪽이 이 교시 끝 상태(여섯 노드)가 됩니다. 앱은 6교시에 만든 것을 그대로 씁니다.

  1. 파일 내려받기 워크플로우 내려받기 d1-p7.json
  2. n8n에서 가져오기 Create workflow → 오른쪽 위 … → Import → From file을 누르고 파일을 고릅니다. 시간대(서울)는 파일에 들어 있습니다.
  3. 자격 증명 다시 연결하기 오늘 접수 조회와 시트에 기록 두 노드를 열어 Credential 칸에서 내 구글 시트 자격 증명을 고릅니다.
  4. 자리표시자 바꾸기 같은 두 노드의 Document 칸 왼쪽 목록(지금은 By ID)을 From list로 바꾸고 민원대장 연습을 고릅니다. 여기에_본인_시트_ID 글자가 없어지면 됩니다. Sheet는 내 탭 이름(파일에는 시트1)으로 둡니다. 시트 1행에 접수번호, 처리상태 머리글이 있는지도 확인합니다(따라하기 2단계).
  5. Publish하고 앱 주소 확인하기 Publish → 확인 창의 Publish. 새로 가져온 워크플로우는 주소가 같으므로 앱의 WEBHOOK_URL은 6교시에 넣은 Production URL 그대로 둡니다. 다르게 보이면 6교시 9단계 순서로 민원 받기의 Production URL을 앱에 넣습니다. 앱에서 접수해 번호가 보이면 복구 완료입니다.
