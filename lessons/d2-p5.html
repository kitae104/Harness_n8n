목차 › 2일차 › 5교시 (14:00~14:50)

프로젝트 제작 ①

설계서대로 앱 화면을 만들고, 민원 접수 완성본을 고쳐 내 워크플로우를 만듭니다

학습목표

  • 설계서를 바탕으로 프롬프트 템플릿을 고쳐 내 앱 화면을 만듭니다.
  • 기존 완성 파일을 복사·변형해 내 워크플로우를 구성합니다.

처음부터 만들지 않고 고쳐 씁니다

이틀 동안 만든 민원 접수 서비스는 대부분의 "접수형" 업무에 그대로 쓸 수 있는 뼈대입니다. 내 서비스는 이 뼈대에서 칸 이름과 문구만 바꾸면 됩니다. 오늘 예시는 4교시 설계서의 "현장점검 보고 앱"입니다. 이 교시 끝에 예시 완성본이 있으니, 내 주제가 비슷하면 그것을 가져와 고쳐도 됩니다.

한 문장 요약 칸 이름은 설계서 → 앱 → 시트 머리글 → 정리 노드까지 똑같이 씁니다. 이것만 지키면 나머지는 민원 접수 때와 같습니다.
용어 다시 보기
  • Webhook: 외부 앱이 n8n을 부르는 주소(초인종)
  • Test URL: 만드는 중에 시험할 때 쓰는 주소 / Production URL: 게시한 뒤 앱에 넣는 진짜 주소
  • Publish: 워크플로우를 게시해 주소가 항상 동작하게 하는 버튼(고친 뒤에는 다시 누름)
  • CORS: 다른 주소의 앱이 n8n을 불러도 되는지 정하는 허락 규칙(Allowed Origins (CORS) = *)
  • 표현식: {{ }} 안에 써서 앞 노드의 값을 가져오는 문장

활동

진행 방법 팀이면 앱 담당은 1단계, n8n 담당은 2~3단계를 동시에 합니다. 개인이면 차례로 합니다. 막히면 해당 교시 교안(링크)을 다시 봅니다.
  1. 앱 화면 만들기 (10분) 4교시에 채운 주문서를 AI Studio에 붙여 넣어 새 앱을 만듭니다(aistudio.google.com/apps, 1일차 4교시와 같은 방법). 미리보기에서 칸 이름이 설계서와 같은지, 보내기 버튼을 누르면 "아직 연결되지 않았습니다."가 뜨는지 확인합니다. 예시 주문서: 현장점검 보고 앱 주문서. 화면이 마음에 들지 않으면 1일차 5교시의 수정 요청 문장을 씁니다.
  2. 새 시트 만들기 (5분) sheets.new로 새 구글 시트를 만들고 이름을 (서비스 이름) 연습으로 바꿉니다(예: 점검대장 연습). 1행에 입력 칸 이름 + 등록일, 접수번호, 처리상태를 한 칸씩 적습니다. 
    점검장소	점검결과	특이사항	점검자	등록일	접수번호	처리상태
    위는 예시입니다. 앞 네 칸을 내 입력 칸 이름으로 바꿔 적습니다. 띄어쓰기 없이, 설계서와 똑같이 씁니다.
  3. 워크플로우 고쳐 만들기 (20분) 이 교시 끝 "완성본 가져오기"로 현장점검 예시를 가져오거나, n8n에서 1일차 7교시 민원 접수 워크플로우를 열어 오른쪽 위 … → 복제(Duplicate)합니다. 그다음 아래 표의 곳만 고칩니다.
    노드고칠 곳
    받기(Webhook)Path를 새 영어 단어로(예: field-check). 민원 접수와 같은 minwon을 쓰면 충돌합니다. Allowed Origins (CORS) *, Respond는 그대로
    정리(Edit Fields)다섯 줄을 지우고 내 입력 칸 이름으로 다시 만들기: 왼쪽 이름 = 칸 이름, 오른쪽 값 = {{ $json.body['칸 이름'] }}
    오늘 접수 조회Document를 새 시트로
    접수번호 만들기정리 노드 이름을 바꿨다면 한 줄 표현식 안의 $('민원 정리')를 새 이름으로(예: $('점검 정리'))
    시트에 기록Document를 새 시트로, 열 목록을 다시 불러와 칸마다 {{ $json.칸 이름 }}, 등록일·접수번호·처리상태는 1일차 7교시와 같게
    앱에 답하기메시지 문구만 내 서비스에 맞게(예: "점검 보고가 접수되었습니다")

    메일·캘린더·AI·텔레그램 가지는 6교시에 붙입니다. 지금은 받기 → 시트 기록 → 앱에 답하기까지만 완성합니다.

    자주 하는 실수

    증상 시트에 줄은 생기는데 칸이 비어 있어요
    원인 앱이 보내는 칸 이름, 정리 노드의 이름, 시트 머리글 중 하나가 달라요
    해결 세 곳의 칸 이름을 나란히 적어 한 글자씩 비교하세요. 띄어쓰기가 가장 흔한 원인입니다

  4. 연결하고 한 번 보내 보기 (5분) 1일차 6교시와 같은 순서입니다: 앱에 WEBHOOK_URL로 Test URL 넣기 → 시험 → Publish → Production URL로 바꾸기. 자세한 단계는 1일차 6교시 따라하기 2~3단계와 8~9단계를 봅니다.

    앱에서 가상 값을 보내 시트에 한 줄이 생기고 앱에 접수번호가 보이면 이 교시의 목표를 이룬 것입니다.

    개인정보 주의 내 업무 서비스라도 실습에는 가상 값만 넣습니다. 실제 적용은 3교시 점검표를 거친 뒤 부서에서 합니다.
빨리 끝났다면 6교시 내용(If·AI·메일·텔레그램 붙이기)을 먼저 해도 되고, 선택 실습을 해 봐도 됩니다: PDF 공문 요약 앱, 음성 입력 민원 접수.

정리

  • 민원 접수 완성본의 칸 이름·경로·시트·문구만 바꿔 내 서비스를 만들었습니다.
  • 칸 이름은 설계서 → 앱 → 시트 → 정리 노드까지 똑같이 씁니다.
  • 다음: 6교시에는 연결을 마무리하고 메일·AI·알림을 붙인 뒤 발표를 준비합니다.

완성본 가져오기(Import) — 현장점검 예시 기본형

내 주제가 현장점검과 비슷하면 이 예시를 가져와 칸 이름만 고쳐 써도 됩니다.

  1. 파일 내려받기 예시 워크플로우 내려받기 d2-p5.json
  2. n8n에서 가져오기 Create workflow → 오른쪽 위 … → Import → From file. 노드 여섯 개가 보이면 성공입니다.
  3. 자격 증명 다시 연결하기 오늘 접수 조회와 시트에 기록을 열어 Credential 칸에서 내 구글 시트 자격 증명(n8n이 내 계정을 대신 쓰도록 맡겨 둔 열쇠)을 고릅니다.
  4. 자리표시자 바꾸기 같은 두 노드의 Document: 왼쪽 목록을 From list로 바꾸고 2단계에서 만든 새 시트(여기에_본인_시트_ID 대신), Sheet: 내 탭 이름.
  5. Publish하고 앱에 주소 넣기 Publish → 확인 창의 Publish. 점검 받기의 Production URL을 1일차 6교시 9단계 순서로 내 앱의 WEBHOOK_URL에 넣습니다. 앱에서 보내 시트에 줄이 생기면 복구 완료입니다.
