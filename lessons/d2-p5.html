프로젝트 제작 ①

설계서대로 앱 화면을 만들고, 민원 접수 완성본을 고쳐 내 워크플로우를 만듭니다

학습목표

  • 설계서를 바탕으로 프롬프트 템플릿을 고쳐 내 앱 화면을 만듭니다.
  • 기존 완성 파일을 복사·변형해 내 워크플로우를 구성합니다.

처음부터 만들지 않고 고쳐 씁니다

이틀 동안 만든 민원 접수 서비스는 대부분의 "접수형" 업무에 그대로 쓸 수 있는 뼈대입니다. 내 서비스는 이 뼈대에서 칸 이름과 문구만 바꾸면 됩니다. 오늘 예시는 4교시 설계서의 "현장점검 보고 앱"입니다. 이 교시 끝에 예시 완성본이 있으니, 내 주제가 비슷하면 그것을 가져와 고쳐도 됩니다.

용어 다시 보기
  • Webhook: 외부 앱이 n8n을 부르는 주소(초인종)
  • Test URL: 만드는 중에 시험할 때 쓰는 주소 / Production URL: 게시한 뒤 앱에 넣는 진짜 주소
  • Publish: 워크플로우를 게시해 주소가 항상 동작하게 하는 버튼(고친 뒤에는 다시 누름)
  • CORS: 다른 주소의 앱이 n8n을 불러도 되는지 정하는 허락 규칙(Allowed Origins (CORS) = *)
  • 표현식: {{ }} 안에 써서 앞 노드의 값을 가져오는 문장

활동

진행 방법 팀이면 "만드는 사람" 컴퓨터 한 대로, 읽어 주는 사람이 이 교안을 읽고 칸 이름 철자를 확인합니다. 막히면 해당 교시 교안(링크)을 새 탭에서 엽니다(링크를 마우스 오른쪽 버튼으로 눌러 "새 탭에서 열기").

시간 기준: 14시 35분까지 3단계 표를 다 고치지 못했으면 강사에게 알리고, 이 교시 끝 "완성본 가져오기"로 현장점검 예시를 가져와 4단계부터 합니다. 내 칸 이름으로 바꾸는 일은 6교시 앞부분에 합니다.

칸 이름을 똑같이 맞출 다섯 곳 ① 앱이 보내는 키(AI Studio Code 탭) ② 정리 노드 오른쪽 값의 body['…'] ③ 정리 노드 왼쪽 이름 ④ 시트 1행 머리글 ⑤ 시트에 기록의 {{ $json.… }}. 한 글자, 띄어쓰기 하나라도 다르면 그 칸이 비어서 기록됩니다.
  1. 앱 화면 만들기 (10분) 4교시에 저장한 내주문서.txt를 열어 전체를 복사하고, AI Studio(aistudio.google.com/apps)에 붙여 넣어 새 앱을 만듭니다(1일차 4교시와 같은 방법).
    • 미리보기의 칸 이름이 설계서와 같나요?
    • 보내기 버튼을 누르면 "아직 연결되지 않았습니다."가 뜨나요?
    • Code 탭에서 Ctrl+F로 WEBHOOK_URL과 내 칸 이름(예: 점검장소)을 찾았을 때 한글 그대로 보이나요?

    셋 다 그렇다면 성공입니다.

    예시 주문서: 현장점검 보고 앱 주문서. 화면이 마음에 들지 않으면 1일차 5교시의 수정 요청 문장을 씁니다. 연습에 넣는 값도 가상 값(예: OO동 체육공원 / 오점검)입니다.
  2. 새 시트 만들기 (5분) sheets.new로 새 구글 시트를 만들고 이름을 (서비스 이름) 연습으로 바꿉니다(예: 점검대장 연습). 1행에 입력 칸 이름 + 등록일, 접수번호, 처리상태를 한 칸씩 적습니다. 
    점검장소	점검결과	특이사항	점검자	등록일	접수번호	처리상태
    위는 예시입니다. 앞 네 칸을 내 입력 칸 이름으로 바꿔 적습니다. 띄어쓰기 없이, 설계서와 똑같이 씁니다.

    1행이 내 칸 이름 + 세 칸으로 채워지면 성공입니다.

  3. 워크플로우 뼈대 준비하기 (5분) 이 교시 끝 "완성본 가져오기"로 현장점검 예시를 가져오는 것이 가장 쉽습니다(노드 여섯 개가 이미 한 줄로 이어져 있습니다). 민원 접수 워크플로우를 복제해 쓰려면: n8n에서 그 워크플로우를 열고 오른쪽 위 … → Duplicate를 누른 뒤, 복사본에서 민원 받기·민원 정리·오늘 접수 조회·접수번호 만들기·시트에 기록·앱에 답하기 여섯 개만 남기고 나머지(메일·캘린더·AI·If·텔레그램·조회 흐름)는 한 번 눌러 Delete로 지웁니다.

    캔버스에 노드 여섯 개가 한 줄로 이어져 있으면 성공입니다.

  4. 받기 노드 고치기 받기(Webhook) 노드를 엽니다. Path를 새 영어 단어로 바꿉니다(예시는 field-check, 내 서비스면 my-report 같은 다른 단어). 민원 접수와 같은 minwon을 쓰면 충돌합니다. Allowed Origins (CORS) *, Respond는 그대로 둡니다.

    위쪽 주소가 새 단어로 끝나면 성공입니다.

  5. 정리 노드 고치기 현장점검 예시와 칸이 같으면 이 단계는 건너뜁니다. 다르면:
    1. 정리 노드를 열고, 줄마다 마우스를 올리면 나오는 휴지통으로 원래 줄을 모두 지웁니다.
    2. Add Field를 누르고 왼쪽 칸에 내 칸 이름(예: 점검장소)을 적습니다.
    3. 오른쪽 칸에 마우스를 올려 Expression을 누르고 {{ $json.body['점검장소'] }}처럼 적습니다(따옴표 안에 내 칸 이름).
    4. 칸 수만큼 2~3을 되풀이합니다.

    줄 수가 칸 개수와 같고, 왼쪽 이름과 body['…'] 안의 이름이 설계서와 한 글자도 다르지 않으면 성공입니다.

    아직 앱에서 보낸 적이 없어 왼쪽 입력 목록이 비어 있으므로, 1일차 6교시처럼 끌어다 놓는 방법 대신 직접 적습니다.
  6. 접수번호 만들기 고치기 정리 노드 이름을 바꾸지 않았으면 건너뜁니다. 바꿨으면 JSON 칸을 Ctrl+A, Delete로 비우고, 아래 줄을 세 번 눌러 복사해 붙여 넣은 뒤 점검 정리 네 글자만 내 정리 노드 이름으로 고칩니다. 
    {{ Object.assign({}, $('점검 정리').first().json, { "접수번호": $now.toFormat('yyyy-MMdd') + '-' + String($('오늘 접수 조회').all().filter(i => String(i.json['접수번호'] || '').startsWith($now.toFormat('yyyy-MMdd'))).length + 1).padStart(3, '0'), "처리상태": "접수" }) }}

    JSON 칸 안에 내 정리 노드 이름이 보이고 }) }}로 끝나면 성공입니다.

  7. 시트 노드 두 개 고치기
    1. 오늘 접수 조회와 시트에 기록의 Document를 From list에서 2단계의 새 시트로, Sheet는 시트1(내 탭 이름)로 바꿉니다.
    2. 시트에 기록의 열 목록이 새 머리글로 안 바뀌면 Mapping Column Mode를 다른 것으로 바꿨다가 Map Each Column Manually로 되돌립니다.
    3. 내 칸마다 {{ $json.점검장소 }}처럼 적습니다(Expression).
    4. 나머지 세 칸: 등록일 = {{ $now.toFormat('yyyy-MM-dd') }}, 접수번호 = {{ $json.접수번호 }}, 처리상태 = {{ $json.처리상태 }}
    5. 맨 아래 Cell Format이 Let n8n format인지 봅니다.

    열 목록이 새 시트 머리글과 같고 모든 칸에 fx 표시가 있으면 성공입니다. 앱에 답하기는 메시지 문구만 내 서비스에 맞게 바꿉니다(예: "점검 보고가 접수되었습니다").

    자주 하는 실수

    증상 시트에 줄은 생기는데 칸이 비어 있어요
    원인 위 "다섯 곳"의 칸 이름 중 하나가 달라요
    해결 다섯 곳의 칸 이름을 나란히 적어 한 글자씩 비교하세요. 띄어쓰기가 가장 흔한 원인입니다

    증상 접수번호 만들기가 빨갛게 멈춰요
    원인 표현식 안의 정리 노드 이름이 실제 노드 이름과 달라요
    해결 6단계대로 다시 붙여 넣고 노드 이름을 한 글자씩 맞추세요

  8. 연결하고 한 번 보내 보기 (12분)
    1. 받기 노드의 Test URL을 앱의 WEBHOOK_URL에 넣습니다(1일차 6교시 2단계 문장, "문장 먼저 → 주소 나중" 순서).
    2. 앱에 가상 값을 채우고 아직 누르지 않습니다.
    3. n8n 캔버스 아래 Execute workflow를 누르고 2분 안에 앱에서 보냅니다. 여섯 노드가 초록이고 시트에 한 줄이 생기면 성공입니다.
    4. Publish → 확인 창의 Publish를 누릅니다.
    5. 받기 노드의 Production URL(/webhook/)을 같은 방법으로 앱에 넣고 한 번 더 보냅니다. 앱에 접수번호가 보이면 이 교시의 목표를 이룬 것입니다.
    개인정보 주의 내 업무 서비스라도 실습에는 가상 값만 넣습니다. 실제 적용은 3교시 점검표를 거친 뒤 부서에서 합니다.
    자주 하는 실수

    증상 Test URL로는 됐는데 Production URL로 바꾸니 안 돼요
    원인 Publish를 안 했거나, Publish 뒤에 노드를 고쳤어요
    해결 Publish를 다시 누르고 보내 보세요

    증상 현장점검 예시를 둘 다 가져왔더니 하나가 동작하지 않아요
    원인 같은 경로(field-check)는 하나만 동작해요
    해결 쓰지 않는 쪽을 Unpublish하거나 경로를 바꾸세요

빨리 끝났다면 6교시 내용(If·AI·메일·텔레그램 붙이기)을 먼저 해도 되고, 선택 실습을 해 봐도 됩니다: PDF 공문 요약 앱, 음성 입력 민원 접수.

정리

  • 민원 접수 완성본의 칸 이름·경로·시트·문구만 바꿔 내 서비스를 만들었습니다.
  • 칸 이름은 앱·정리 노드·시트 머리글·시트 기록 노드 다섯 곳에 똑같이 씁니다.
  • 다음: 6교시에는 연결을 마무리하고 메일·AI·알림을 붙인 뒤 발표를 준비합니다.

완성본 가져오기(Import) — 현장점검 예시 기본형

내 주제가 현장점검과 비슷하면 이 예시를 가져와 칸 이름만 고쳐 써도 됩니다. 내 주제가 다르면, 가져온 뒤 활동 4~7단계대로 받기·정리·시트 노드를 내 칸 이름으로 고쳐야 내 앱과 연결됩니다.

  1. 파일 내려받기 예시 워크플로우 내려받기 d2-p5.json
  2. n8n에서 가져오기 Create workflow → 오른쪽 위 … → Import → From file. 노드 여섯 개가 보이면 성공입니다.
  3. 자격 증명 다시 연결하기 오늘 접수 조회와 시트에 기록을 열어 Credential 칸에서 내 구글 시트 자격 증명(n8n이 내 계정을 대신 쓰도록 맡겨 둔 열쇠)을 고릅니다.
  4. 자리표시자 바꾸기 같은 두 노드의 Document: 왼쪽 목록을 From list로 바꾸고 활동 2단계에서 만든 새 시트(여기에_본인_시트_ID 대신), Sheet: 내 탭 이름.
  5. Publish하고 앱에 주소 넣기 Publish → 확인 창의 Publish. 점검 받기의 Production URL을 1일차 6교시 9단계 순서로 내 앱의 WEBHOOK_URL에 넣습니다. 앱에서 보내 시트에 줄이 생기면 복구 완료입니다.
