프로젝트 제작 ②

처음부터 끝까지 시험하고, 막히면 점검 순서표로 원인을 좁히고, 시간이 남으면 기능을 더합니다

강사 준비·확인이 교시에서 수업 전에 강사가 할 일입니다. 수강생용 내용이 아니며, 준비가 끝나면 python scripts/strip_inotes.py로 모두 지웁니다.
  • 확장 예시(workflows/d2-p6.json) 보수필요 → AI 조치 요약 → 팀장 메일·텔레그램 동작, 점검 순서표로 오류 찾기가 되는지
  • 확인이 끝나면 docs/instructor-checklist.md의 이 교시 행에 체크

학습목표

  • 내 앱과 워크플로우를 연결해 처음부터 끝까지 테스트합니다.
  • 막히면 점검 순서표에 따라 원인을 스스로 좁힙니다.

왜 순서대로 점검하나

앱과 n8n 사이에는 확인할 곳이 여러 군데 있습니다. "안 돼요"에서 멈추지 않으려면 늘 같은 순서로 하나씩 확인합니다. 이 순서는 이틀 동안 겪은 실수를 모은 것입니다. 앞에서부터 확인하면 대부분 세 번째 안에 원인이 나옵니다.

용어 다시 보기
  • Webhook: 외부 앱이 n8n을 부르는 주소 / Respond to Webhook: 부른 쪽에 답장을 보내는 노드
  • Test URL: 만드는 중에 시험할 때 쓰는 주소 / Production URL: 게시한 뒤 앱에 넣는 진짜 주소
  • Publish: 워크플로우를 게시해 주소가 항상 동작하게 하는 버튼
  • CORS: 다른 주소의 앱이 n8n을 불러도 되는지 정하는 허락 규칙
  • 자격 증명: n8n이 내 계정을 대신 쓰도록 맡겨 둔 열쇠 / 표현식: {{ }} 안에 써서 앞 노드의 값을 가져오는 문장
  • API 키: Gemini 같은 서비스를 쓸 수 있게 해 주는 비밀 번호표

먼저 한 곳만 봅니다. n8n 워크플로우 화면 위쪽의 Executions 탭을 누르고, 왼쪽 목록 맨 위(방금 시각) 줄을 한 번 누릅니다. 그리고 아래 셋 중 어느 경우인지 고릅니다.

  • ① 목록에 방금 시각 줄이 없다 → 앱이 n8n에 닿지 못했습니다. 아래 표 가의 1~3번을 봅니다.
  • ② 빨간 노드가 있다 → 그 노드 이름을 보고 아래 표 나에서 같은 이름 줄을 봅니다.
  • ③ 모두 초록인데 결과가 안 보인다 → 앱 화면이 실패면 표 가의 4번, 메일·알림만 안 오면 보수필요인가? 같은 If 노드를 눌러 false 쪽으로 갔는지 봅니다.

활동

시간 기준 15시 20분까지 1단계(보내면 시트에 쌓이고 번호가 돌아옴)가 안 되면 3단계 기능 더하기는 건너뛰고 2단계만 합니다. 발표는 되는 데까지와 설계서로 해도 됩니다.

5교시 기본 흐름이 없으면 먼저 5교시 완성본 가져오기로 맞춥니다.

  1. 처음부터 끝까지 시험하기 (10분) 앱에서 가상 값(예: OO동 체육공원 / 보수필요 / 벤치 1개 파손 / 오점검)으로 세 번 보냅니다. 매번 아래를 확인합니다.
    • 앱에 접수번호가 보이나요? 두 번째는 …-002로 늘어나나요?
    • 시트에 한 줄씩 쌓이고 칸이 모두 채워졌나요?
    • n8n Executions에 실행 기록이 세 줄 생겼나요?
    개인정보 주의 내 업무 서비스라도 실제 사람 이름·연락처·실제 사건을 넣지 않습니다. 발표 캡처에도 가상 값만 보이게 합니다.
  2. 막히면 점검 순서표로 좁히기 위 표의 1번부터 차례로 확인합니다. 한 번에 하나만 고치고, 고칠 때마다 다시 Publish → 앱에서 한 번 보내기를 합니다.
    자주 하는 실수

    증상 여러 곳을 한꺼번에 고쳤더니 무엇 때문에 된 건지(또는 안 되는지) 모르겠어요
    원인 고칠 때마다 시험하지 않았어요
    해결 점검 순서표 한 줄 → 고치기 → Publish → 한 번 보내기. 이 순서를 지키세요

    증상 표 가의 1~4번이 다 맞는데 앱에 "보내지 못했습니다"(또는 "접수하지 못했습니다")가 뜨고, Executions에 방금 시각 줄이 없어요
    원인 브라우저가 앱에서 n8n을 직접 부르는 것을 막는 경우예요
    해결 AI Studio 대화 입력창에 아래 글을 그대로 보내세요(1일차 6교시 3단계 끝 박스의 글에서 버튼 이름과 문구만 바꾼 것입니다)

    보내기 버튼을 누르면 "보내지 못했습니다"가 떠. n8n 주소 호출은 서버 쪽 코드에서 하도록 바꿔 줘. WEBHOOK_URL 값과 보내는 JSON의 키 이름은 바꾸지 마.

    증상 조건에 맞는 값을 보냈는데 메일이 안 와요(모두 초록)
    원인 If의 비교 글자와 앱이 보낸 글자가 달라요(예: 보수 필요와 보수필요)
    해결 If 노드의 오른쪽 칸을 앱 목록의 글자와 한 글자도 다르지 않게 고치세요

  3. 기능 더하기 (20분, 설계서의 "처리·출력"대로) 기본 흐름이 되면 설계서에 적은 처리·출력을 하나씩 붙입니다. 붙이는 방법은 이미 배운 교시와 같습니다.
    더할 기능붙이는 곳따라 할 교안
    담당자·팀장 메일시트에 기록에서 새 가지2일차 1교시 5단계
    조건에 따라 나누기(예: 보수필요일 때만)가지 앞에 If2일차 2교시 1~2단계
    AI 요약·안내문If의 true 점 뒤(If가 없으면 시트에 기록에서 새 가지). 앱에 답하기보다 아래에 둡니다2일차 1교시 2~3단계. 단, 2단계 끝의 "위쪽으로 옮기기"와 4단계는 하지 않습니다. 주문 문장만 내 업무로 바꿉니다
    캘린더 일정시트에 기록에서 새 가지2일차 1교시 6~7단계
    텔레그램 부서방 알림시트에 기록에서 맨 아래 가지2일차 2교시 10~11단계

    현장점검 예시에서는 보수필요인가?(If) → AI 조치 요약 → 팀장 메일과 텔레그램 알림을 붙였습니다. 이 교시 끝 예시 완성본에서 모양을 볼 수 있습니다.

    다른 교안을 따라 할 때 바꿔 읽기
    • 교안의 종류·이름·상세설명 같은 칸 이름은 내 칸 이름으로 바꿔 적습니다(예: {{ $json.종류 }} → {{ $json.점검결과 }}).
    • 노드 이름도 내 것으로 붙입니다(담당자 메일 → 팀장 메일).
    • AI 노드 뒤에 붙인 메일·알림에서는 {{ $json.칸이름 }} 대신 {{ $('시트에 기록').first().json.칸이름 }}으로 씁니다. AI 뒤의 $json에는 AI가 쓴 글($json.text)만 들어 있기 때문입니다.
    • 메일 To에는 실제 팀장 주소가 아니라 {본인 이메일}을 적습니다(실습에서는 내가 팀장입니다).
    • 가지를 붙일 때마다 앱에 답하기 가지가 캔버스 맨 위에 있는지 봅니다(n8n은 위쪽 가지부터 실행). AI 주문 문장에는 "비용·법령·업체 이름은 지어내지 않습니다"를 꼭 넣습니다.
  4. 선택 실습을 하려면 기본 흐름과 기능 하나가 다 되었고 시간이 남으면 선택 실습을 해도 됩니다. 수료 뒤 혼자 해도 되도록 교안과 완성본이 준비되어 있습니다.
    • PDF 공문 요약 앱 — 파일을 올리면 Gemini가 요약해 메일·텔레그램으로 보냄
    • 음성 입력 민원 접수 — 민원 접수 앱에 "음성으로 입력" 버튼 더하기(n8n은 그대로)
  5. 발표 준비 (마지막 5분) 7교시 발표에 쓸 화면 세 장을 캡처해 둡니다: ① 앱 화면(입력과 완료), ② n8n 워크플로우 전체, ③ 결과(시트·메일·알림 중 하나). 캡처에 가상 값만 보이는지, 이메일 주소·API 키·Webhook 주소가 가려졌는지 확인합니다.

정리

  • 막히면 점검 순서표(Publish → 주소 → CORS → 응답 방식 → 시트·칸 이름)를 앞에서부터 확인합니다.
  • 기능은 하나씩 붙이고, 붙일 때마다 Publish하고 한 번 보냅니다.

완성본 가져오기(Import) — 현장점검 예시 확장형

이 파일은 내 서비스의 복구본이 아니라 현장점검 예시의 완성 모양(보수필요일 때 AI 조치 요약 → 팀장 메일, 텔레그램 알림)입니다. 두 가지 경우에만 가져옵니다.

  • 모양만 보고 싶을 때: 1~2단계만 하고 Publish는 하지 않습니다. 내 서비스는 그대로 동작합니다.
  • 내 서비스가 끝내 안 되어 발표를 이 예시로 할 때: 5교시 현장점검 앱(주문서)이 있어야 합니다. 내 워크플로우가 같은 경로 field-check를 쓰고 있으면 내 워크플로우를 먼저 Unpublish합니다(같은 경로는 하나만 동작합니다).

  2. n8n에서 가져오기 Create workflow → 오른쪽 위 … → Import → From file. 노드 열한 개가 보이면 성공입니다.
  3. 자격 증명 다시 연결하기
    • 오늘 접수 조회, 시트에 기록 — 구글 시트용
    • Google Gemini Chat Model — Gemini API 키
    • 팀장 메일 — Gmail용
    • 텔레그램 알림 — 텔레그램 봇 토큰(없으면 이 노드를 지웁니다)
  4. 자리표시자 바꾸기
    • 시트 노드 두 개의 Document: From list로 바꾸고 내 시트(여기에_본인_시트_ID 대신), Sheet: 내 탭 이름
    • 팀장 메일의 To: 본인이메일@example.com → 내 Gmail 주소
    • 텔레그램 알림의 Chat ID: 여기에_본인_채팅_ID → 내 chat id
    • Gemini Model: models/gemini-3.8-flash 다시 고르기
  5. Publish하고 보내 보기 Publish를 누르고, 앱의 WEBHOOK_URL에 점검 받기의 Production URL이 들어 있는지 확인합니다(없으면 1일차 6교시 9단계 순서로 넣습니다). 점검결과를 "보수필요"로 보내 팀장 메일에 AI 조치 요약이 오면 성공입니다.
