앱 배포·공유·보안

동료에게 앱을 보여 주고, 비밀값과 개인정보가 어디에 남는지 점검합니다

학습목표

  • AI Studio 앱의 공유 링크를 만들어 동료가 열어 보게 합니다.
  • API 키 등 비밀값을 앱·워크플로우에 노출하지 않는 방법을 압니다.
  • 실제 적용 전 개인정보·보안 점검표를 작성하고, 기관 설치형 n8n 전환이 무엇인지 설명할 수 있습니다.

왜 이 단계가 필요한가

용어 다시 보기 (n8n) Webhook(외부 앱이 n8n을 부르는 주소), Test URL(시험할 때만 쓰는 주소), Production URL(게시한 뒤 앱에 넣는 진짜 주소), n8n의 Publish(워크플로우를 게시해 주소가 항상 동작하게 하는 버튼), CORS(다른 주소의 앱이 n8n을 불러도 되는지 정하는 허락 규칙, 설정 이름 Allowed Origins (CORS))

지금까지 만든 서비스는 내 계정 안에서 잘 돌아갑니다. 동료와 함께 쓰려면 앱을 보여 줘야 하고, 그 순간 "누가 무엇을 볼 수 있나"가 중요해집니다. 이번 시간에는 앱을 공유해 보고, 비밀값과 개인정보가 어디에 남는지 확인해 실제 적용 전 점검표를 씁니다.

이름이 비슷한 버튼어디하는 일이번 시간
ShareAI Studio정한 사람에게 내 앱을 보여 주는 공유 링크실습
PublishAI Studio앱을 구글 클라우드(Cloud Run)에 올려 누구나 여는 공개 주소를 만듦소개만
Publishn8n워크플로우 켜기 — 이름만 같고 다른 기능이미 배움
세 가지만 기억합니다
  1. 공유하면 코드도 보입니다. 공유받은 사람은 앱 코드를 볼 수 있으므로, 코드에 비밀값·실제 개인정보를 넣지 않습니다.
  2. 비밀값은 금고에 둡니다. API 키(서비스를 쓸 수 있게 해 주는 비밀 번호표)는 AI Studio의 Secrets, n8n의 자격 증명(n8n이 내 계정을 대신 쓰도록 맡겨 둔 열쇠)에만 둡니다.
  3. 입력한 값은 여러 곳에 남습니다. 시트·메일·n8n 실행 기록·AI 서비스. 실제 개인정보는 기관 협의 뒤에만 넣습니다.
허락 명단(CORS)은 자물쇠가 아니라 "안내판"입니다 Allowed Origins (CORS)는 다른 웹사이트 화면이 내 n8n의 답을 읽지 못하게 하는 브라우저용 안내판입니다. 주소를 아는 사람이 다른 방법으로 요청을 보내는 것까지 막는 자물쇠는 아닙니다. 실제 자물쇠는 Webhook 노드의 Authentication(비밀번호처럼 약속한 글자를 함께 보내야만 받아 주는 설정)인데, 그 비밀 글자를 앱 화면 코드에 넣으면 공유받은 사람이 볼 수 있어 앱의 서버 쪽(보이지 않는 뒤편)에서 처리해야 합니다. 실습에서는 하지 않아도 괜찮습니다. 가상 데이터만 쓰기 때문입니다. 실제 운영 전에 기관 보안 담당과 정합니다.
기관 설치형 n8n — 한 줄 결론: 운영은 기관이 승인한 환경에서 교육에 쓴 n8n Cloud는 n8n 회사의 서버를 빌려 쓰는 것이고, n8n은 기관 서버에 직접 설치해 쓸 수도 있습니다(무료판). 설치와 보안 관리는 전산 담당 부서가 맡습니다. 무료판은 조직 내부 업무용으로 쓸 수 있지만 여러 사람이 함께 관리하는 기능 등은 빠져 있고, 구글 연결 설정을 따로 해야 하며, 앱이 부르려면 인터넷 주소가 열려 있어야 합니다. 도입 여부와 사용 조건은 기관 보안·전산·법무 담당과 협의합니다. 참고: n8n 설치 안내(영문)
AI Studio Publish는 소개만 합니다 Publish는 앱을 Google Cloud Run에 올려 누구나 여는 공개 주소를 만드는 기능입니다. 조건이 맞는 개인 계정은 결제 등록 없이 앱 2개까지 올릴 수 있지만, 기관 계정이거나 예전에 Google Cloud 결제 계정을 만든 적이 있으면 결제 계정이 필요하고 사용량에 따라 요금이 나올 수 있습니다. 이 과정에서는 실습하지 않습니다.

따라하기

  1. 공유 링크 만들기 AI Studio에서 민원 접수 앱을 열고 오른쪽 위 Share를 누릅니다. 공개 범위에서 링크가 있는 사람이 볼 수 있게(보기 권한) 고르고 공유 링크를 복사합니다.

    링크가 복사되면 성공입니다. 편집 권한은 주지 않습니다(받은 사람이 코드를 고칠 수 있게 됩니다).

  2. 옆 사람과 서로 시험하기
    내 서비스가 아직 동작하지 않을 때 이번 교시에서는 고치지 않습니다. 옆 사람 앱 링크를 받아 접수만 해 보고, 5단계는 옆 사람 화면의 Executions를 함께 봅니다. 내 서비스는 2일차 2교시 완성본 가져오기로 쉬는 시간이나 6교시에 복구합니다. 짝이 없으면 강사에게 링크를 받습니다.
    옆 사람과 링크를 주고받습니다. 개인 메신저·연락처를 주고받지 않도록, 링크가 뜬 화면을 옆 사람에게 보여 주고 그 사람이 자기 브라우저 주소창에 옮겨 적게 합니다(강사가 교실 공유 문서를 준비했다면 거기에 붙여 넣습니다). 받은 링크를 새 탭에서 열고 가상 민원(이접수 / 010-0000-0008 / minwon@example.com / 생활 / 공원 벤치가 부서졌습니다.)을 접수합니다. 받은 사람은 구글 계정으로 로그인해야 열릴 수 있습니다. 공유 앱에서 쓰는 AI 사용량은 앱을 만든 사람 몫입니다.

    옆 사람이 접수한 민원이 내 시트 민원대장 연습에 쌓이고, 내 메일로 담당자 메일이 오면 성공입니다. 내 앱은 내 n8n으로 연결되어 있기 때문입니다.

    자주 하는 실수

    증상 옆 사람이 링크를 열었는데 "권한이 없습니다" 같은 화면이 떠요
    원인 공개 범위가 "나만 보기"로 남아 있거나, 받은 사람이 로그인하지 않았어요
    해결 Share 창에서 공개 범위를 다시 고르고, 받은 사람은 개인 구글 계정으로 로그인하세요

    증상 옆 사람이 접수했는데 내 시트에 안 쌓여요
    원인 앱 주소가 Test URL이거나, n8n을 고친 뒤 Publish하지 않았어요
    해결 아래 세 가지를 차례로 확인하세요. ① n8n 워크플로우 위쪽 Publish를 눌렀는지(고친 뒤 다시 눌러야 합니다) ② AI Studio Code 탭에서 Ctrl+F로 WEBHOOK_URL을 찾아 주소 안에 webhook-test가 아니라 /webhook/가 들어 있는지 ③ n8n Executions에 방금 시각 줄이 생겼는지. 그래도 안 되면 1일차 6교시 9단계 순서로 Production URL을 다시 넣습니다

    증상 Share 대신 Publish를 눌러 결제·게시 화면이 떠요
    원인 AI Studio의 두 버튼 이름이 비슷해요
    해결 창을 닫고(아무것도 게시하지 않습니다) 오른쪽 위 Share를 다시 누르세요

  3. 앱 코드에 비밀이 없는지 확인하기 내 앱의 Code 탭을 열고 코드 영역을 한 번 누른 뒤 Ctrl+F로 아래 글자를 하나씩 찾습니다.
    • AIza — 구글 API 키가 시작하는 글자. 이것이 나오면 문제입니다.
    • key, token — 여러 개 나오는 것이 보통입니다. 찾은 줄에서 따옴표 안에 알 수 없는 긴 영어·숫자 섞인 글자(20자 넘게)가 붙어 있는지만 봅니다. GEMINI_API_KEY처럼 이름만 있는 것은 정상입니다.
    • @gmail.com 같은 실제 이메일 주소, 실제 이름·전화번호

    AIza가 나오지 않고, key·token 옆에 긴 비밀 글자가 없고, 실제 이메일·이름이 없으면 성공입니다. WEBHOOK_URL의 n8n 주소는 보이는 것이 정상이지만, 공유받은 사람도 이 주소를 볼 수 있다는 점을 기억합니다.

    자주 하는 실수

    증상 코드에 AIza…로 시작하는 키가 보여요
    원인 앱을 고치다가 키를 직접 붙여 넣었어요
    해결 대화 입력창에 "코드에 적힌 API 키를 모두 지워 줘. 앱이 Gemini를 직접 부르는 코드가 있으면 그 기능도 지워 줘"라고 보내세요. 이미 공유했다면 그 키는 발급한 곳에서 지우고 새로 만듭니다

  4. 비밀값이 있는 곳 둘러보기
    1. AI Studio: 앱 화면의 Settings → Secrets를 엽니다. Gemini 키(GEMINI_API_KEY)는 AI Studio가 자동으로 관리합니다. 내가 따로 넣을 비밀값이 생기면 여기에 넣습니다.
    2. n8n: 왼쪽 메뉴의 Overview를 누르고 가운데 위쪽 탭 중 Credentials를 누릅니다. 구글 시트·Gmail·캘린더·Gemini·텔레그램 이름이 붙은 줄이 보이면 됩니다. 키와 토큰은 여기에만 있습니다.

    두 곳을 찾으면 성공입니다. 워크플로우를 Export JSON으로 내려받아도 자격 증명의 키 값은 파일에 들어가지 않습니다. 다만 노드에 직접 적은 주소·chat id·이메일은 들어가므로, 파일을 남에게 줄 때는 확인합니다.

  5. 실행 기록에 남은 값 보기 n8n 워크플로우 위쪽 Executions에서 방금 옆 사람이 접수한 실행을 열고, 민원 받기를 눌러 결과에 이름·연락처가 그대로 보이는지 확인합니다.

    실행 기록에 입력값이 남는 것을 봤으면 성공입니다.

  6. 저장 설정 찾아보기 (바꾸지 않음) 워크플로우 오른쪽 위 … → Settings를 열어 Save successful production executions 항목을 찾아봅니다. 지금은 바꾸지 않습니다(남은 교시에서 실행 기록으로 오류를 찾아야 합니다).

    항목을 찾았으면 창을 닫습니다. 실행 기록은 요금제에 따라 정해진 기간 보관되고, 운영 때는 이 항목을 Do not save로 바꾸는 것을 검토합니다.

  7. 점검표 쓰기 실제 적용 전 개인정보·보안 점검표를 열어(인쇄본이면 손으로) 내 서비스 기준으로 표시합니다. 오늘은 A~C 묶음만 표시하고(10분), D·E는 7교시 로드맵을 쓸 때 봅니다.

    각 줄의 "됨 / 아직 / 모름" 중 하나에 ○를 합니다. 교육 중에는 대부분 "아직"이나 "모름"인 것이 정상입니다. "모름"은 7교시 로드맵의 "협의" 단계로 옮겨 적습니다. A~C의 모든 줄에 ○가 하나씩 있으면 성공입니다.

확인 문제

객관식Q1. 공유 링크를 받은 사람이 할 수 있는 것은?

  1. 앱을 쓰고, 앱 코드도 볼 수 있다
  2. 앱만 쓸 수 있고 코드는 절대 볼 수 없다
  3. 내 n8n 워크플로우를 고칠 수 있다
  4. 내 구글 시트를 지울 수 있다
정답 확인

정답: ① 공유받은 사람은 코드를 볼 수 있습니다. 그래서 코드에 비밀값·개인정보를 넣지 않습니다.

단답형Q2. 앱 코드에 API 키를 적으면 왜 안 될까요?

정답 확인

정답: 공유받은 사람이 코드를 볼 수 있기 때문입니다. 키는 AI Studio Secrets(자동 관리)와 n8n 자격 증명에만 둡니다.

정리

  • 공유 링크는 보기 권한으로, 필요한 사람에게만 줍니다. 받은 사람은 코드를 볼 수 있습니다.
  • 비밀값은 AI Studio Secrets와 n8n 자격 증명에만 둡니다.
  • 입력값은 시트·메일·실행 기록·AI 서비스에 남습니다. 실제 개인정보는 기관 협의 뒤에만 넣습니다.
