PDF 공문 요약 앱

앱에서 PDF 공문을 올리면 n8n이 글자를 뽑아 Gemini로 요약하고, 앱·메일·텔레그램으로 돌려줍니다

학습목표

  • 앱에서 PDF 공문을 올리면 n8n이 받아 Gemini로 요약합니다.
  • 요약을 메일과 텔레그램으로 보냅니다.

왜 이 실습인가

용어 다시 보기 Webhook(외부 앱이 n8n을 부르는 주소), Test URL(시험할 때만 쓰는 주소), Production URL(게시한 뒤 앱에 넣는 진짜 주소), Publish(워크플로우를 게시하는 버튼), CORS(다른 주소의 앱이 불러도 되는지 정하는 허락 규칙), Respond to Webhook(부른 쪽에 답장을 보내는 노드), 표현식({{ }}로 앞 노드의 값을 가져오는 문장), 자격 증명(n8n이 내 계정을 대신 쓰도록 맡겨 둔 열쇠), 프롬프트(AI에게 시키는 일을 적은 문장), API 키(서비스를 쓸 수 있게 해 주는 비밀 번호표)

기초과정 P1에서는 n8n 입력 폼으로 공문을 올렸습니다. 이번에는 내가 만든 앱에서 올립니다. 민원 접수와 다른 점은 글자 대신 파일을 보낸다는 것 하나입니다.

순서노드하는 일
1공문 받기 (Webhook)앱이 보낸 PDF를 file이라는 이름으로 받음
2글자 뽑기 (Extract from File)PDF 안의 글자를 꺼냄(text)
3AI 공문 요약 (+ Gemini)목적·주요 내용·지원 사항·대상·일정 다섯 줄 요약
4앱에 답하기 / 요약 메일 / 텔레그램 알림앱에 요약 표시, 메일·텔레그램으로 전달
실습에는 가상 공문만 실제 공문·내부 문서는 올리지 않습니다. PDF 내용이 n8n 실행 기록과 AI 서비스(Gemini)에 남습니다. 아래 1단계의 가상 공문을 씁니다.
한 문장 요약 파일은 앱이 file이라는 이름으로 보내고, n8n은 그 이름으로 받아 글자를 뽑은 뒤 기존처럼 AI·메일·텔레그램으로 처리합니다. 사진으로 찍은(스캔) PDF는 글자가 없어 읽지 못합니다.

따라하기

빠른 길 n8n 쪽을 직접 만들지 않으려면 이 교안 끝 "완성본 가져오기"로 워크플로우를 가져온 뒤 7단계(앱 만들기)부터 합니다.
  1. 가상 공문 PDF 만들기 가상 공문을 열고 Ctrl+P → 대상(프린터)을 PDF로 저장으로 바꾸고 저장합니다. 파일 이름은 가상공문.pdf로 합니다.

    저장한 PDF를 열어 글자를 마우스로 끌어 고를 수 있으면 성공입니다(글자가 들어 있는 PDF라는 뜻입니다).

  2. 공문 받기 만들기 n8n에서 Create workflow → Webhook 노드를 추가하고 이름을 공문 받기로 고칩니다.
    • HTTP Method: POST, Path: gongmun-summary
    • Respond: Using 'Respond to Webhook' Node
    • Add Option → Allowed Origins (CORS): *
    Add Option 목록의 Field Name for Binary Data는 넣지 않습니다. 넣으면 파일 이름이 file이 아니라 다른 이름으로 바뀝니다.

    위쪽 주소가 …/gongmun-summary로 끝나면 성공입니다.

  3. 글자 뽑기 잇기 공문 받기 오른쪽 + → Extract from File을 고르고 이름을 글자 뽑기로 고칩니다. Operation: Extract From PDF, Input Binary Field: file(기본값 data를 지우고 적습니다).

    Input Binary Field에 file이 보이면 성공입니다.

  4. AI 공문 요약 잇기 글자 뽑기 오른쪽 + → Basic LLM Chain, 이름 AI 공문 요약. Source for Prompt (User Message)를 Define below로 바꾸고 Expression으로 아래를 붙여 넣습니다. 아래 Model 자리에 Google Gemini Chat Model을 붙이고 Gemini 자격 증명과 models/gemini-3.8-flash를 고릅니다. 
    다음 공문서를 5줄 이내로 핵심만 요약하세요.

  6. Test URL 복사해 두기 공문 받기를 열어 Test URL을 복사합니다. 7단계에서 씁니다.
  7. 앱 만들기 AI Studio(aistudio.google.com/apps)에서 새 앱을 만듭니다. PDF 공문 요약 앱 주문서의 "1) 새 앱 만들기" 글을 붙여 넣어 보냅니다. 이어서 "2) 주소 넣기" 문장을 입력창에 먼저 붙여 넣고, {Production URL} 자리를 지운 뒤 6단계의 Test URL을 따옴표 사이에 붙여 넣어 보냅니다(시험이 끝나면 9단계에서 Production URL로 바꿉니다).

    파일 고르는 칸과 요약하기 버튼이 보이고, Code 탭의 WEBHOOK_URL에 webhook-test 주소가 보이면 성공입니다.

  8. 시험하기
    1. 앱에서 1단계의 가상공문.pdf를 고릅니다. 아직 누르지 않습니다.
    2. n8n 캔버스 아래 Execute workflow를 누릅니다(2분 동안 기다립니다).
    3. 앱에서 요약하기를 누릅니다. 30초쯤 걸릴 수 있습니다.

    앱에 목적·주요 내용·지원 사항·대상·일정 요약이 보이고, 메일(과 텔레그램)이 오면 성공입니다. 공문 받기 결과의 Binary 탭에 file이 보입니다.

  9. Publish하고 Production URL로 바꾸기 Publish → 확인 창의 Publish. 공문 받기의 Production URL을 7단계와 같은 방법(문장 먼저 → 주소 나중)으로 앱의 WEBHOOK_URL에 넣습니다.

    n8n에서 아무것도 누르지 않고 앱에서 PDF를 올려 요약이 오면 완성입니다.

파일 보내기가 끝내 안 될 때(심화) 앱이 파일을 글자(base64)로 바꿔 JSON에 담아 보내고, n8n에서 Convert to File(Move Base64 String to File)로 다시 파일로 바꾸는 방법도 있습니다. 앱이 글자 앞의 data:…;base64, 머리말을 떼야 해서 더 까다롭습니다. 강사와 함께 해 봅니다.

정리

  • 파일은 앱이 file이라는 이름으로 보내고, n8n은 Extract from File로 글자를 뽑습니다.
  • 그 뒤는 민원 접수와 같습니다 — AI 요약, 앱에 답하기(맨 위), 메일, 텔레그램.
  • 스캔 PDF는 글자가 없어 요약하지 못합니다. AI 요약은 초안이므로 원문과 대조합니다.

완성본 가져오기(Import)

  1. 파일 내려받기 워크플로우 내려받기 opt-pdf.json
  2. n8n에서 가져오기 Create workflow → 오른쪽 위 … → Import → From file. 노드 일곱 개가 보이면 성공입니다.
  3. 자격 증명 다시 연결하기 Google Gemini Chat Model(Gemini API 키), 요약 메일(Gmail), 텔레그램 알림(봇 토큰, 없으면 이 노드를 지웁니다)에서 내 자격 증명을 고릅니다.
  4. 자리표시자 바꾸기 요약 메일의 To: 본인이메일@example.com → 내 Gmail 주소. 텔레그램 알림의 Chat ID: 여기에_본인_채팅_ID → 내 chat id. Gemini Model: models/gemini-3.8-flash 다시 고르기.
  5. 앱 만들고 연결하기 따라하기 1·6·7·8·9단계를 합니다. 앱에서 PDF를 올려 요약이 오면 완성입니다.
