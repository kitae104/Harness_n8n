종류별 담당자 나누기, 텔레그램 알림, 그리고 민원인이 스스로 보는 처리 상태 조회 화면

강사 준비·확인이 교시에서 수업 전에 강사가 할 일입니다. 수강생용 내용이 아니며, 준비가 끝나면 python scripts/strip_inotes.py로 모두 지웁니다.
  • A·C를 10:35까지(B 텔레그램 선택), 트리거 둘일 때 Execute workflow → from 상태 조회(F123), 교육망에서 api.telegram.org 접속
  • 이 교안 안의 강사 확인 표시 2곳(노란 점선 상자)
  • 캡처 3장 촬영 → assets/img/에 넣고 python scripts/apply_captures.py
  • 확인이 끝나면 docs/instructor-checklist.md의 이 교시 행에 체크

학습목표

  • If 노드로 민원 유형별 담당자를 나눕니다.
  • 텔레그램으로 접수 알림을 보냅니다.
  • 접수번호로 처리 상태를 조회하는 GET Webhook과 조회 화면을 만듭니다.

왜 이 단계가 필요한가

지금은 모든 민원 메일이 한 담당자에게 갑니다. 실제로는 생활 민원과 쓰레기 수거 민원의 담당자가 다릅니다. 또 급한 민원은 메일보다 메신저가 빨리 눈에 띕니다. 그리고 민원인은 "내 민원 어떻게 됐나?"를 전화로 묻습니다. 이번 시간에는 이 세 가지를 해결해 민원 접수 서비스를 완성합니다.

더하는 것노드하는 일
담당자 나누기생활인가? (If)종류가 "생활"이면 담당자 메일(정담당), 아니면 일반 담당자 메일(강처리)
메신저 알림텔레그램 알림부서방(실습에서는 내 텔레그램)에 새 민원 알림
처리 상태 조회상태 조회 → 접수번호로 찾기 → 찾았나? → 답하기 둘앱에서 접수번호를 넣으면 처리상태·담당자·처리마감을 돌려줌

조회 흐름은 같은 워크플로우 안에 두 번째 입구를 하나 더 만드는 것입니다. 접수는 minwon 주소로 편지를 보내고(POST), 조회는 minwon-status 주소 뒤에 ?no=접수번호를 붙여 묻습니다(GET, 1일차 3교시에 주소창으로 불렀던 방식). 이 입구도 Webhook(외부 앱이 n8n을 부르는 주소)이고, 답은 Respond to Webhook(부른 쪽에 답장을 보내는 노드)으로 돌려줍니다. 앱이 부르므로 CORS(다른 주소의 앱이 불러도 되는지 정하는 허락 규칙) 명단이 필요합니다.

한 문장 요약 If로 길을 나누고, 텔레그램으로 알리고, 두 번째 입구(GET)로 조회에 답하면 — 접수부터 알림, 조회까지 이어지는 서비스가 완성됩니다.
강사 메모 이 교시의 결과(workflows/d2-p2.json)가 과정 전체의 최종 완성본이며, 1일차 1교시 시연에 이 파일을 씁니다.

따라하기

준비 1교시 워크플로우(노드 열 개)를 엽니다. 없으면 2일차 1교시 완성본 가져오기로 먼저 맞춥니다.

시간 기준: 이 교시는 A → C 순서로 합니다. B(텔레그램 알림)는 선택이며 C를 모두 마친 뒤 시간이 남으면 합니다. 10시 25분까지 A를 못 마쳤으면 A는 건너뛰고 C부터 합니다. 10시 35분까지 5단계를 못 마쳤으면 이 교시 끝 "완성본 가져오기"로 맞추고(10분쯤 걸립니다), 조회 화면(8단계)은 쉬는 시간에 마칩니다.

A. 종류별 담당자 나누기

  1. 생활인가? 끼워 넣기 시트에 기록과 담당자 메일 사이 선에 마우스를 올리면 나오는 +를 누르고 If를 고릅니다. 이름을 생활인가?로 고칩니다. Conditions에서 왼쪽 칸에 마우스를 올려 Expression을 누르고 {{ $json['종류'] }}, 가운데는 is equal to, 오른쪽 칸에 생활을 적습니다. 이 {{ }}는 앞 노드의 값을 가져오는 표현식(앞 노드의 값을 가져오는 문장)입니다. 기초과정 07강의 "생활인가?"와 같은 조건입니다.

    생활인가?의 true 갈래(위)가 담당자 메일로 이어져 있으면 성공입니다. 이어져 있지 않으면 true 점에서 담당자 메일로 끌어 잇습니다.

  2. 일반 담당자 메일 만들기 담당자 메일을 한 번 눌러 고르고 Ctrl+C, 빈 곳을 누르고 Ctrl+V로 복사본을 만듭니다. 이름을 일반 담당자 메일로 고칩니다. 생활인가?의 false 점(아래)에서 일반 담당자 메일로 끌어 잇습니다.

    일반 담당자 메일의 Subject를 지우고(Expression 상태 유지) 아래 한 줄을 붙여 넣어 두 메일을 구분합니다.

    [{{ $json.종류 }}·강처리] 민원 접수 {{ $json.접수번호 }}

    생활인가?에서 true → 담당자 메일, false → 일반 담당자 메일로 갈라지면 성공입니다. 실습에서는 두 메일 모두 내 주소로 옵니다.

C. 처리 상태 조회 — 두 번째 입구

  1. 상태 조회 만들기 캔버스 아래쪽 빈 곳을 한 번 누르고, 오른쪽 위 +(노드 추가)를 눌러 Webhook을 추가합니다. 이름을 상태 조회로 고칩니다.
    • HTTP Method: GET
    • Path: 글자를 모두 지우고 minwon-status
    • Respond: Using 'Respond to Webhook' Node
    • Add option → Allowed Origins (CORS): * — 체크리스트 1번, 이 입구도 앱이 부릅니다

    위쪽 주소가 …/minwon-status로 끝나면 성공입니다.

  2. 접수번호로 찾기 잇기 상태 조회 오른쪽 + → Google Sheets → Get Row(s). 이름을 접수번호로 찾기로 고칩니다.
    • Credential: 구글 시트 자격 증명(n8n이 내 계정을 대신 쓰도록 맡겨 둔 열쇠)
    • Document: From list에서 민원대장 연습, Sheet: 시트1(내 탭 이름)
    • Filters → Add Filter: Column = 접수번호, Value(Expression) = {{ $json.query.no }}
    • Add option → Return only First Matching Row 켜기
    • Settings 탭 → Always Output Data 켜기
    query.no는 주소 뒤 ?no=에 붙여 보낸 접수번호입니다.

    Filters에 한 줄, Always Output Data가 켜져 있으면 성공입니다.

  3. 찾았나?와 답하기 둘
    1. 접수번호로 찾기 오른쪽 + → If, 이름 찾았나?. 조건: 왼쪽 {{ $json['접수번호'] }}(Expression), 가운데 is not empty.
    2. true 점 오른쪽 +를 누르고 Respond to Webhook을 고릅니다. 이름을 조회 결과 답하기로 고치고 Respond With를 JSON으로 바꿉니다. Response Body에 마우스를 올려 Expression을 누르고, Ctrl+A, Delete로 원래 글을 지운 뒤 아래 [조회 결과 답하기] 줄을 붙여 넣습니다.
    3. false 점에서 같은 방법으로 없음 답하기를 만들고 [없음 답하기] 줄을 붙여 넣습니다.

    [조회 결과 답하기]

    {{ { "찾음": true, "접수번호": $json['접수번호'], "처리상태": $json['처리상태'], "담당자": $json['종류'] === '생활' ? '정담당' : '강처리', "처리마감": DateTime.fromISO($json['등록일']).plus({ days: 3 }).toFormat('yyyy-MM-dd') } }}

    [없음 답하기]

    {{ { "찾음": false, "오류": "접수번호를 찾을 수 없습니다" } }}
    긴 줄은 세 번 빠르게 눌러 한 줄 전체를 고른 뒤 복사합니다(인쇄본은 줄이 잘리므로 웹 교안에서 복사). 처리마감은 등록일에 3일을 더한 날이며, 법정 처리 기한이 아닙니다.

    찾았나?에서 두 답하기로 갈라지면 성공입니다.

  4. 주소창으로 먼저 시험하기 시트 민원대장 연습에서 어제 받은 접수번호 하나(예: 2026-0925-001)를 복사해 둡니다.
    1. 캔버스 아래 Execute workflow 버튼 오른쪽의 작은 화살표를 눌러 from 상태 조회를 고르고 버튼을 누릅니다(입구가 둘이라 어느 입구를 기다릴지 고릅니다).
    2. 상태 조회의 Test URL(만드는 중에 시험할 때 쓰는 주소)을 복사해 새 탭 주소창에 붙이고, 끝에 ?no=와 접수번호를 이어 씁니다.
    3. 2분 안에 Enter를 누릅니다.
    https://(내 n8n 주소)/webhook-test/minwon-status?no=2026-0925-001

    브라우저에 "찾음": true와 처리상태·담당자·처리마감이 보이면 성공입니다.

    시간이 남으면: Execute workflow를 다시 눌러 from 상태 조회로 기다리게 한 뒤, 주소 끝 번호만 2026-0101-999로 바꿔 Enter를 누릅니다. "찾음": false가 보이면 성공입니다.
    자주 하는 실수

    증상 브라우저에 The requested webhook "…" is not registered. 같은 영어 글이 떠요
    원인 시험 버튼을 누르지 않았거나, 누른 뒤 2분이 지났거나, 이미 한 번 받은 뒤예요
    해결 Execute workflow 옆 화살표 → from 상태 조회를 다시 누르고 2분 안에 주소창에서 Enter를 누르세요

    증상 있는 번호인데 "찾음": false가 나와요
    원인 번호를 잘못 옮겨 적었거나, Filters의 Column이 접수번호가 아니에요
    해결 시트에서 접수번호를 복사해 붙이고, Column을 다시 고르세요

    증상 브라우저가 한참 기다리다 빈 화면이 나와요
    원인 접수번호로 찾기의 Always Output Data가 꺼져 있어 답하기까지 가지 못했어요
    해결 Settings 탭에서 켜고 다시 시험하세요

  5. Publish하고 담당자 나누기 확인하기 위쪽 Publish(워크플로우를 게시해 주소가 항상 동작하게 하는 버튼) → 확인 창의 Publish.
    개인정보 주의 가상 값만 넣습니다.
    앱에서 가상 민원 두 건을 접수합니다: ① 최주민 / 010-0000-0006 / minwon@example.com / 생활 / 가로등이 깜빡입니다. ② 박시민 / 010-0000-0007 / minwon@example.com / 음식물 / 수거함이 넘칩니다. ①의 접수번호를 메모해 둡니다(9단계에서 조회합니다).

    ①은 원래 제목([생활] 민원 접수 …), ②는 [음식물·강처리] 제목으로 메일이 오면 성공입니다.

  6. 앱에 조회 화면 만들기
    1. 아래 글을 AI Studio 대화 입력창에 먼저 붙여 넣습니다. 아직 보내지 않습니다. 입력창에서 {조회용 Production URL} 글자를 중괄호까지 지웁니다(따옴표는 남김).
    2. n8n에서 상태 조회를 열고 위쪽에서 Production URL(게시한 뒤 앱에 넣는 진짜 주소)을 골라 주소를 복사합니다(끝이 webhook/minwon-status, ?no=는 넣지 않음).
    3. AI Studio로 돌아와 따옴표 사이에 붙여 넣고 보냅니다.
    이 앱에 "처리 상태 조회" 화면을 하나 더 만들어 줘. 맨 위에 "민원 접수"와 "처리 상태 조회" 두 개의 탭(또는 버튼)을 두고 오갈 수 있게 해 줘.

[처리 상태 조회 화면]
- 입력 칸 1개: 접수번호 (안내 글: 예) 2026-0925-001)
- "조회하기" 버튼
- 코드 맨 위에 STATUS_URL 이라는 상수를 새로 만들고 값은 "{조회용 Production URL}"로 해 줘.
- 조회하기를 누르면 STATUS_URL 뒤에 ?no=입력한접수번호 를 붙여 GET 방식으로 불러 줘. (접수번호는 주소에 넣을 수 있게 인코딩해 줘)
- 응답 JSON의 "찾음"이 true면 접수번호, 처리상태, 담당자, 처리마감을 표로 보여 줘.
- "찾음"이 false면 "오류" 글을 빨간색으로 보여 줘.
- 응답이 오지 않으면 "조회하지 못했습니다. 잠시 뒤 다시 시도해 주세요."를 보여 줘.

[바꾸지 말 것]
- 민원 접수 화면, 입력 칸 이름, WEBHOOK_URL은 그대로 둬.

    AI의 답이 끝나고 미리보기 위쪽에 민원 접수와 처리 상태 조회 두 탭(또는 버튼)이 보이면 성공입니다.

  7. 앱에서 조회해 보기 앱 위쪽 처리 상태 조회로 가서 7단계에서 메모한 접수번호를 넣고 조회하기를 누릅니다.

    처리상태 접수, 담당자 정담당, 처리마감(등록일 + 3일)이 표로 보이면 성공입니다.

    시간이 남으면: 시트에서 그 줄의 처리상태를 처리중으로 고친 뒤 다시 조회해, 바뀐 상태가 보이는지 확인합니다.
    자주 하는 실수

    증상 "조회하지 못했습니다"가 떠요
    원인 상태 조회의 Allowed Origins (CORS)가 비었거나, STATUS_URL에 Test URL을 넣었거나, Publish 전이에요
    해결 아래 체크리스트를 차례로 보세요. 모두 맞는데도 막히면 조회 화면 문장 모음의 "막혔을 때" 문장을 보냅니다

B. 텔레그램 알림 (선택 — C를 마친 뒤 시간이 남으면)

  1. 텔레그램 알림 추가하기 시트에 기록의 오른쪽 점을 누른 채 맨 아래 빈 곳으로 끌었다가 놓고, Telegram을 검색해 Send a text message를 고릅니다. 이름을 텔레그램 알림으로 고칩니다. 강사 확인 F200연결된 출력 점을 끌어 빈 곳에 놓으면 새 가지가 생기는지, Gmail 동작 이름 Send a message

    새 가지는 캔버스 맨 아래에 둡니다(AI 가지가 맨 위여야 앱이 먼저 답을 받습니다).

  2. 봇 연결하고 알림 글 넣기
    • Credential: Create new credential → Access Token에 봇 토큰을 붙여 넣고 저장(Base URL은 그대로)
    • Chat ID: 내 chat id(숫자)
    • Text(Expression): 아래 글
    • Additional Fields → Append n8n Attribution 끄기
    새 민원이 접수되었습니다
접수번호: {{ $json.접수번호 }}
종류: {{ $json.종류 }}
접수자: {{ $json.이름 }}
    알림에는 상세 설명을 넣지 않습니다. 민원인이 쓴 글에 _, * 같은 기호가 있으면 텔레그램 전송이 실패할 수 있고, 메신저에 개인정보가 덜 남게 하기 위해서입니다.

    다시 Publish하고 앱에서 가상 민원을 한 건 접수했을 때 텔레그램에 알림이 오면 성공입니다.

    텔레그램 봇이 없거나 토큰을 모를 때
    • 봇은 있는데 토큰을 모를 때: 텔레그램에서 @BotFather 대화방을 열고 /mybots → 내 봇 이름 → 토큰 보기를 누르면 다시 보입니다. 강사 확인 F202BotFather에서 기존 봇 토큰을 다시 보는 메뉴(/mybots → 봇 → API Token) 표기
    • 봇이 없을 때: @BotFather에게 /newbot을 보내고, 봇 이름과 끝이 bot인 사용자 이름을 차례로 보내면 토큰을 줍니다. 만든 봇을 열어 아무 말이나 한 번 보냅니다(봇은 먼저 말을 걸 수 없습니다).
    • chat id: 브라우저 주소창에 https://api.telegram.org/bot(토큰)/getUpdates를 넣으면 "chat":{"id":숫자가 보입니다. 그 숫자가 chat id입니다.
    자세한 그림은 기초과정 2일차 준비물에 있습니다. 토큰은 비밀번호처럼 다룹니다.
    자주 하는 실수

    증상 메일은 오는데 텔레그램 알림이 없어요
    원인 chat id가 틀렸거나, 봇에게 먼저 말을 걸지 않았거나, 고친 뒤 Publish하지 않았어요
    해결 봇 대화방에서 아무 말이나 보낸 뒤 chat id를 다시 확인하고, Publish를 다시 누르세요

조회 Webhook 체크리스트

  1. 상태 조회의 Allowed Origins (CORS)가 *인가요?
  2. HTTP Method가 GET, Respond가 Using 'Respond to Webhook' Node인가요?
  3. 접수번호로 찾기의 Always Output Data가 켜져 있나요?
  4. 앱의 STATUS_URL이 /webhook/minwon-status로 끝나는 Production URL인가요?
  5. 노드를 고친 뒤 다시 Publish했나요?

확인 문제

객관식Q1. 음식물 민원은 어느 메일로 가나요?

  1. 담당자 메일(true 갈래)
  2. 일반 담당자 메일(false 갈래)
  3. 둘 다
  4. 텔레그램만
정답 확인

정답: ② "생활"이 아니므로 생활인가?의 false 갈래로 갑니다. 텔레그램 알림은 종류와 상관없이 따로 갑니다.

단답형Q2. 조회 주소 뒤에 붙이는 글자는? (접수번호가 2026-0925-003일 때)

정답 확인

정답: ?no=2026-0925-003

정리 — 민원 접수 서비스 완성

접수: 앱 → 민원 받기 → 민원 정리 → 오늘 접수 조회 → 접수번호 만들기 → 시트에 기록
                                                          ├→ AI 안내문 작성 → 앱에 답하기(접수번호·안내문)
                                                          ├→ 생활인가? → 담당자 메일 / 일반 담당자 메일
                                                          ├→ 처리 마감 일정(캘린더)
                                                          └→ 텔레그램 알림
조회: 앱 → 상태 조회 → 접수번호로 찾기 → 찾았나? → 조회 결과 답하기 / 없음 답하기
  • If는 조건에 따라 길을 둘로 나눕니다(true 위, false 아래).
  • 한 워크플로우에 입구(Webhook)를 둘 둘 수 있습니다. 앱이 부르는 입구마다 CORS 명단을 적습니다.
  • 다음: 3교시에는 이 서비스를 동료에게 공유하고, 비밀값과 개인정보를 점검합니다.

완성본 가져오기(Import)

이 파일을 가져오면 n8n 쪽이 과정 최종 완성본(노드 열여덟 개, 입구 둘)이 됩니다.

먼저: 1교시 워크플로우를 Unpublish하세요 1교시에 Publish한 워크플로우를 열어 Publish 오른쪽 작은 화살표를 눌러 목록 맨 아래 Unpublish를 누르고, 뜨는 창에서 다시 Unpublish를 누릅니다. 같은 주소(minwon)를 쓰는 Webhook은 하나만 동작할 수 있습니다.
  1. 파일 내려받기 워크플로우 내려받기 d2-p2.json
  2. n8n에서 가져오기 Create workflow → 오른쪽 위 … → Import → From file. 노드 열여덟 개가 보이면 성공입니다.
  3. 자격 증명 다시 연결하기
    • 오늘 접수 조회, 시트에 기록, 접수번호로 찾기 — 구글 시트용
    • Google Gemini Chat Model — Gemini API 키(Gemini를 쓸 수 있게 해 주는 비밀 번호표)
    • 담당자 메일, 일반 담당자 메일 — Gmail용
    • 처리 마감 일정 — 캘린더용
    • 텔레그램 알림 — 텔레그램 봇 토큰

    텔레그램 알림에 고를 자격 증명이 없으면(봇이 없거나 B를 건너뛴 경우) 그 노드를 한 번 눌러 고르고 Delete로 지웁니다. 나머지는 그대로 동작합니다. 처리 마감 일정에 캘린더 자격 증명이 없으면 1교시 6단계처럼 새로 만듭니다.

  4. 자리표시자 바꾸기
    • 시트 노드 세 개의 Document: 왼쪽 목록을 From list로 바꾸고 민원대장 연습(여기에_본인_시트_ID 대신), Sheet: 내 탭 이름
    • 메일 두 개의 To: 본인이메일@example.com → 내 Gmail 주소
    • 텔레그램 알림의 Chat ID: 여기에_본인_채팅_ID → 내 chat id
    • 처리 마감 일정의 Calendar: 목록에서 내 캘린더, Gemini Model: models/gemini-3.8-flash
  5. Publish하고 앱 확인하기 Publish를 누릅니다. 앱의 WEBHOOK_URL은 그대로 둡니다(앱에서 접수 오류가 나면 민원 받기의 Production URL을 앱에 다시 넣습니다 — 1일차 6교시 9단계). 조회 화면이 없으면 따라하기 8단계로 만듭니다. 접수와 조회가 모두 되면 복구 완료입니다.
