앱 ↔ n8n 연동 ①

앱에 n8n 주소를 넣고, 앱에서 접수한 민원이 구글 시트에 한 줄로 쌓이게 합니다

학습목표

  • 앱에 n8n Production URL을 넣어 접수 데이터를 보낼 수 있습니다(Test URL로 먼저 시험한 뒤).
  • 받은 데이터가 구글 시트에 한 줄로 기록되는 것을 확인합니다.

왜 이 단계가 필요한가

지금까지 세 조각을 따로 만들었습니다. 2교시의 일하는 워크플로우, 3교시의 초인종인 Webhook(외부 앱이 n8n을 부르는 주소), 4·5교시의 창구 화면인 앱입니다. 이번 시간에 이 셋을 이어 붙여, 앱에서 누른 접수가 시트까지 가게 합니다.

순서누가무엇을
1앱(AI Studio)접수하기를 누르면 다섯 값을 봉투에 담아 n8n 주소로 보냅니다(이렇게 봉투에 담아 보내는 방식을 POST라고 부릅니다)
2민원 받기 (Webhook)봉투를 받습니다. 값은 봉투 안쪽 body에 들어 있습니다
3민원 정리 (Edit Fields)봉투에서 값을 꺼내 2교시와 같은 모양(이름, 연락처 …)으로 정리합니다
4시트에 기록2교시에 쓰던 노드를 그대로 가져와 한 줄을 적습니다

이번에는 앱 화면(AI Studio 주소)이 n8n(다른 주소)을 부르기 때문에, 브라우저가 "이 앱이 불러도 되나?"를 검사합니다. 이것이 CORS(다른 주소의 앱이 n8n을 불러도 되는지 정하는 허락 규칙)입니다. 3교시에 미리 적어 둔 허락 명단(Allowed Origins (CORS))이 오늘 처음으로 쓰입니다.

오늘의 순서: 시험 먼저, 그다음 사용 주소는 두 개입니다. 먼저 Test URL(만드는 중에 시험할 때 쓰는 주소)을 앱에 넣어 한 번 보내 보고, 잘 되면 Publish(워크플로우를 게시해 주소가 항상 동작하게 하는 버튼)를 누른 뒤 Production URL(워크플로우를 게시한 뒤 앱에 넣는 진짜 주소)로 바꿉니다.
앱이 보내는 값민원 정리가 만드는 값시트 열
body의 이름이름이름
body의 연락처연락처연락처
body의 이메일이메일이메일
body의 종류종류종류
body의 상세설명상세설명상세설명

따라하기

준비: 탭 세 개를 열어 두세요 ① n8n, ② AI Studio(4·5교시 앱), ③ 구글 시트 민원대장 연습(2교시에 만든 시트). 이번 시간에는 세 탭을 오가며 작업합니다. 시작 전에 AI Studio 미리보기에서 가상 값을 넣고 접수하기를 눌러 보세요. "아직 접수 창구와 연결되지 않았습니다"가 뜨면 준비된 것입니다. 오류 글이 뜨면 5교시 오류 신고 문장으로 먼저 고칩니다.

시간 기준: 15시 35분까지 7단계(시트 확인)를 마치지 못했으면 이 교시 끝 "완성본 가져오기" 1~5단계로 맞춘 뒤 10단계(실제 접수)를 함께 합니다. 늦어도 7교시에 따라잡을 수 있습니다.

개인정보 주의 앱에는 교안의 가상 값만 넣습니다. 내 이름·전화번호를 넣으면 시트와 n8n 실행 기록에 그대로 남습니다. Production URL은 다른 사람에게 알리지 않습니다.
  1. 새 워크플로우에 민원 받기 만들기 n8n에서 Create workflow를 누르고, 3교시처럼 Webhook 노드를 추가합니다. 설정 창에서 아래처럼 바꿉니다.
    • HTTP Method: POST (앱은 POST로 보냅니다)
    • Path: 들어 있는 글자를 모두 지우고 minwon만 적습니다
    • Add Option → Allowed Origins (CORS): *
    • Respond: 기본값 그대로(7교시에 바꿉니다)
    설정 창 맨 위의 노드 이름(Webhook)을 한 번 눌러 민원 받기로 고치고 Enter를 누릅니다. n8n은 바꾼 내용을 저절로 저장합니다. 따로 저장 버튼을 찾지 않아도 됩니다.

    설정 창 위쪽 주소가 …/webhook-test/minwon으로 끝나면 성공입니다.

  2. 앱에 Test URL 넣기 주소를 나중에 복사해야 지워지지 않습니다. 아래 순서를 지킵니다.
    1. 아래 문장을 복사해 AI Studio 대화 입력창에 붙여 넣습니다. 아직 보내지 않습니다.
    2. 입력창에서 {Test URL} 글자(중괄호 포함)를 끌어서 고르고 지웁니다. 따옴표 " "는 남깁니다.
    3. n8n 탭의 민원 받기 설정 창 위쪽에서 Test URL이 골라져 있는지 보고, 그 주소를 복사합니다.
    4. AI Studio 탭으로 돌아와 따옴표 사이를 한 번 누르고 Ctrl+V를 누른 뒤 보냅니다.
    코드 맨 위 WEBHOOK_URL 값을 "{Test URL}"로 바꿔 줘. 다른 부분은 바꾸지 마.

    AI의 답이 끝나고 미리보기가 다시 나타나면, Code 탭에서 Ctrl+F로 WEBHOOK_URL을 찾습니다(4교시 5단계와 같음). 따옴표 안에 webhook-test가 들어간 주소가 보이면 성공입니다. 확인했으면 미리보기 탭으로 돌아옵니다.

  3. 첫 시험 — 앱에서 보내 보기 Listen for test event를 누르면 n8n은 2분 동안만 기다립니다. 그래서 앱 입력을 먼저 끝내 둡니다.
    1. AI Studio 미리보기에 가상 값(홍길동 / 010-1234-5678 / minwon@example.com / 생활 / 보도블록이 깨져 있습니다.)을 넣고 동의에 체크합니다. 아직 누르지 않습니다.
    2. n8n 탭에서 민원 받기를 열고 Listen for test event를 누릅니다.
    3. 곧바로 AI Studio 탭으로 와서 접수하기를 누릅니다. 2분이 지났으면 2번부터 다시 합니다.

    민원 받기 설정 창 오른쪽 OUTPUT에서 body를 눌러 펼쳤을 때 다섯 값이 보이면 성공입니다. 앱이 n8n을 부르는 데 성공했다는 뜻이므로 CORS도 통과한 것입니다.

    성공 여부는 n8n 쪽으로 판단합니다. n8n에 다섯 값이 보였다면 앱 화면에 무엇이 뜨든(빈 접수번호, 실패 문구 모두) 이 단계는 성공입니다. 앱 화면의 답은 7교시에 고칩니다.

    자주 하는 실수

    증상 n8n에 아무것도 오지 않아요
    원인 아래 셋 중 하나일 때가 많아요
    해결 차례로 확인하세요 — ① Listen for test event를 누르고 2분 안에 보냈나요? ② WEBHOOK_URL에 webhook-test 주소가 따옴표 안에 정확히 들어갔나요? ③ Allowed Origins (CORS)가 *인가요? 확인한 뒤 위 1~3을 다시 합니다

    세 가지가 다 맞는데도 n8n에 값이 오지 않으면 브라우저가 앱에서 n8n을 직접 부르는 것을 막는 경우입니다. AI Studio 대화 입력창에 아래 글을 보내 n8n 호출을 앱의 서버 쪽에서 하게 바꾼 뒤, 다시 1~3을 합니다. "서버 쪽 코드"는 AI에게 하는 말입니다. 뜻을 몰라도 그대로 보내면 됩니다. 
    접수하기를 누르면 "접수하지 못했습니다"가 떠. n8n 주소 호출은 서버 쪽 코드에서 하도록 바꿔 줘. WEBHOOK_URL 값과 보내는 JSON의 키 이름은 바꾸지 마.
    그래도 안 되면 손을 들어 강사에게 알리고, 이 교시 끝 "완성본 가져오기"로 n8n 쪽을 먼저 맞춰 둡니다.
  4. 민원 정리 노드 만들고 이름 고치기 민원 받기 오른쪽의 +를 누르고 Edit Fields (Set)를 고릅니다. 설정 창 맨 위 노드 이름을 한 번 눌러 민원 정리로 고칩니다.

    왼쪽 입력 목록에서 body를 펼치고, 이름·연락처·이메일·종류·상세설명을 하나씩 가운데 Drag input fields here 자리로 끌어다 놓습니다.

    끌어다 놓으면 왼쪽 이름 칸이 body['이름']처럼 들어갑니다. 다섯 줄 모두 왼쪽 이름 칸만 눌러 이름, 연락처처럼 글자만 남기고, 오른쪽 값은 그대로 둡니다.

    다섯 줄의 왼쪽 이름이 이름~상세설명이고, 오른쪽 값이 {{ $json.body['이름'] }} 모양이면 성공입니다. 이 {{ }}는 2교시에 복습한 표현식(앞 노드의 값을 가져오는 문장)입니다.

    왼쪽이 비어 있어 끌어올 값이 없으면(3단계를 못 한 경우), Add Field를 눌러 왼쪽 칸에 이름, 오른쪽 칸에 {{ $json.body['이름'] }}을 직접 적습니다. 다섯 개 모두 같은 방법으로 넣습니다.
    자주 하는 실수

    증상 왼쪽 이름을 body['이름'] 그대로 두었어요
    원인 이름을 고치지 않으면 값이 다시 body 안으로 들어가, 시트 노드가 이름을 찾지 못해요
    해결 다섯 줄의 왼쪽 이름을 이름·연락처·이메일·종류·상세설명으로 고치세요

  5. 2교시의 시트에 기록 복사해 오기
    1. 브라우저 위쪽 n8n 탭 옆 +로 새 탭을 열고, n8n 첫 화면에서 2교시 워크플로우(d1-p2 n8n 핵심 복습 또는 내가 붙인 이름)를 엽니다.
    2. 시트에 기록을 한 번 눌러 테두리가 생기면 Ctrl+C를 누릅니다. 이 탭에서는 아무것도 바꾸지 않고 탭 오른쪽 X로 닫습니다.

    2교시 워크플로우를 찾지 못하면, 이 교시 끝 "완성본 가져오기" 1~4단계로 새 워크플로우를 만든 뒤 7단계부터 그 워크플로우에서 이어 갑니다(세 노드가 이미 이어져 있습니다).

  6. 붙여 넣고 잇기 지금 만들던 워크플로우 탭에서 빈 캔버스를 한 번 누르고 Ctrl+V를 누릅니다. 민원 정리의 오른쪽 점에서 시트에 기록의 왼쪽 점으로 끌어 선을 잇습니다.

    세 노드가 선으로 이어지면 성공입니다. 시트에 기록을 열어 Credential 칸에 2교시에 만든 구글 시트 자격 증명(n8n이 내 구글 계정을 대신 쓰도록 맡겨 둔 열쇠)이 보이는지, Document가 민원대장 연습인지 확인합니다. Credential이 비어 있으면 목록에서 내 구글 시트 자격 증명을 고릅니다.

  7. 두 번째 시험 — 시트까지 확인하기
    1. 앱의 새 민원 접수를 눌러 입력 화면으로 돌아갑니다.
    2. 김민원 / 010-0000-0002 / minwon@example.com / 음식물 / 매주 화요일 음식물 쓰레기 수거가 되지 않고 있습니다. 를 넣고 동의에 체크합니다. 아직 누르지 않습니다.
    3. n8n 탭에서 캔버스 아래쪽 Execute workflow를 누릅니다. 이번에도 2분 동안 기다립니다.
    4. AI Studio 탭에서 접수하기를 누릅니다.

    세 노드 모두 초록색이 되고 시트 민원대장 연습에 김민원 줄이 새로 생기면 성공입니다.

    자주 하는 실수

    증상 시트에 줄은 생겼는데 칸이 비어 있어요
    원인 민원 정리의 왼쪽 이름이 시트 머리글과 달라요(예: body['이름'], 상세 설명)
    해결 민원 정리의 다섯 이름을 이름·연락처·이메일·종류·상세설명으로 맞추세요

  8. Publish하기 화면 위쪽 Publish → 뜨는 창의 Publish를 누릅니다.

    위쪽 버튼 모양이 3교시 [그림 1-3-8]처럼 바뀌면 성공입니다.

  9. 앱 주소를 Production URL로 바꾸기 2단계와 같은 순서로 합니다. 아래 문장을 먼저 입력창에 붙여 넣고 {Production URL}을 지운 뒤, 민원 받기 위쪽에서 Production URL을 골라 주소를 복사해 따옴표 사이에 붙여 넣고 보냅니다. 
    코드 맨 위 WEBHOOK_URL 값을 "{Production URL}"로 바꿔 줘. 다른 부분은 바꾸지 마.

    복사한 주소에 webhook-test가 없고 /webhook/이 있는지 봅니다. Code 탭의 WEBHOOK_URL에 그 주소가 보이면 성공입니다.

  10. 실제 사용처럼 접수해 보기 앱에서 새 민원 접수를 눌러 입력 화면으로 돌아간 뒤, 이접수 / 010-0000-0001 / minwon@example.com / 대형 / 아파트 앞에 버려진 소파 수거를 요청합니다. 를 넣고 동의에 체크한 다음 접수하기를 누릅니다. n8n 쪽 버튼은 누르지 않습니다.

    시트에 이접수 줄이 생기고, n8n 위쪽 Executions 탭에 실행 기록이 한 줄 보이면 성공입니다. 이제 n8n 화면을 닫아 두어도 앱에서 언제든 접수됩니다.

    자주 하는 실수

    증상 시험 때는 됐는데 지금은 시트에 아무것도 안 쌓여요
    원인 앱에 아직 Test URL이 들어 있거나, Publish를 하지 않았어요
    해결 Code 탭에서 WEBHOOK_URL이 /webhook/ 주소인지 확인하세요. 주소가 맞다면 n8n 위쪽 버튼이 Publish된 모양인지 보고, Publish 뒤에 노드를 고친 적이 있으면 Publish를 한 번 더 누르세요

연결 점검표 (앞으로 계속 씁니다)

  1. Allowed Origins (CORS)가 *인가요?
  2. HTTP Method가 POST인가요?
  3. 시험 중이면 Listen for test event / Execute workflow를 누르고 2분 안에 보냈나요? 실제 사용이면 Publish했나요?
  4. 앱의 WEBHOOK_URL이 지금 쓰는 주소(Test 또는 Production)와 같나요?
  5. 민원 정리의 이름과 시트 머리글이 같은가요?

확인 문제

객관식Q1. 앱이 보낸 이름은 민원 받기 결과의 어디에 들어 있나요?

  1. headers
  2. body
  3. query
  4. 시트
정답 확인

정답: ② POST로 보낸 값은 body 안에 들어옵니다. 그래서 민원 정리에서 꺼내 줍니다. query는 3교시처럼 주소 뒤 ?이름=홍길동으로 보낸 값이 들어가는 곳입니다.

단답형Q2. 시험이 끝나고 실제로 쓰기 전에 n8n에서 눌러야 하는 버튼은?

정답 확인

정답: Publish — 그다음 앱의 주소를 Production URL로 바꿉니다.

정리

  • 앱 → 민원 받기 → 민원 정리 → 시트에 기록으로 이어져, 앱에서 누른 민원이 시트에 쌓입니다.
  • Test URL로 먼저 시험하고, Publish한 뒤 Production URL로 바꿉니다.
  • 앱에서 n8n을 부를 수 있었다면 CORS 허락 명단이 제 역할을 한 것입니다.
  • 다음: 7교시에는 접수번호를 만들어 앱 화면에 돌려주고, 1일차를 정리합니다.

완성본 가져오기(Import)

이 파일을 가져오면 n8n 쪽이 이 교시의 세 노드 연결 상태가 됩니다. 5단계까지 하면 앱에서 바로 접수할 수 있습니다.

먼저: 따라 만들던 워크플로우를 Publish했다면 그 워크플로우의 Publish 옆 목록에서 Unpublish를 누르세요. 같은 주소 끝부분(minwon)과 같은 방식(POST)을 쓰는 Webhook은 하나만 동작할 수 있습니다.
  1. 파일 내려받기 워크플로우 내려받기 d1-p6.json
  2. n8n에서 가져오기 Create workflow → 오른쪽 위 … → Import → From file을 누르고 파일을 고릅니다.
  3. 자격 증명 다시 연결하기 시트에 기록을 열어 Credential 칸에서 2교시에 만든 내 구글 시트 자격 증명을 고릅니다. 자격 증명이나 시트 민원대장 연습이 없으면 1일차 2교시 따라하기대로 먼저 만듭니다.
  4. 자리표시자 바꾸기 시트에 기록의 Document 칸 왼쪽 작은 목록(지금은 By ID)을 눌러 From list로 바꾼 뒤, 목록에서 민원대장 연습을 고릅니다. 여기에_본인_시트_ID 글자가 없어지면 됩니다. Sheet는 내 구글 시트 아래쪽 탭 이름과 같아야 합니다. 파일에는 시트1로 들어 있습니다. 내 탭 이름이 다르면(예: Sheet1) 목록에서 내 탭을 고릅니다.
  5. Publish하고 앱 주소 바꾸기 Publish → 확인 창의 Publish를 누르고, 따라하기 9단계 순서대로 민원 받기의 Production URL을 앱의 WEBHOOK_URL에 넣습니다. 앱에서 가상 민원을 접수해 시트에 줄이 생기면 복구 완료입니다.

앱 쪽이 망가졌다면 4교시 2단계의 주문 문장으로 앱을 새로 만들고 5교시 요청 1·3을 보낸 뒤, 위 5단계의 Production URL을 넣습니다.
