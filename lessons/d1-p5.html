첫 앱 다듬기

화면은 문장으로 고치고, 오류는 정해진 루틴으로 AI에게 고치게 합니다

강사 준비·확인이 교시에서 수업 전에 강사가 할 일입니다. 수강생용 내용이 아니며, 준비가 끝나면 python scripts/strip_inotes.py로 모두 지웁니다.
  • 요청 1~3을 차례로 보내 칸 이름·WEBHOOK_URL이 유지되는지, 연습 오류 요청에 AI가 따르는지(F84)
  • 이 교안 안의 강사 확인 표시 7곳(노란 점선 상자)
  • 캡처 3장 촬영 → assets/img/에 넣고 python scripts/apply_captures.py
  • 확인이 끝나면 docs/instructor-checklist.md의 이 교시 행에 체크

학습목표

  • 원하는 화면 변경을 구체적인 문장으로 요청할 수 있습니다.
  • 오류가 나면 "오류 문구 복사 → AI에 붙여 넣고 고쳐 달라고 요청" 루틴을 스스로 해냅니다.

왜 이 단계가 필요한가

4교시에 만든 화면은 첫 초안입니다. 실제로 쓰려면 기관 이름을 넣고, 개인정보 동의를 받는 등 손볼 곳이 생깁니다. 또 AI가 만든 코드는 가끔 틀립니다. 오류가 나는 것은 내 잘못이 아니며, 알려 주면 AI가 고칩니다. 이번 시간에는 고쳐 달라고 말하는 법과 오류가 났을 때 알려 주는 법을 익힙니다.

고쳐 달라는 말도 AI에게 주는 프롬프트(AI에게 시키는 일을 적은 문장)입니다. 좋은 수정 요청에는 세 가지가 있습니다.

  • 한 번에 한 가지 — 여러 가지를 한꺼번에 바꾸면 무엇이 잘못됐는지 찾기 어렵습니다.
  • 어디를 · 어떻게 — "제목을", "접수하기 버튼을"처럼 위치를, "진한 파란색으로"처럼 결과를 적습니다.
  • 바꾸면 안 되는 것 — "입력 칸은 그대로 둬"를 덧붙입니다. 칸 이름과 WEBHOOK_URL은 6교시 연결 약속입니다.

오류 대처 루틴 (앞으로 계속 씁니다)
  1. 찾기 — 오른쪽 미리보기나 대화 패널에서 영어로 된 오류 글을 찾습니다([그림 1-5-3]).
  2. 신고 문장 먼저 — "오류 신고 문장"을 대화 입력창에 붙여 넣어 둡니다(아직 보내지 않음).
  3. 오류 글 끼워 넣고 보내기 — 오류 글을 복사해 신고 문장의 오류: 아래에 붙여 넣고 보냅니다.
  4. 확인 — 미리보기에서 다시 눌러 봅니다. 두 번 해도 안 되면 손을 듭니다.

2번과 3번의 순서가 중요합니다. Ctrl+C는 마지막에 복사한 것 하나만 기억하기 때문입니다.

따라하기

이번 시간의 공통 동작 상자 안 글을 처음부터 끝까지 끌어서 고르고 Ctrl+C로 복사합니다. AI Studio의 대화 입력창(4교시에 고쳐 달라는 말을 쓰던 곳)을 누르고 Ctrl+V로 붙여 넣은 뒤, 보내기 버튼(화살표 모양)을 누릅니다. Enter는 줄만 바뀔 수 있습니다. 고치는 데 1분쯤 걸리니 미리보기가 바뀌기 전에는 다음 요청을 보내지 않습니다. 강사 확인 F82AI Studio 화면 배치(대화창·입력창·미리보기 위치), Preview/Code 탭 표기, Code 탭 파일 목록

A. 화면 고쳐 달라고 요청하기

  1. 4교시 앱 다시 열기 AI Studio(aistudio.google.com/apps) 왼쪽 메뉴의 Apps를 누르고, 목록 맨 위(가장 최근)의 앱을 누릅니다. 앱 이름은 영어일 수 있습니다.

    오른쪽 미리보기에 민원 접수 화면이 보이면 성공입니다.

    앱을 찾지 못하면 4교시 따라하기 2단계의 프롬프트를 다시 붙여 넣어 새로 만듭니다(3분). 다 만들어지면 브라우저의 뒤로 가기(←)로 이 교안에 돌아옵니다.
  2. 요청 1 — 제목과 안내 문구 바꾸기 아래 글을 대화 입력창에 붙여 넣습니다. OO를 끌어서 고르고 기관 이름(예: 가나구)을 치면 됩니다. 바꾸지 않아도 됩니다. 그다음 보냅니다. 
    맨 위 제목을 "OO구 민원 접수"로 바꾸고, 제목 아래에 작은 글씨로 "평일 09:00~18:00 확인 후 연락드립니다."를 한 줄 더해 줘. 입력 칸과 버튼은 그대로 둬.

    미리보기의 제목과 안내 문구가 바뀌고 입력 칸은 그대로면 성공입니다.

  3. 요청 3 — 개인정보 동의 칸 넣기 아래 글을 대화 입력창에 붙여 넣고 보냅니다. 
    "접수하기" 버튼 바로 위에 "개인정보 수집·이용에 동의합니다(필수)" 체크 칸을 넣어 줘. 체크하지 않으면 접수되지 않고 "개인정보 수집·이용에 동의해 주세요."라고 알려 줘. 이 체크 여부는 보내는 JSON에 넣지 마.
    JSON, 함수, 괄호 같은 말은 AI에게 하는 말입니다. 뜻을 몰라도 그대로 붙여 넣으면 됩니다.

    미리보기에 가상 값(이름 홍길동, 연락처 010-1234-5678, 이메일 minwon@example.com, 종류 생활, 상세설명 보도블록이 깨져 있습니다.)을 모두 넣고, 동의 칸만 비운 채 접수하기를 누릅니다. "개인정보 수집·이용에 동의해 주세요."가 뜨면 성공입니다. 실제 이름·연락처는 넣지 않습니다.

  4. 접수하기로 확인하기 이번에는 동의 칸에 체크하고 접수하기를 누릅니다.

    "아직 접수 창구와 연결되지 않았습니다"가 뜨면 성공입니다.

  5. Code 탭에서 주소 자리 확인하기 미리보기 위쪽의 Code 탭을 누르고, 4교시 5단계([그림 1-4-4])처럼 코드 영역을 한 번 누른 뒤 Ctrl+F로 WEBHOOK_URL을 검색합니다. 코드 영역을 누른 뒤에는 글자를 치지 않습니다.

    WEBHOOK_URL이 보이면 성공입니다. 확인했으면 미리보기 탭을 눌러 돌아갑니다. 화면을 고칠 때마다 4·5단계 확인을 한 번씩 하는 습관을 들입니다.

    자주 하는 실수

    증상 입력 칸 이름이 바뀌었어요(예: 이름이 성함으로)
    원인 AI가 칸 이름까지 손봤어요
    해결 "입력 칸 이름을 이름, 연락처, 이메일, 종류, 상세설명으로 원래대로 되돌려 줘"라고 보내세요. 칸 이름이 다르면 6교시에 n8n이 값을 찾지 못합니다

    증상 WEBHOOK_URL이 코드에서 안 보여요
    원인 화면을 고치면서 AI가 그 줄을 옮기거나 지웠어요
    해결 먼저 다른 파일도 열어 Ctrl+F로 찾아보세요. 없으면 "코드 맨 위에 WEBHOOK_URL 상수를 빈 문자열로 다시 만들고, 접수하기를 누르면 그 주소로 보내게 해 줘"라고 보내세요

  6. (시간이 남으면) 요청 2와 되돌리기 연습 옆 사람보다 늦었다면 이 단계는 건너뛰고 B로 갑니다. 아래 요청 2를 보내 색과 버튼을 바꿔 봅니다. 
    배경을 아주 연한 하늘색으로, "접수하기" 버튼은 진한 파란색 바탕에 흰 글씨로 바꾸고 버튼을 화면 가로 폭에 꽉 차게 해 줘. 입력 칸의 이름과 순서는 바꾸지 마.

    색이 바뀌었으면, 마음에 들지 않는다고 생각하고 아래 글로 되돌립니다. 색이 원래대로 돌아가면 성공입니다.

    방금 바꾼 것을 되돌려서 바로 전 상태로 돌아가 줘.
    대화 패널에 Restore 같은 되돌리기 버튼이 보여도 오늘은 누르지 않습니다. 어느 요청의 버튼을 누르느냐에 따라 여러 단계가 한꺼번에 사라질 수 있습니다. 강사 확인 F77되돌리기(체크포인트) 버튼 이름·위치, 새로고침 뒤 유지, Apps 목록 자동 저장

B. 오류 대처 루틴 연습 (두 번 반복)

  1. 연습용 오류 만들기 (1회차) 아래 글을 대화 입력창에 붙여 넣고 보냅니다. 
    연습을 위해 일부러 오류를 하나 만들어 줘. "접수하기" 버튼을 누르면 화면에 오류 문구가 뜨도록, 버튼을 눌렀을 때 실행되는 코드 안에서 존재하지 않는 함수를 부르게 바꿔 줘. 오류는 고치지 말고 그대로 둬. 다른 부분은 바꾸지 마.

    바뀐 뒤 A-3과 같은 가상 값을 넣고 동의에 체크한 다음 접수하기를 누릅니다. 미리보기나 대화 패널에 오류 글(보통 영어, 예: … is not defined)이 보이면 성공입니다. 읽지 않아도 됩니다. 강사 확인 F84"오류를 일부러 만들어 줘" 요청에 AI가 따르는지·거절하는지·스스로 고치는지. 안 따르면 연습 방법을 바꿔야 함

    오류 대신 "아직 접수 창구와 연결되지 않았습니다"가 뜨면 AI가 오류를 만들지 않았거나 스스로 고친 것입니다. 이때는 2단계대로 신고 문장을 입력창에 붙여 넣고, 오류 글 대신 아래 연습용 오류 문구를 복사해 오류: 아래에 붙여 넣는 데까지만 연습합니다. 보내지 않습니다. 
    Uncaught ReferenceError: sendMinwonNow is not defined
    붙여 넣었으면 입력창을 누르고 Ctrl+A, Delete로 비웁니다. 입력창이 비면 이 연습은 끝입니다. 4단계(2회차)로 갑니다.
  2. 오류 신고 문장 먼저 붙여 넣기 아래 문장을 복사해 대화 입력창에 붙여 넣습니다. 아직 보내지 않습니다. 입력창 안의 (여기에 복사한 오류 문구를 붙여 넣기) 줄을 끌어서 고르고 Delete로 지웁니다. 
    아래 오류가 났어. 원인을 쉬운 말로 한 줄 설명하고 고쳐 줘. 입력 칸 이름, 보내는 JSON의 키, WEBHOOK_URL 값(조회 화면이 있으면 STATUS_URL 값도)은 바꾸지 마.

오류:
(여기에 복사한 오류 문구를 붙여 넣기)

    오류: 아래가 빈 줄이면 성공입니다.

  3. 오류 글 복사해 끼워 넣고 보내기 오류 글의 첫 글자 앞을 누른 채 끝까지 끌어서 고르고 Ctrl+C로 복사합니다. 입력창의 오류: 아래 빈 줄을 한 번 누르고 Ctrl+V로 붙여 넣은 뒤 보냅니다. 강사 확인 F85오류 글을 마우스로 골라 복사할 수 있는 위치(미리보기 오류 표시, 대화창 메시지) 글이 선택되지 않으면 Win+Shift+S를 누릅니다. 화면이 조금 어두워지면 오류 부분을 네모로 끌어 고르고, 신고 문장이 들어 있는 입력창을 눌러 Ctrl+V로 그림을 붙여 보냅니다. F12 키로 열리는 화면(개발자 도구)은 쓰지 않습니다. 대화 패널에 오류를 고치는 버튼(예: Fix errors)이 보여도 오늘 연습에서는 누르지 않고 신고 문장을 씁니다. 강사 확인 F8앱 오류 화면의 오류 표시와 자동 수정 버튼 이름(예: Fix errors / Auto-fix)을 캡처해 교안 표기와 맞추기

    AI가 원인을 한 줄로 설명하고, 다시 접수하기를 눌렀을 때 "아직 접수 창구와 연결되지 않았습니다"가 뜨면 성공입니다.

    자주 하는 실수

    증상 입력창에 붙여 넣었더니 오류 글이 아니라 신고 문장이 또 들어가요
    원인 신고 문장을 나중에 복사해서, 복사해 둔 오류 글이 덮어써졌어요
    해결 입력창에 신고 문장이 이미 있으면 그대로 두고, 오류 글만 다시 복사해 오류: 아래에 붙여 넣으세요

    증상 대화 패널에 An internal error occurred. Retry. 같은 글이 떠요
    원인 앱이 아니라 AI 쪽에 잠깐 문제가 생겼어요
    해결 잠시 기다렸다가 같은 요청을 다시 보내세요. 이것은 오류 신고 문장을 쓸 상황이 아닙니다

  4. 두 번째 연습 (2회차) 이번에는 다른 오류로 1~3단계를 한 번 더 합니다. 아래 글을 붙여 넣고 보냅니다. 
    연습을 위해 일부러 오류를 하나 더 만들어 줘. 이번에는 앱이 열리자마자 미리보기에 오류가 보이도록, 화면을 그리는 코드에서 닫는 괄호 하나를 지워 줘. 오류는 고치지 말고 그대로 둬. 다른 부분은 바꾸지 마.

    미리보기가 다시 민원 접수 화면으로 돌아오면 성공입니다.

    미리보기가 하얗게 비어 있고 오류 글이 어디에도 보이지 않으면, 신고 문장의 오류: 아래에 "미리보기가 하얗게 비어 있고 아무것도 안 보여"라고 직접 적어서 보냅니다. 이것도 루틴 연습입니다.
  5. 6교시 준비 확인 가상 값을 넣고 동의 칸에 체크한 뒤 접수하기를 누릅니다. 이어서 Code 탭에서 WEBHOOK_URL을 찾습니다.

    "아직 접수 창구와 연결되지 않았습니다"가 뜨고 WEBHOOK_URL이 보이면 오늘 실습이 끝났습니다. 미리보기 탭으로 돌아가 둡니다.

  1. 아래 글을 보냅니다. 
    연습용으로 만든 오류를 모두 없애고, 오류 연습 요청을 보내기 전 상태로 되돌려 줘. 입력 칸 이름, 보내는 JSON의 키, WEBHOOK_URL 값(조회 화면이 있으면 STATUS_URL 값도)은 바꾸지 마.
  2. 그래도 안 되면 4교시 2단계 프롬프트로 새 앱을 만들고 요청 1·3을 다시 보냅니다(약 10분).
  3. 끝나면 B-5(6교시 준비 확인)를 합니다. 이 상태면 6교시를 시작할 수 있습니다.
요청마다 무료 사용량이 쓰입니다 수정 요청도 AI Studio의 무료 사용량을 씁니다. 연습 요청은 오늘 교안에 있는 것만 보내고, 한도에 걸렸다는 안내가 나오면 강사에게 알리세요. 강사 확인 F86수정 요청 10회 전후 한도 차감, 한도 초과 화면 문구
알아 두면 좋아요: 화면에 표시해서 요청하기 AI Studio에는 미리보기 화면의 한 부분에 상자를 그리고 고칠 내용을 적어 요청하는 기능(Annotation)이 있습니다. 상자 그리기 → 글 쓰기 → Add to chat → 보내기 순서입니다. 오늘은 해 보지 않아도 됩니다. 시간이 남으면 강사 화면을 보며 함께 해 봅니다. 강사 확인 F82AI Studio 화면 배치(대화창·입력창·미리보기 위치), Preview/Code 탭 표기, Code 탭 파일 목록

  2. 제목 글자를 지금보다 크게 해 줘. 입력 칸은 그대로 둬
  3. 다 고쳐 줘
  4. 버튼이랑 색이랑 칸이랑 전부 바꿔 줘
정답 확인

정답: ② 한 가지를, 어디를 어떻게 바꿀지, 바꾸면 안 되는 것까지 적었습니다.

단답형Q2. 오류 신고 문장과 오류 글 중 무엇을 먼저 입력창에 넣어야 할까요? 이유는?

정답 확인

정답: 신고 문장을 먼저 넣습니다. Ctrl+C는 마지막에 복사한 것 하나만 기억하기 때문에, 오류 글을 먼저 복사하면 신고 문장을 복사할 때 지워집니다.

정리

  • 수정 요청은 한 번에 한 가지, 어디를 · 어떻게, 바꾸면 안 되는 것까지 적습니다.
  • 고친 뒤에는 접수하기와 WEBHOOK_URL을 확인해 연결 약속이 지켜졌는지 봅니다.
  • 오류는 찾기 → 신고 문장 먼저 → 오류 글 끼워 넣고 보내기 → 확인 루틴으로 AI에게 고치게 합니다.
  • 다음: 6교시에는 WEBHOOK_URL에 n8n 주소를 넣어, 이 화면에서 보낸 민원이 구글 시트에 쌓이게 합니다.

프롬프트 전체는 수정 요청 문장 모음과 오류 대처 루틴 문장에도 있습니다.
