발표·피드백 및 적용 로드맵

내 서비스를 5분 동안 뽐내고, 부서에 적용하기까지의 길을 한 장에 적습니다

강사 준비·확인이 교시에서 수업 전에 강사가 할 일입니다. 수강생용 내용이 아니며, 준비가 끝나면 python scripts/strip_inotes.py로 모두 지웁니다.
  • 팀 수에 맞춘 발표 시간, 발표 화면 띄우는 방식, 수료 설문 링크(아래 해당 단계), 로드맵 양식 print/forms/roadmap.html 인쇄
  • 이 교안 안의 강사 확인 표시 1곳(노란 점선 상자)
  • 확인이 끝나면 docs/instructor-checklist.md의 이 교시 행에 체크

학습목표

  • 팀별 5분 동안 설계서와 완성 화면으로 서비스를 발표합니다.
  • 부서에 적용할 때 점검할 항목과 다음 단계를 로드맵으로 정리합니다.

왜 발표하고 로드맵을 쓰나

교육장에서 동작한 서비스가 부서에서 쓰이려면 두 가지가 더 필요합니다. 하나는 동료가 알아듣는 설명, 다른 하나는 실제 적용까지의 순서입니다. 발표는 설명을 연습하는 자리이고, 로드맵은 교육이 끝난 뒤 무엇부터 할지 정하는 한 장입니다.

한 문장 요약 "무엇이 불편했고, 이렇게 바꿨고, 이만큼 줄었다"를 5분에 보여 주고, 실제 데이터는 점검과 협의를 거친 뒤에 넣습니다.

활동

  1. 발표 준비 (3분) 6교시 끝에 캡처한 세 장(앱 화면, 워크플로우 전체, 결과)과 설계서를 준비합니다. 발표 5분은 아래 네 부분으로 나눕니다.
    순서시간내용
    1. 문제1분지금 이 업무를 어떻게 하고 있고, 무엇이 불편한가
    2. 화면 시연1분 30초앱에서 실제로 한 건 보내 보기(가상 값)
    3. 자동화 흐름1분 30초워크플로우 캡처를 보며 입력 → 처리 → 출력 설명
    4. 전후 비교1분설계서의 "자동화 전 → 후" 한 문장, 부서에 적용하려면 필요한 것
    발표 화면 점검 화면에 실제 이름·연락처가 없는지, 이메일 주소·API 키(서비스를 쓸 수 있게 해 주는 비밀 번호표)·Webhook(외부 앱이 n8n을 부르는 주소) 주소인 Production URL(게시한 뒤 앱에 넣는 진짜 주소)이 가려졌는지 발표 전에 확인합니다.
  2. 내 서비스 뽐내기 — 팀별 5분 (25분) 발표 팀 수에 따라 강사가 방식을 정하고, 발표 준비 시간에 알려 줍니다.
    • 4팀 이하: 모두 앞에서 5분씩 발표합니다.
    • 5~7팀: 3분 발표(문제 30초 → 화면 시연 1분 → 자동화 흐름 1분 → 전후 비교 30초)로 줄입니다.
    • 8팀 이상: 두 모둠으로 나누어 자리에서 동시에 5분씩 발표하고, 모둠마다 한 팀을 골라 마지막에 앞에서 한 번 더 보여 줍니다.
    시연이 안 될 때
    • 앱에서 보냈는데 결과가 안 오면 30초 안에 시연을 멈추고 캡처로 넘어갑니다. 발표가 끝난 뒤 다시 Publish(워크플로우를 게시해 주소가 항상 동작하게 하는 것)했는지, 앱에 Test URL(시험할 때만 쓰는 주소)이 아니라 진짜 주소를 넣었는지 확인합니다.
    • 캡처가 없으면 설계서 한 장으로 발표합니다. "여기까지 만들었고, 이 단계에서 막혔다"를 말하는 것도 좋은 발표입니다. 같은 곳에서 막힌 동료에게 도움이 됩니다.
    • 앱을 아예 못 만들었으면 6교시 끝 현장점검 예시 화면을 보여 주며 "내 서비스는 이 모양에서 이 칸과 이 알림이 다르다"고 설명해도 됩니다.

    듣는 사람은 아래 피드백 양식을 발표마다 한 줄씩 채웁니다(인쇄본에 손으로 쓰거나 메모장에 적습니다. 줄이 모자라면 아래에 이어 씁니다).

  3. 부서 적용 로드맵 쓰기 (7분) 적용 로드맵 양식을 채웁니다. 교실에서는 "적용 단계" 표만 채우고, "다음에 더하고 싶은 기능"은 수료 뒤에 채워도 됩니다. 1단계 "점검"은 2일차 3교시 개인정보·보안 점검표를 그대로 씁니다.
    • 점검 → 협의 → 시범 → 보완 → 운영 다섯 단계마다 "누구와, 언제까지"를 적습니다.
    • 실제 민원·개인정보는 2단계(기관 보안 담당 협의) 뒤에만 넣습니다.
    • 교육에 쓴 n8n Cloud 체험 계정은 곧 끝납니다. 끝나기 전에 내 워크플로우를 열어 오른쪽 위 … → Export JSON으로 내려받아 둡니다. 운영 환경(기관 설치형 n8n 등)은 3교시 안내를 참고해 부서와 정합니다.
  4. 수료 설문과 마무리 (5분) 수료 설문을 작성합니다. 강사 준비수료 설문 링크(또는 QR)를 여기에 넣거나 화면에 띄울 준비 교안 사이트와 완성본 파일은 수료 뒤에도 볼 수 있습니다. 선택 실습(PDF 공문 요약, 음성 입력 접수)은 혼자 해 볼 수 있게 만들어 두었습니다.

정리 — 이틀 동안 만든 것

  • AI Studio로 화면을, n8n으로 일을 만들어 접수 → 처리 → 알림 → 조회까지 이어지는 서비스를 완성했습니다.
  • 내 업무 서비스를 설계서 한 장에서 시작해 실제로 동작하게 만들었습니다.
  • 부서 적용은 점검 → 협의 → 시범 → 보완 → 운영 순서로, 실제 데이터는 협의 뒤에 넣습니다.
